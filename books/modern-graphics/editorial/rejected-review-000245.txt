## 2. 真錯誤與技術修正 (Must Fix)

### 2.1 程式碼中 `L_dir` 函式的邊界處理缺失
**位置**：`## 實作與程式` -> `self_check` 函式
**原句**：
```python
L_dir   = lambda w: w[1]          # cosθ
```
**錯誤原因**：
1.  **物理意義不一致**：輻射亮度 $L_i$ 通常定義為非負值。雖然在 Lambert 半球積分中，$\cos\theta$ 在 $\theta \in [0, \pi/2]$ 範圍內非負，但 `sample_uniform_hemisphere` 和 `sample_cosine_hemisphere` 生成的向量 $\omega$ 理論上可能因浮點誤差或邊界情況（例如 $\cos\theta$ 極小但為負，雖然在 $[0,1]$ 取樣中不太可能，但 `w[1]` 是 $y$ 分量，即 $\cos\theta$）而出現異常。
2.  **更嚴重的問題**：在 `estimate_lambert` 中，計算項為：
    ```python
    total += (rho / math.pi) * L_i_fn(w) * max(0.0, cos_t) / p
    ```
    這裡使用了 `max(0.0, cos_t)` 來確保 $\cos\theta$ 非負。
    然而，`L_dir` 函式直接回傳 `w[1]`。
    如果 $L_i(\omega) = \cos\theta$，則在 $\theta > \pi/2$ 時（雖在半球取樣中不應發生，但為防禦性程式設計考慮），$L_i$ 應為 0 或負值被截斷。
    但在本例中，由於取樣限制在上半球，$\cos\theta \ge 0$ 是成立的。
    **然而**，仔細看 `L_dir` 的定義：$L_i(\omega) = \cos\theta$。
    在 `estimate_lambert` 中，積分項是 $f_r L_i \cos\theta / p$。
    如果 $L_i = \cos\theta$，則項為 $\rho/\pi \cdot \cos\theta \cdot \cos\theta / p$。
    程式碼中：
    `L_i_fn(w)` 回傳 `w[1]` (即 $\cos\theta$)。
    `cos_t` 是 `w[1]`。
    `max(0.0, cos_t)` 確保非負。
    所以計算邏輯是正確的。
    
    **但是**，有一個潛在的**數值穩定性**陷阱。
    如果 `w[1]` 是負數（例如 -0.0000001），`L_i_fn(w)` 回傳負數。
    `max(0.0, cos_t)` 回傳 0.0。
    乘積為 0。這是安全的。
    
    **真正的問題在於習題 3 的解答與程式碼的一致性**：
    習題 3 討論了錯誤的 `sin_t` 計算導致向量非單位向量。
    程式碼 `sample_cosine_hemisphere` 使用：
    ```python
    cos_t = math.sqrt(max(0.0, 1.0 - r1))
    sin_t = math.sqrt(r1)
    ```
    這確保了 $\cos^2\theta + \sin^2\theta = (1-r_1) + r_1 = 1$。
    所以 $w$ 是單位向量。
    
    **修正建議**：
    雖然目前程式碼在本特定測試用例中是正確的，但為了嚴謹性，`L_dir` 應該明確處理非負性，或者在註解中說明 $L_i$ 假設為非負。
    更建議的寫法是：
    ```python
    L_dir = lambda w: max(0.0, w[1])  # 確保輻射亮度非負
    ```
    雖然在半球取樣中 `w[1] >= 0` 幾乎恆成立，但防禦性程式設計是最佳實踐。
    
    **判定**：這不是導致結果錯誤的「真錯誤」，因為數學上半球取樣 $\cos\theta \ge 0$。但在工程嚴謹性上，建議修正。鑑於這不影響本章的核心數學證明（變異數計算基於理論分布），且程式碼在當前測試中行為正確，此項列為**可選優化**而非阻斷性錯誤。
    
    *重新評估*：
    查看 `estimate_lambert` 中的 `p`。
    對於 `uniform`：$p = 1/(2\pi)$。
    對於 `cosine`：$p = \cos\theta/\pi$。
    如果 $\cos\theta$ 非常接近 0，$p$ 也非常接近 0。
    `if p <= 0.0: continue` 處理了嚴格為 0 的情況。
    如果 $p$ 極小但非零，$f/p$ 會極大。這是 Monte Carlo 的特性（高方差），不是錯誤。
    
    **結論**：程式碼邏輯無實質錯誤。

### 2.2 手算例題二的「真值」計算驗證
**位置**：`## 逐步手算例題` -> `### 例題二`
**原句**：
$$
L_o = \frac{\rho}{\pi}\int_{\Omega^+}\cos^2\theta \, d\omega .
$$
由 $\int_{\Omega^+}\cos^2\theta\, d\omega = 2\pi/3$，得
$$
L_o = \frac{0.6}{\pi} \cdot \frac{2\pi}{3} = 0.4 .
$$
**核對**：
$\int_{\Omega^+} \cos^2\theta d\omega = \int_0^{2\pi} d\phi \int_0^{\pi/2} \cos^2\theta \sin\theta d\theta$。
令 $u=\cos\theta, du=-\sin\theta d\theta$。
$\int_0^1 u^2 du = [u^3/3]_0^1 = 1/3$。
積分結果為 $2\pi \cdot (1/3) = 2\pi/3$。
計算正確。

### 2.3 例題三中的標準誤差計算驗證
**位置**：`## 逐步手算例題` -> `### 例題三`
**原句**：
均勻取樣：
$$
E[g_u] = 1.2 \cdot \frac{1}{2\pi} \cdot \frac{2\pi}{3} = 0.4
$$
$$
E[g_u^2] = 1.44 \cdot \frac{1}{2\pi} \cdot \frac{2\pi}{5} = 0.288
$$
**核對**：
$g_u = 2\rho \cos^2\theta = 1.2 \cos^2\theta$。
$E[g_u] = 1.2 E[\cos^2\theta] = 1.2 (1/3) = 0.4$。正確。
$E[g_u^2] = 1.44 E[\cos^4\theta]$。
$E[\cos^4\theta] = \frac{1}{2\pi} \int_0^{2\pi} d\phi \int_0^{\pi/2} \cos^4\theta \sin\theta d\theta = \int_0^1 u^4 du = 1/5$。
$E[g_u^2] = 1.44 \cdot 0.2 = 0.288$。正確。
$\sigma_u^2 = 0.288 - 0.4^2 = 0.288 - 0.16 = 0.128$。
$\sigma_u = \sqrt{0.128} \approx 0.35777$。
$\text{SE} = 0.35777 / \sqrt{500} \approx 0.0160$。
計算正確。

餘弦加權：
$g_c = \rho \cos\theta = 0.6 \cos\theta$。
$E[g_c] = 0.6 E_{cos}[\cos\theta]$。
$E_{cos}[\cos\theta] = \int \cos\theta \frac{\cos\theta}{\pi} d\omega = \frac{1}{\pi} \int \cos^2\theta d\omega = \frac{1}{\pi} \frac{2\pi}{3} = 2/3$。
$E[g_c] = 0.6 \cdot (2/3) = 0.4$。正確。
$E[g_c^2] = 0.36 E_{cos}[\cos^2\theta]$。
$E_{cos}[\cos^2\theta] = \int \cos^2\theta \frac{\cos\theta}{\pi} d\omega = \frac{1}{\pi} \int \cos^3\theta d\omega$。
$\int_0^{\pi/2} \cos^3\theta \sin\theta d\theta = \int_0^1 u^3 du = 1/4$。
$\int \cos^3\theta d\omega = 2\pi (1/4) = \pi/2$。
$E_{cos}[\cos^2\theta] = \frac{1}{\pi} \frac{\pi}{2} = 0.5$。
$E[g_c^2] = 0.36 \cdot 0.5 = 0.18$。
$\sigma_c^2 = 0.18 - 0.4^2 = 0.02$。
$\sigma_c = \sqrt{0.02} \approx 0.1414$。
$\text{SE} = 0.1414 / \sqrt{500} \approx 0.0063$。
計算正確。

### 3.2 `L_dir` 的防禦性寫法
**位置**：`## 實作與程式`
**建議**：
雖然目前邏輯正確，但將 `L_dir` 改為 `lambda w: max(0.0, w[1])` 會更符合物理上輻射亮度非負的定義，並防止未來若取樣範圍擴展或浮點誤差導致負值時出現非預期行為。

### 3.3 習題 2 的引導
**位置**：`## 習題` -> `**習題 2**`
**建議**：
題目要求「修改 `estimate_lambert`... 在 `mode='broken'` 下對所有樣本使用 $p = 0$」。
解答中說「原程式在關鍵位置用 `if p <= 0.0: continue` 事先攔截」。
這暗示如果讀者真的把 `p` 設為 0，程式會跳過所有樣本，導致 `used = 0`，然後 `return total / max(1, used)` 回傳 0.0。
這並**不會**產生 `inf` 或 `nan`。
要觀察 `inf` 或 `nan`，讀者必須**移除** `if p <= 0.0: continue` 的保護，並讓 `f/p` 實際發生除以零。
**修正建議**：
習題 2 的題干應更明確：「修改程式以**移除** `p <= 0.0` 的保護，並強制 $p=0$...」 或者 「討論若**未**有 `p <= 0.0` 保護...」
目前的題干「修改...使用 $p=0$」配合原有的 `if p <= 0: continue` 邏輯，結果會是 0.0，而非 `inf/nan`。這可能導致讀者困惑。
**具體修法**：
將習題 2 改為：
> **習題 2（程式測試）** 修改 `estimate_lambert`，在 `mode='broken'` 下對所有樣本使用 $p = 0$，並**移除** `if p <= 0.0: continue` 的保護機制。執行 10 次樣本，觀察是否出現 `inf` 或 `nan`。說明原始程式碼的 `p <= 0.0` 檢查如何防止這件事...
