# 審稿結果

本章涵蓋局部規則、時間更新與相機投影，但核心程式的分離力方向、鄰居計數及同步更新均有錯；深度公式前後矛盾，且實作沒有產生宣稱的深度圖、ID 圖或遮擋標註。這些是結果正確性問題，不是文風問題。

## 一、必須修正的數學與程式錯誤

### 1. 程式的分離力方向相反

**公式原句：**

$$
\Delta \mathbf{v}_{sep}
= w_s\sum_j\frac{\mathbf p_i-\mathbf p_j}{d_{ij}^2}
$$

**程式原句：**

```python
dist = f_i.pos - f_j.pos
...
sep_force -= dist / (d * d)
```

**問題：**

`dist = p_i-p_j` 已指向遠離鄰居的方向，再取負號會改成朝向鄰居，實際造成吸引而非分離。

**修法：**

```python
sep_force += dist / (d * d + eps)
```

但須先統一究竟使用哪一種模型：

- 位移向量除以 $d^2$：

$$
\frac{\mathbf p_i-\mathbf p_j}{d^2}
=\frac{\hat{\mathbf d}}{d};
$$

- 單位方向除以 $d^2$：

$$
\frac{\hat{\mathbf d}}{d^2}
=\frac{\mathbf p_i-\mathbf p_j}{d^3}.
$$

兩者衰減率不同，不能混用。

### 2. 手算例 1 與所列公式不一致

**原句：**

> $\Delta\mathbf v_{sep}=w_s\cdot\hat d\cdot 1/(d^2+\epsilon)=(-7.692,0,0)$。

但前文公式使用：

$$
\frac{\mathbf p_i-\mathbf p_j}{d^2}.
$$

對例題資料，若按前文並以 $d^2+\epsilon$ 正規化：

$$
\mathbf p_A-\mathbf p_B=(-0.5,0,0),
$$

$$
\Delta\mathbf v_{sep}
=2\frac{(-0.5,0,0)}{0.25+0.01}
\approx(-3.846,0,0).
$$

若要得到 $(-7.692,0,0)$，公式必須明寫成單位方向除以 $d^2+\epsilon$。請選定一種並同步修改推導、例題及程式。

此外，這裡若乘上 `dt` 才是單步速度增量；否則該量應稱為加速度或 steering acceleration，不能同時稱「力」與「$\Delta v$」。

---

### 3. Alignment 與 cohesion 錯用同一個鄰居數量

**原句：**

```python
count = 0

if d < self.params['R_ali']:
    ali_sum += f_j.vel
    count += 1

if d < self.params['R_coh']:
    coh_sum += f_j.pos

if count > 0:
    ali_force = (ali_sum / count) - f_i.vel
    coh_force = (coh_sum / count) - f_i.pos
```

**問題：**

對齊與聚合半徑分別是 `R_ali`、`R_coh`，必須使用各自的鄰居數量。目前只計數 alignment 鄰居：

- 有 cohesion 鄰居但無 alignment 鄰居時，聚合被忽略。
- 有 alignment 鄰居但無 cohesion 鄰居時，`coh_sum=0`，卻會產生朝世界原點的錯誤加速度。
- 兩個半徑不同時，平均值分母錯誤。

**修法：**

```python
ali_count = 0
coh_count = 0

if d < R_ali:
    ali_sum += old_vel[j]
    ali_count += 1

if d < R_coh:
    coh_sum += old_pos[j]
    coh_count += 1
```

然後分別計算。

### 4. 原地逐魚更新造成順序相依

**原句：**

```python
for i, f_i in enumerate(self.fish):
    ...
    f_i.vel += accel * dt
    f_i.pos += f_i.vel * dt
```

**問題：**

更新第 $i$ 條魚後，後面的魚會讀到部分已更新、部分未更新的狀態。因此結果依魚在列表中的順序而異，不是公式所描述的同一時間步局部規則。

**修法：**

每一步先複製舊狀態：

```python
old_pos = np.array([f.pos.copy() for f in self.fish])
old_vel = np.array([f.vel.copy() for f in self.fish])
```

所有加速度只能由 `old_pos`、`old_vel` 計算，再一次提交新速度與新位置。並明示使用半隱式 Euler：

$$
\mathbf v^{k+1}=\mathbf v^k+\mathbf a^k\Delta t,
$$

$$
\mathbf p^{k+1}=\mathbf p^k+\mathbf v^{k+1}\Delta t.
$$

### 5. 邊界模型與測試宣稱不符

**原句：**

> 若 $\mathbf p_i$ 接近邊界……

程式卻只有在魚已出界後才施力：

```python
if f_i.pos[axis] < -limit:
```

測試又宣稱：

> `pos_world` 應在 bounds 內。  
> 魚群應……不飛離邊界。

**問題：**

軟力不能保證位置永遠在邊界內，而且目前是在越界後才作用。速度較大時可持續越界多幀。

**修法：**

選擇並明示一種策略：

- 軟牆：在距邊界小於 margin 時施力，但不得宣稱永不越界；
- 硬反射：裁回邊界並反轉法向速度；
- 週期邊界：由另一側進入。

測試應配合所選模型，而不是直接要求軟牆必然保持 bounds。

### 6. 相機投影段落混用正深度與負 $z_{cam}$

**原句：**

> 若 $z'>z_{near}$（前置）

但全書約定相機看向 $-Z$，所以可見點應有 $z_{cam}<0$。應定義正的前向距離：

$$
z=-z_{cam}>0,
$$

並以

$$
z_{near}\le z\le z_{far}
$$

判斷裁切。

投影應統一為：

$$
u=f_x\frac{x_{cam}}{-z_{cam}}+c_x,
$$

$$
v=c_y-f_y\frac{y_{cam}}{-z_{cam}}.
$$

前文的

$$
x_{ndc}=\frac f{z'}(x'-c_x)
$$

維度也不正確：$x'$ 是相機空間長度，$c_x$ 是像素，兩者不能相減。

---

### 7. OpenGL 深度推導含錯誤公式與未定稿文字

**原句：**

> $z_{ndc} = \frac{z' + z_{far}}{z_{far} - z'} - 1$（OpenGL 風格，需確認符號）

以及：

> 標準 OpenGL 深度映射：……（複雜）

**問題：**

這些不是標準 OpenGL 投影深度公式，「需確認符號」「複雜」也不能留在正式教材。

對相機空間 $z_{cam}<0$，正距離 $z=-z_{cam}$，正確公式為：

$$
z_{ndc}
=\frac{f+n}{f-n}
-\frac{2fn}{(f-n)z},
$$

其中 $n=z_{near}$、$f=z_{far}$。深度緩衝值為：

$$
d=\frac{z_{ndc}+1}{2}
=\frac{f}{f-n}-\frac{fn}{(f-n)z}.
$$

驗算邊界：

$$
z=n\Rightarrow d=0,\qquad z=f\Rightarrow d=1.
$$

---

### 8. 線性深度方向與全書 depth buffer 約定相反

**原句：**

$$
d_{linear}=1-\frac{z-z_{near}}{z_{far}-z_{near}}.
$$

這使 near 對應 1、far 對應 0；但本卷 OpenGL depth buffer 約定是 near 對應 0、far 對應 1。

若需要線性深度標註，應使用：

$$
d_{linear}=\frac{z-z_{near}}{z_{far}-z_{near}}.
$$

也可以保留實際公尺距離 `depth_m=z`，通常比倒置的線性值更容易稽核。若另存 inverse depth，欄位名稱必須明示。

程式也需先裁切：

```python
z = -z_cam
if not (self.z_near <= z <= self.z_far):
    continue
```

否則目前 `depth_linear` 可能超出 $[0,1]$，與測試宣稱矛盾。

---

### 9. 例 2不應中途更改焦距

**原句：**

> 焦距 $f=500$ px……

算出畫面外後又改成：

> 令 $f=200$。

**問題：**

畫面外不是數學異常，沒有理由改題目參數。按原設定：

$$
z=-z_{cam}=1,
$$

$$
u=500\frac11+400=900,
$$

$$
v=300-500\frac11=-200.
$$

結果 $(900,-200)$ 正確表示中心投影落在影像外。接著應說明需要影像邊界裁切，而不是更換焦距。

使用 $n=0.1,f=10,z=1$ 時，標準 OpenGL 深度為：

$$
d=\frac{10}{9.9}-\frac{1}{9.9}
=\frac9{9.9}\approx0.9091.
$$

此例剛好與稿件倒置線性深度得到同一數值只是巧合；兩種映射一般不相同。

### 10. 實作沒有生成章名與核心要求中的深度圖、ID 圖

**原句：**

> 並生成包含相機投影、深度資訊及物體識別（ID）的合成訓練資料。

以及：

> 建立一張與 RGB 影像同尺寸的整數矩陣 `ID_Map`。

但程式只輸出每條魚中心的列表：

```json
{"id": ..., "u": ..., "v": ..., "depth": ...}
```

**問題：**

這不是像素級 ID map，也沒有：

- 魚體幾何覆蓋；
- 每像素 z-buffer；
- 可見遮擋；
- 深度影像；
- RGB 影像；
- 2D bounding box；
- 畫面裁切。

因此不能稱為「完美標註」，也未完成指定實驗「相機／深度／ID 標註」。

**修法：**

至少使用圓盤或矩形作為魚體螢幕空間代理：

1. 投影魚體中心及尺寸；
2. 列舉代理圖形覆蓋的像素；
3. 以 `(v,u)` 索引深度與 ID 陣列；
4. 通過深度測試才更新；
5. 背景 ID 使用 0，魚 ID 建議由 1 開始；
6. 分別輸出 `depth.npy`／可稽核文字格式及整數 ID PGM/PPM，或清楚說明列表只屬中心點標註。

---

### 11. `ID_Map[u,v]` 的索引順序錯誤

**原句：**

> `ID_Map[u, v] = i`

依本卷影像陣列慣例，NumPy 陣列第一維是影像 row，即 $v$；第二維是 column，即 $u$。應為：

```python
id_map[v, u] = object_id
```

並先將連續投影座標轉為明確的像素規則，例如 `floor(u)`、`floor(v)`，再檢查 $0\le u<W$、$0\le v<H$。

### 12. 習題 2與習題 4解答不可執行或不完整

#### 習題 2

**原句：**

```python
target = min(other_fish, ...)
```

`predator_id`、`other_fish` 均未定義，也沒有完整整合方式。「距離應遞減」亦不保證成立，因獵物正在運動、邊界與速度限制會影響結果。

應提供完整函式及可驗收條件，例如比較初始距離與 50 幀內最小距離，而不是要求每幀單調下降。

#### 習題 4

**原句：**

> $d = \frac{z_{near}}{z'}\cdots$（需調整符號）

解答又只寫：

> $\times\dots$

這不是完整答案。應直接給出上節的標準公式及可貼入程式的實作：

```python
z = -z_cam
z_ndc = (far + near) / (far - near) \
        - (2.0 * far * near) / ((far - near) * z)
depth = 0.5 * z_ndc + 0.5
```

並測 near、far 分別得到 0、1。

## 二、其他工程問題

- `coh_force = np.zeros(0)` 維度錯誤；雖然目前分支通常會覆寫，仍應改成 `np.zeros(3)`。
- `frame_idx` 傳入 `get_annotations` 卻未使用。
- `csv` 模組未使用。
- `mass` 欄位未使用。
- 建議使用 `np.random.default_rng(seed)`，避免修改全域亂數狀態。
- `bounds=np.array(...)` 是可變預設參數；改為 `bounds=None` 後在建構子內建立。
- 相機實作只有固定朝向，沒有使用前文聲稱的一般 $R_{cam}^{-1}$。應明說這是與世界軸對齊的特例，或真正實作 view matrix。
- `focal` 由垂直 FOV 與影像高度計算，作為 $f_y$ 合理；若像素非方形或要一般內參，應分開 `fx`、`fy`。
- 「所有魚中心都輸出」仍不代表魚體可見；魚中心在畫面外時目前也未裁除。

提供的 `measured_characters=2363`，低於至少 3000 字的硬性要求。可用以下必要內容補足，而非增加宣傳文字：

- 同步 Euler 更新推導；
- 正確 OpenGL 深度推導及 near/far 手算；
- 像素級代理魚體、z-buffer、ID map 完整實作；

- JSON manifest 中的相機內外參、單位、seed、時間步及檔名；
- 固定 seed 的不變量測試，而非猜測「某魚可能在中央」。
