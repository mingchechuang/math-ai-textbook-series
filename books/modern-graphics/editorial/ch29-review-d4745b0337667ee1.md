# 審稿結果

本版已修正分離力符號、同步更新、鄰居計數、相機符號及 OpenGL 深度公式，數學主線大致正確。然而程式並未實際輸出宣稱的深度圖、ID 圖與資料清單，像素中心規則不符全書約定，習題解答亦不完整；正文量仍低於硬性下限。

## 一、必須修正的實質問題

### 1. 程式沒有輸出所宣稱的短序列與資料清單

**原句：**

> 以下程式生成魚群動畫，並輸出像素級深度與 ID 標註。

以及：

```python
# Save depth and ID maps (as .npy for binary, or text for demo)
# For this text demo, we just print stats
print(f"Frame {t}: Visible pixels = {manifest['visible_pixels']}")
```

**問題：**

程式只建立記憶體中的陣列並印出統計值，沒有：

- 儲存 `depth_map`；
- 儲存 `id_map`；
- 儲存 `manifest`；
- 建立跨幀資料清單；
- 記錄每幀檔名。

因此不符合實驗要求「合成魚群短序列與資料清單」，也不能稱為「輸出像素級標註」。

**修法：**

至少加入：

```python
np.save(f"depth_{t:04d}.npy", depth_map)
np.save(f"id_{t:04d}.npy", id_map)
```

並累積：

```python
sequence_manifest.append({
    "frame": t,
    "depth_file": f"depth_{t:04d}.npy",
    "id_file": f"id_{t:04d}.npy",
    ...
})
```

最後以 UTF-8 寫出 JSON。相機資料還應包含影像寬高、座標系、深度編碼、時間步、seed 及世界單位。

### 2. 深度圖的語義與 OpenGL depth buffer 混淆

**推導原句：**

> 標準 OpenGL 深度緩衝值 $d\in[0,1]$……

**程式實際儲存：**

```python
depth_map[v_pix, u_pix] = z
```

**問題：**

程式存的是正的相機前向距離 $z$，單位為公尺，不是 OpenGL 深度緩衝值 $d$。兩者都可以作為標註，但不可共用模糊的 `depth` 名稱。

此外：

```python
depth_map = np.full(..., self.z_far)
```

使背景與恰好位於遠平面的幾何無法區分。

**修法：**

明確選擇並記錄：

- `depth_m`：相機前向距離，背景為 `inf` 或另附 valid mask；
- `depth_buffer`：OpenGL 非線性值，背景通常為 1。

例如：

```python
depth_m = np.full((H, W), np.inf, dtype=np.float32)
```

manifest 中加入：

```json
"depth_encoding": "camera_forward_distance_m",
"background_depth": "infinity"
```

若要同時輸出 OpenGL depth，應另建陣列，不能覆蓋公尺深度。

### 3. 像素覆蓋測試違反既定像素中心約定

**原句：**

```python
dx = u_pix - u
dy = v_pix - v
```

全書約定像素 $(u,v)$ 的中心為：

$$
(u+0.5,v+0.5).
$$

**問題：**

目前把整數格點當成像素中心，圓盤會產生半像素偏移，邊界覆蓋也與前面章節不一致。

**修法：**

```python
dx = (u_pix + 0.5) - u
dy = (v_pix + 0.5) - v
```

並依像素中心推導候選範圍。另應使用 `floor`／`ceil`，不要依賴 `int()`；Python 的 `int()` 對負數是朝零截斷，不等同幾何上的 floor。

---

### 4. 圓盤 bounding box 的整數轉換不嚴謹

**原句：**

```python
u_min = max(0, int(u - r_int))
u_max = min(self.img_width - 1, int(u + r_int))
```

**問題：**

`int(-1.8)` 得到 `-1`，不是 $\lfloor-1.8\rfloor=-2$。在畫面左上邊界附近可能漏測或多測像素。

**修法：**

依像素中心條件，可保守使用：

```python
from math import floor, ceil

u_min = max(0, ceil(u - r_screen - 0.5))
u_max = min(W - 1, floor(u + r_screen - 0.5))
v_min = max(0, ceil(v - r_screen - 0.5))
v_max = min(H - 1, floor(v + r_screen - 0.5))
```

再以圓方程作最終包含測試。

### 5. 完全重合的魚不會產生分離效果

**原句：**

```python
d_vec = p_i - old_pos[j]
denom = d * d + self.params['eps']
acc_sep += ... * d_vec / denom
```

**問題：**

加入 $\epsilon$ 只避免除零；若兩魚位置完全相同，`d_vec` 是零向量，分離加速度仍為零，兩者可能永久重合。稿件不能把 epsilon 描述成完整的重合處理。

**修法：**

說明此退化情況，並採用可重現策略，例如：

- 由魚 ID 決定固定反向擾動；
- 使用前一幀有效相對方向；
- 初始化時拒絕小於最小間距的位置。

該 epsilon 單位也應是 $\mathrm{m}^2$，因為它與 $d^2$ 相加。

### 6. 局部規則的量綱沒有交代

**原句：**

```python
total_acc = acc_sep + acc_ali + acc_coh
```

**問題：**

三個未加權原始量的維度不同：

- 分離基礎量 $(p_i-p_j)/(d^2+\epsilon)$：$\mathrm{m}^{-1}$；
- 對齊差：$\mathrm{m/s}$；
- 聚合位置差：$\mathrm{m}$。

因此 $w_s,w_a,w_c$ 必須分別帶有適當單位，才能相加為 $\mathrm{m/s^2}$。目前把權重當無因次「可調參數」，量綱不完整。

**修法：**

明示：

$$
[w_s]=\mathrm{m^2/s^2},\quad
[w_a]=\mathrm{s^{-1}},\quad
[w_c]=\mathrm{s^{-2}}.
$$

或者將各 steering 項先正規化成期望速度／加速度，再用無因次混合權重。

### 7. 手算例 1留有大段自我否定，應整理成單一正確結論

**原句：**

> 結果：兩魚距離由 0.5 縮小至……？  
> 注意：分離力應使距離增加。  
> 錯誤檢查：……

**問題：**

最終計算其實是：

$$
p_A^{new}=0.06154,\qquad p_B^{new}=0.43846,
$$

$$
d^{new}=0.43846-0.06154=0.37692.
$$

距離由 $0.5$ 降為 $0.37692$。這並不表示分離力方向錯誤，而是兩魚原本以相對速度 $2\,\mathrm{m/s}$ 相向運動；該步的分離加速度只令它們減速，尚未反向。

**修法：**

刪除草稿式自問自答，直接寫：

> 分離加速度方向正確，但在此參數與單一步長下，兩魚仍相向移動，因此距離暫時縮短。分離規則不保證每一步的距離都增加。

這也是重要的時間積分教學界線。

### 8. 「硬反射」目前只是裁切加速度翻轉

**原句：**

> 採用硬反射策略……

程式：

```python
p_new[axis] = limit
new_vels[i][axis] *= -1
```

**問題：**

這能保證結果位於邊界內，但丟棄了越界距離。例如一步跨過牆面 $0.3$ m，真正鏡射後應回到牆內 $0.3$ m；目前只是停在牆面。若一步可能跨越兩面牆，結果更不是幾何反射。

**修法：**

可保留簡化法，但改稱「裁切並反轉法向速度」，不要稱精確 hard bounce；或者保留越界量進行鏡射。需加上 $\Delta t$ 不可大到跨越多個箱寬的限制。

### 9. 相機可見性與畫面可見性用語需分開

**例 2原句：**

> $z_{near}\le1.0\le z_{far}$，可見。

但之後得到：

> 點 $(900,-200)$ 在影像外。

**問題：**

通過 near/far 只表示通過深度範圍，不表示在視錐的左右上下界內，更不表示有可見像素。

**修法：**

改成：

> 此點通過前後裁切面，但投影中心位於影像範圍外；其圓盤代理是否與影像相交，仍需做螢幕邊界測試。

### 10. 測試條件「可見像素大於 0」不應依賴假設

**原句：**

> 應……大於 0（假設魚在視野內）。

**問題：**

測試不應以未驗證假設作通過條件。固定 seed 的初始化雖可能產生可見魚，但稿件未手算或列出預期狀態，且本審查不能聲稱已執行確認。

**修法：**

加入一個確定的單魚測試，例如魚位於相機座標 $(0,0,-2)$，驗證：

- 中心投影為主點；
- 半徑為 $f r/2$；
- ID map 有非零像素；
- 中心像素的公尺深度為 2；
- 第二條更遠且重疊的魚不覆蓋第一條 ID。

## 二、數學與座標系核對

以下內容正確：

- 同步讀取舊狀態並以半隱式 Euler 更新。
- 分離方向使用 $\mathbf p_i-\mathbf p_j$。
- Alignment 與 cohesion 使用獨立鄰居數量。
- 相機看向 $-Z$ 時，以 $z=-z_{cam}>0$ 表示前向距離。
- 投影式的 $v$ 軸翻轉符合影像向下約定。
- OpenGL 深度式

$$
d=\frac{f}{f-n}-\frac{fn}{(f-n)z}
$$

及 near/far 邊界值正確。
- 習題 1 的 $(u,v)=(220,40)$ 與 $d\approx0.9848$ 正確。
- ID 使用 1 起算、0 作背景是合理索引設計。
- z-buffer 以較小的正距離 $z$ 判定較近物體正確。

本章沒有表面法線或色彩計算；無須額外加入法線或 sRGB 內容。若輸出 ID 圖，必須明說它是整數資料，不套用 sRGB 或一般影像色彩轉換。
