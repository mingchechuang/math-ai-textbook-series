# 審稿結論

本版已補齊可獨立閱讀的光柵化、雙線性取樣與 PPM 輸出，手算數值也大致正確，篇幅已達最低要求。但程式中的共享頂點 \(w\) 不一致，會使共享邊兩側產生不同透視插值；此外，魚身資料並未真正建立所宣稱的週期 UV 接縫，上下翻轉也只有文字說明、沒有程式測試。這些均直接影響本章指定實驗，仍需修訂。

## 一、必須修正的實質錯誤

### 1. 共享幾何頂點使用不同的 clip \(w\)，資料不一致

**原程式：**

```python
body_tri_1 = (A_ndc, B_ndc, D_ndc)
body_tri_2 = (B_ndc, C_ndc, D_ndc)

w1 = (1.0, 2.0, 3.0)
w2 = (1.5, 2.5, 3.5)
```

依參數順序：

- 第一個三角形中的 \(B\) 使用 \(w=2.0\)，\(D\) 使用 \(w=3.0\)；
- 第二個三角形中的 \(B\) 使用 \(w=1.5\)，\(D\) 使用 \(w=3.5\)。

但 \(B,D\) 被宣告為共享的相同幾何頂點。相同投影頂點不能同時擁有兩個不同的 clip \(w\)。這也會使共享邊上的透視插值不同。

以共享邊 \(B\rightarrow D\) 中點為例，兩端 UV 為：

\[
UV_B=(0.5,1),\qquad UV_D=(0.5,0).
\]

第一個三角形使用 \(w_B=2,w_D=3\)，邊中點的 \(v\) 為：

\[
v_1=
\frac{0.5(1/2)+0.5(0/3)}
{0.5/2+0.5/3}
=
\frac{1/4}{5/12}
=\frac35=0.6.
\]

第二個三角形使用 \(w_B=1.5,w_D=3.5\)，得到：

\[
v_2=
\frac{0.5(1/1.5)}
{0.5/1.5+0.5/3.5}
=
\frac{1/3}{10/21}
=0.7.
\]

所以同一共享邊中點會被兩側算成不同 UV。若貼圖依 \(v\) 變化，將直接產生裂縫。

**修法：**

為四個幾何頂點各指定唯一 \(w\)：

```python
w_A = 1.0
w_B = 2.0
w_C = 3.5
w_D = 3.0

w1 = (w_A, w_B, w_D)
w2 = (w_B, w_C, w_D)
```

接縫可以複製 UV 或法線屬性，但如果兩份渲染頂點代表相同的投影幾何位置，其 clip position，包括 \(w\)，仍必須一致。

---

### 2. 「先寫入者即保留」與實際程式行為相反

**原 docstring：**

> 本函式不處理深度測試，先寫入者即保留；多個三角形時應按深度順序呼叫。

實際程式是：

```python
image[py, px] = ...
```

沒有 occupancy mask 或深度測試，因此後呼叫的三角形會覆寫前者。實際行為是「後寫入者保留」。

**修法二選一：**

- 將說明改成「後寫入者覆蓋先寫入者」；或
- 加入 coverage/depth buffer，真正保留先寫入值。

本章沒有深度需求時，最簡單是修正文句，並實作 top-left 規則以避免共享邊重複覆寫。

---

### 3. 共享邊說明中的「嚴格 \(\geq\)」自相矛盾

**原句：**

> 三條邊函數皆採**嚴格** \(\geq0\) 或 \(\leq0\)

\(\geq\) 與 \(\leq\) 是非嚴格不等式；嚴格不等式是 \(>\) 與 \(<\)。

應改成：

> 三條邊函數皆採非嚴格的 \(\geq0\) 或 \(\leq0\)，因此共享邊可能由兩個三角形同時涵蓋。

---

### 4. 「兩次取樣值相同」在目前程式中不成立

**原句：**

> 共享邊可能被兩邊各寫一次，但因兩次取樣值相同，結果不變。

由於共享的 \(B,D\) 使用不同 \(w\)，前述手算已證明兩側的透視 UV 不同。此外，即使修正 \(w\)，日後兩側若刻意配置不同的 UV 接縫，取樣值也未必相同。

**修法：**

- 先讓共享幾何頂點的 clip position 與 \(w\) 一致；
- 若該邊不是材質接縫，兩側 UV 也須一致；
- 若該邊是刻意的 UV 接縫，貼圖內容需相容；
- 最好實作 top-left 規則，令共享邊只歸屬一個三角形。

不能以「重複寫入值一定相同」取代共享邊規則。

---

### 5. 魚體資料沒有真正建立所宣稱的週期接縫

**原句：**

> 為了示範 UV 接縫，右三角形使用與左三角形不同的渲染頂點記錄……

但實際兩側使用：

```python
uv_B = [0.5, 1.0]
uv_D = [0.5, 0.0]
```

第一與第二三角形都傳入完全相同的 `uv_B`、`uv_D`。這只是兩次傳入同一屬性值，並沒有展示：

- 同一幾何位置對應不同 UV；
- \(0.9\rightarrow1.1\) 的連續週期分支；
- 錯誤的 \(0.9\rightarrow0.1\) 插值；
- 接縫兩側複製完整渲染頂點。

**修法：**

明確建立兩份接縫渲染頂點，例如：

```python
uv_B_left  = np.array([0.9, 1.0])
uv_D_left  = np.array([0.9, 0.0])
uv_B_right = np.array([1.1, 1.0])
uv_D_right = np.array([1.1, 0.0])
```

但需依魚身參數化安排三角形內的連續 UV，不能只把共享邊兩側設成任意不同值。更清楚的做法是另外建立一個專用接縫四邊形，比較：

- 正確分支：\(0.9\rightarrow1.1\)；
- 錯誤分支：\(0.9\rightarrow0.1\)。

魚體主要實驗則維持正常 UV，以免同時混淆兩種目的。

---

### 6. 非對稱條紋貼圖不會測出上下翻轉

**原程式：**

```python
g = x / max(1, width - 1)
tex[y, x] = [g, g, g]
```

此貼圖只隨 \(x\) 變化，所有 row 完全相同。把

\[
y=(1-v)H-0.5
\]

錯寫成不翻轉的版本，輸出仍完全相同。因此程式沒有完成指定的「上下翻轉測試」。

**修法：**

加入真正依 \(v\) 非對稱的貼圖，例如：

```python
def generate_orientation_texture(width=8, height=8):
    tex = np.zeros((height, width, 3), dtype=np.float32)
    for y in range(height):
        for x in range(width):
            if y < height // 2:
                tex[y, x] = [1.0, 0.0, 0.0]  # 影像頂部，UV 高 v
            else:
                tex[y, x] = [0.0, 0.0, 1.0]  # 影像底部，UV 低 v
    return tex
```

再加入明確斷言：

```python
orientation = generate_orientation_texture()
assert np.allclose(
    sample_bilinear(orientation, 0.5, 0.75, wrap=False),
    [1.0, 0.0, 0.0],
)
assert np.allclose(
    sample_bilinear(orientation, 0.5, 0.25, wrap=False),
    [0.0, 0.0, 1.0],
)
```

目前測試章只寫「若貼圖上半紅、下半藍」，但主程式並未建立或測試該貼圖。

### 7. 接縫影像使用的 ramp 本身不是無縫週期貼圖

`generate_stripe_texture` 的左右邊界分別是 0 與 1。Repeat 時 \(u=1\equiv0\)，雙線性取樣會在最後一欄 1 與第一欄 0 之間混合。這可以用來測試 addressing，但它本身具有週期邊界的不連續內容。

因此原句：

> 如果接縫處理正確，接縫附近的像素灰階應連續。

需要限定。雙線性 repeat 會在約一個紋素寬度內混合邊界，但 ramp 的週期延拓不是連續函數；使用 mipmap 時還可能產生更明顯的邊界污染。

**修法：**

區分兩種測試：

1. **addressing 測試**：使用 ramp，方便辨認不同 \(u\)；
2. **外觀無縫測試**：使用週期相容貼圖，例如週期正弦或首尾內容匹配的圖樣。

不要把「Repeat 位址正確」等同於「貼圖內容天然無縫」。

---

### 8. 條紋貼圖註解用語錯置

**原 docstring：**

> 每一橫列灰階值為 \(x/(W-1)\)

因數值隨 \(x\) 變化，每一個固定 \(x\) 的直欄同色，應稱為「垂直灰階條紋」或「每一 column 的灰階值」。不是每一橫列只有一個灰階值。

這是可定位的描述錯誤，應修正以免混淆 row/column。

## 三、程式與預期結果

`write_ppm` 的 P6 寫法與 shape 檢查正確。稿件也明確標示其為線性 RGB 直接量化，沒有誤稱一般 sRGB 顯示結果。

但仍應加入：

```python
assert np.any(img_pc != img_affine)
```

此斷言不能取代實際人工檢視，但可抓出「所有 \(w\) 相同」或根本未繪製的錯誤。

### 2. 未實作 top-left 規則

本章可以把完整 top-left 規則留給第 6 章，但既然目前特別討論共享邊，就不應宣稱共享邊問題已解決。至少應寫明：

> 本簡化程式使用非嚴格邊測試，並非正式 top-left 實作；共享邊可能重複寫入。輸出僅適用於無 alpha、無深度競爭的示範。

## 四、法線、色彩、索引與邊界

- **法線：** 本章沒有法線變換，無直接法線錯誤。接縫複製頂點時應保持需要的法線屬性；不必強迫兩側法線相同，因硬邊可能刻意不同。
- **索引：** 理論上已說明 render vertex key，但程式仍未使用 index buffer。這可接受於小型教學程式，但應稱為展開後的三角形資料，而非已展示索引式網格。
- **色彩：** 線性 RGB 與 PPM 編碼界線交代清楚。
- **邊界：** \(1\times1\) 貼圖不越界的設計正確，但目前只呼叫函式，沒有斷言回傳確為 \((0.25,0.25,0.25)\)。應改為：

```python
assert np.allclose(
    sample_bilinear(tiny_tex, 12.3, -4.5, wrap=True),
    [0.25, 0.25, 0.25],
)
```

Clamp 亦同。
- **繞序：** 目前函式同時接受兩種繞序，不做背面剔除，數學上可行；若稱全書外向法線逆時針，應另以斷言檢查正式魚體資料的繞序。
