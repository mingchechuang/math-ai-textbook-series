## 一、數學與邏輯錯誤（真錯誤）

### 1. 程式碼 `is_top_left` 與理論定義在 Y-Down 座標系下的不一致性
*   **原句/代碼**：
    *   理論：「在螢幕座標（Y 向下）下，定義邊 $a\to b$ 為**左上邊**當且僅當 $(b_y-a_y)<0 \quad\text{或}\quad (b_y=a_y \land b_x>a_x)$。」
    *   代碼：
        ```python
        def is_top_left(ax, ay, bx, by):
            dy, dx = by - ay, bx - ax
            return (dy < 0.0) or (dy == 0.0 and dx > 0.0)
        ```
*   **錯誤原因**：
    1.  **座標系分析**：本章明確約定「像素原點在左上...螢幕 Y 向下」。
    2.  **Top-Left 規則的本質**：該規則旨在消除共享邊上的像素重複或縫隙。它規定：如果像素中心位於邊上，且該邊是「Top-Left」邊，則該像素屬於此三角形。
    3.  **方向性**：在 Y-Down 座標系中，「Top-Left」通常指邊向量指向**上方**（Y 減小）或**右方**（X 增大，Y 不變）。
    4.  **核對**：
        *   理論定義：$(b_y-a_y)<0$ (向上) 或 $(b_y=a_y \land b_x>a_x)$ (向右)。
        *   代碼實現：`dy < 0.0` (向上) 或 `dy == 0.0 and dx > 0.0` (向右)。
        *   **結論**：代碼與理論描述一致。
    5.  **潛在陷阱檢查**：許多文獻（如 OpenGL 規範）定義的是 NDC 空間（Y-Up）的 Top-Left。在 Y-Up 座標中，Top-Left 邊通常定義為邊向量指向**下方**（Y 減小？不，Y-Up 中向下是 Y 減小）或**左方**（X 減小）。
        *   讓我們回顧標準實現。在 Y-Down 螢幕座標中，為了讓兩個相鄰的順時針（或逆時針，依約定）三角形正確共享邊界，Top-Left 邊的定義必須與繞序一致。
        *   本章約定：「螢幕座標 Y 向下...定義正繞序為 $area2 > 0$...（視覺上為順時針）」。
        *   在 Y-Down 座標中，順時針三角形（例如 A(0,0), B(1,0), C(0,1)）：
            *   $A \to B$: 向右。$dy=0, dx>0$。符合 Top-Left。
            *   $B \to C$: 左上。$dy=1, dx=-1$。$dy>0$，不符合。
            *   $C \to A$: 向下。$dy=-1, dx=0$。$dy<0$，符合 Top-Left。
        *   相鄰三角形共享邊 $AC$。T1 邊 $C \to A$ (向下)，T2 邊 $A \to C$ (向上)。
        *   T1 的 $C \to A$: $dy=-1$ (符合 Top-Left)。
        *   T2 的 $A \to C$: $dy=1$ (不符合 Top-Left)。
        *   因此，共享邊像素歸屬 T1。
        *   如果 T2 是另一個順時針三角形（例如 A(0,0), C(0,1), D(1,1)），邊 $A \to C$ 是 $dy=1$。
        *   這看起來是正確的實現。
    6.  **但是**，有一個細微的邏輯問題：**頂點交換後的邊一致性**。
        *   程式碼中，如果 `area2 < 0`，會交換 `v0` 和 `v1`。
        *   原始頂點 `v0, v1, v2`。
        *   若 `area2 < 0`，交換後 `v0' = v1, v1' = v0, v2' = v2`。
        *   新的 `area2` 變正。
        *   邊的定義：
            *   `e0` (新 `v1' -> v2'` 即 `v0 -> v2`): `edge(x0_new, y0_new, x2_new, y2_new, ...)`?
            *   程式碼中：
                ```python
                e0 = edge(x1, y1, x2, y2, px, py)   # 對 BC 邊
                e1 = edge(x2, y2, x0, y0, px, py)   # 對 CA 邊
                e2 = edge(x0, y0, x1, y1, px, py)   # 對 AB 邊
                ```
            *   注意變數命名：`(x0, y0, ...)` 是交換後的 `v0`，`(x1, y1, ...)` 是交換後的 `v1`。
            *   `e0` 對應邊 $1 \to 2$。
            *   `e1` 對應邊 $2 \to 0$。
            *   `e2` 對應邊 $0 \to 1$。
            *   Top-Left 檢查：
                ```python
                if e0 == 0.0 and not is_top_left(x1, y1, x2, y2):
                if e1 == 0.0 and not is_top_left(x2, y2, x0, y0):
                if e2 == 0.0 and not is_top_left(x0, y0, x1, y1):
                ```
            *   這檢查的是當前頂點順序下的邊方向。
            *   由於 `area2` 被修正為正，頂點順序保證了「內部」對應 `e > 0`。
            *   在 Y-Down 座標且 `area2 > 0`（順時針）的情況下，Top-Left 規則的邊方向定義是否正確？
            *   如前所述，順時針三角形的邊，符合 `(dy < 0) or (dy == 0 and dx > 0)` 的邊會被選中。
            *   這通常是正確的實現方式之一（具體取決於 `area2 > 0` 對應的是順時針還是逆時針，以及 Top-Left 的定義）。
            *   在 Y-Down 座標中，`area2 > 0` 意味著 $x$ 向右，$y$ 向下時，叉積 $z$ 分量正向。根據右手定則，如果 $X$ 向右，$Y$ 向下，則 $Z$ 指向屏幕內（負值）。
            *   等等，右手系：$X$ 右，$Y$ 上，$Z$ 出屏幕。
            *   本章約定：「全書右手世界系...相機看向 -Z」。
            *   螢幕座標：Y 向下。
            *   如果在螢幕空間使用右手系：$X$ 右，$Y$ 下，則 $Z$ 必須指向屏幕**內**（$-Z_{world}$ 方向？不，螢幕空間通常是左手的，或者定義 $Z$ 向下）。
            *   如果我們定義螢幕空間為 $X$ 右，$Y$ 下，$Z$ 朝向觀察者（標準左手螢幕座標），則叉積行為會反轉。
            *   但如果我們堅持使用 Volume I 的「2D 外積」定義 $(x_1 y_2 - x_2 y_1)$，在 $Y$ 向下時，這個值對應於有號面積的負值（相對於 $Y$ 向上的標準數學定義）。
            *   讓我們檢查例 1：$A=(0,0), B=(4,0), C=(0,4)$。
            *   $area2 = (4-0)(4-0) - (0-0)(0-0) = 16 > 0$。
            *   在 Y-Down 座標中，A(左上), B(右上), C(左下)。
            *   從 A 到 B (右)，到 C (下)。這是**順時針**。
            *   所以 `area2 > 0` 對應順時針。
            *   程式碼假設 `area2 > 0` 時，內部 $e > 0$。
            *   對於順時針三角形，內部點在所有邊的「右側」。
            *   邊函數 $e_{AB}(P)$ 計算的是 $P$ 相對 $AB$ 的有號面積。
            *   如果 $P$ 在 $AB$ 的右側（順時針內部），$e_{AB}$ 應該是正還是負？
            *   $e_{AB}(P) = (x_B-x_A)(y_P-y_A) - (y_B-y_A)(x_P-x_A)$。
            *   取 $A(0,0), B(1,0)$。$P(0.5, -0.5)$ (下方，順時針內部)。
            *   $e = (1)(-0.5) - 0 = -0.5$。
            *   取 $P(0.5, 0.5)$ (上方，順時針外部)。
            *   $e = (1)(0.5) - 0 = 0.5$。
            *   **發現矛盾**：
                *   在 Y-Down 座標中，順時針三角形的內部點，其邊函數值通常為**負**。
                *   但是程式碼判斷 `inside = e0 > 0.0 and ...`。
                *   並且程式碼計算 `area2`，如果 `area2 < 0` 則交換頂點使 `area2 > 0`。
                *   如果 `area2 > 0` 對應順時針，而內部點邊函數為負，那麼 `inside` 判斷應該為 `e < 0`。
                *   **或者**，我們的 `area2` 計算方式在 Y-Down 座標下的符號含義與標準數學相反？
                *   標準數學（Y-Up）：逆時針 $area2 > 0$，內部 $e > 0$。
                *   Y-Down 座標：$Y$ 軸翻轉。
                *   $area2_{YDown} = -(area2_{YUp})$。
                *   如果頂點在 Y-Up 中是逆時針（$area2_{YUp} > 0$），則在 Y-Down 中是順時針（$area2_{YDown} < 0$? 不，座標值變了）。
                *   讓我們看例 1：$A(0,0), B(4,0), C(0,4)$。
                *   Y-Up 座標下：A(0,0), B(4,0), C(0,4)。逆時針。$area2 = 16 > 0$。
                *   Y-Down 座標下：A(0,0), B(4,0), C(0,4)。座標數值不變，但物理意義是 A(左上), B(右上), C(左下)。
                *   視覺上是順時針。
                *   代碼計算：$(4-0)(4-0) - (0-0)(0-0) = 16$。
                *   所以代碼計算出的 `area2` 是正的。
                *   但在 Y-Down 座標中，這個三角形是順時針的。
                *   對於順時針三角形，內部點的邊函數符號是什麼？
                *   如前測試，$A(0,0), B(1,0)$，內部點 $P(0.5, 0.5)$ (在 Y-Down 中是下方)。
                *   $e = -0.5$。
                *   所以，如果 `area2 > 0` 對應順時針，內部點應滿足 `e < 0`。
                *   **但程式碼使用 `e > 0` 作為內部條件。**
                *   這意味著程式碼假設 `area2 > 0` 對應**逆時針**（Y-Up 慣例），或者邊函數定義有反轉。
                *   然而，邊函數公式 `(bx - ax) * (py - ay) - (by - ay) * (px - ax)` 是標準的 2D 叉積。
                *   在 Y-Down 座標中，使用此公式，順時針三角形會有負的 `area2` 嗎？
                *   $A(0,0), B(1,0), C(0,1)$ (Y-Down 順時針: 右, 下, 左上)。
                *   $area2 = (1-0)(1-0) - (0-0)(0-0) = 1$。
                *   $e_{AB}$ (A->B) for P(0.5, 0.5) [內部]: $(1)(0.5) - 0 = 0.5 > 0$.
                *   **重新檢查**：
                    *   $A(0,0), B(1,0)$。
                    *   $P(0.5, 0.5)$。
                    *   $Y$ 向下。$P$ 在 $AB$ 的「下方」，即順時針三角形的內部。
                    *   $e = (1)(0.5) - (0)(0.5) = 0.5$。
                    *   所以，在 Y-Down 座標中，使用標準叉積公式，順時針三角形的內部點邊函數為**正**。
                    *   為什麼？
                    *   在 Y-Up 中，順時針是負面積。
                    *   在 Y-Down 中，座標 $y$ 翻轉。
                    *   叉積 $x_1 y_2 - x_2 y_1$。
                    *   如果 $y$ 翻轉，$y_2 \to -y_2, y_1 \to -y_1$。
                    *   $x_1 (-y_2) - x_2 (-y_1) = -(x_1 y_2 - x_2 y_1)$。
                    *   所以符號翻轉。
                    *   Y-Up 中，逆時針（正面積）$\to$ Y-Down 中，順時針（負面積？不，數值變負？）。
                    *   例：Y-Up 逆時針 $A(0,0), B(1,0), C(0,1)$。$Area = 0.5$。
                    *   Y-Down 座標 $A(0,0), B(1,0), C(0,1)$。$Area_{calc} = (1)(1) - (0)(0) = 1$。
                    *   視覺上：A(左上), B(右上), C(左下)。順時針。
                    *   所以，Y-Down 座標中，使用標準公式，**順時針**三角形的 `area2` 是**正**的。
                    *   且內部點 $e > 0$。
                    *   **結論**：程式碼邏輯 `area2 > 0` 且 `e > 0` 在 Y-Down 座標中是**正確**的（對應順時針三角形）。
    7.  **Top-Left 規則的方向性**：
        *   我們已確認程式碼使用順時針三角形（`area2 > 0`）。
        *   在 Y-Down 座標中，順時針三角形的 Top-Left 邊定義：
        *   邊向量指向「上」($y$ 減小) 或 「右」($y$ 同, $x$ 增)。
        *   代碼：`dy < 0` (上) 或 `dy == 0 and dx > 0` (右)。
        *   這與理論描述一致。
        *   **但是**，我們需要確認這是否正確地解決了共享邊問題。
        *   相鄰三角形共享邊，方向相反。
        *   如果邊向量指向上（$dy < 0$），則 $A \to B$ 是 Top-Left。
        *   $B \to A$ 則 $dy > 0$，不是 Top-Left。
        *   所以像素歸屬 $A \to B$ 的三角形。
        *   這是正確的 Top-Left 實現（在 Y-Down 順時針約定下）。

    **結論**：數學邏輯似乎正確。之前的疑慮（關於 $Y$ 軸方向）通過具體數值驗證被消解。Y-Down 座標中，標準叉積公式對順時針三角形產生正值 `area2` 和正值內部邊函數。

### 2. 習題 2 解答中的覆蓋次數統計
*   **原句**：
    > (b) ... 覆蓋0次、1次、2次分別為144、528、352個，聯集共880個。
*   **核對**：
    *   這需要實際計算。由於無法執行程式，我們檢查邏輯合理性。
    *   $T_1: (0,0), (32,0), (0,32)$。區域 $x+y \le 32, x \ge 0, y \ge 0$。
    *   $T_2: (0,0), (0,32), (32,32)$。區域 $y \ge x, x \ge 0, y \le 32$。
    *   $T_3: (16,0), (32,16), (16,32)$。
        *   邊 1: $(16,0) \to (32,16)$。$y = x - 16$。
        *   邊 2: $(32,16) \to (16,32)$。$y = -x + 48$。
        *   邊 3: $(16,32) \to (16,0)$。$x = 16$。
        *   內部：$x \ge 16$, $y \ge x-16$, $y \le -x+48$。
    *   $T_1 \cap T_2$: $x+y \le 32$ 且 $y \ge x$。
        *   交點：$x+x=32 \Rightarrow x=16, y=16$。
        *   區域為三角形 $(0,0)-(0,32)-(16,16)$? 不，$(0,0)$ 是頂點。
        *   $T_1$ 邊 $(0,0)-(0,32)$ 是 $x=0$。$T_2$ 邊 $(0,0)-(0,32)$ 是 $x=0$。
        *   它們共享邊 $x=0$。
        *   $T_1$ 在 $x \ge 0$。$T_2$ 在 $x \ge 0$。
        *   $T_1$ 在 $y \le 32-x$。$T_2$ 在 $y \ge x$。
        *   交疊區域：$0 \le x \le 16$, $x \le y \le 32-x$。
    *   $T_3$ 的位置：$x \in [16, 32]$。
    *   $T_1$ 在 $x=16$ 處，$y \in [0, 16]$。
    *   $T_3$ 在 $x=16$ 處，$y \in [0, 32]$。
    *   $T_2$ 在 $x=16$ 處，$y \in [16, 32]$ (因為 $y \ge x=16$)。
    *   看起來 $T_3$ 與 $T_1, T_2$ 有重疊。
    *   具體數值 144, 528, 352 總和 1024。
    *   $144+528+352 = 1024$。
    *   這表示每個像素至少被覆蓋一次？
    *   $T_1 \cup T_2$ 覆蓋了 $x \le 16$ 的大部分，以及 $x > 16$ 的一部分？
    *   $T_1$: $x+y \le 32$。
    *   $T_2$: $y \ge x$。
    *   $T_1 \cup T_2$ 覆蓋：
        *   $x < 16$: $T_1$ 覆蓋 $y \in [0, 32-x]$。$T_2$ 覆蓋 $y \in [x, 32]$。
            *   並集：$y \in [0, 32]$ (因為 $32-x > x$)。
            *   所以 $x < 16$ 時，全部覆蓋。
        *   $x = 16$: $T_1$ 覆蓋 $y \in [0, 16]$。$T_2$ 覆蓋 $y \in [16, 32]$。
            *   並集：$y \in [0, 32]$。
        *   $x > 16$:
            *   $T_1$: $y \in [0, 32-x]$。
            *   $T_2$: $y \in [x, 32]$。
            *   因為 $x > 16 \Rightarrow x > 32-x$。
            *   兩段分開。中間有縫隙 $y \in (32-x, x)$。
            *   $T_3$ 覆蓋 $y \in [x-16, -x+48]$。
            *   縫隙長度：$x - (32-x) = 2x - 32$。
            *   $T_3$ 是否覆蓋縫隙？
            *   $T_3$ 的 $y$ 範圍：$x-16$ 到 $48-x$。
            *   縫隙：$32-x < y < x$。
            *   檢查邊界：
                *   $32-x$ vs $x-16$: $32-x - (x-16) = 48 - 2x$。
                    *   若 $x < 24$， $32-x > x-16$。
                    *   若 $x > 24$， $32-x < x-16$。
                *   這表明覆蓋情況複雜。
    *   解答給出的數字 144 (0次), 528 (1次), 352 (2次) 總和 1024。
    *   如果 144 個像素是 0 次，意味著 $T_1, T_2, T_3$ 的並集沒有覆蓋整個 $32 \times 32$。
    *   這在幾何上是可能的，因為 $T_3$ 較小。
    *   **結論**：數字邏輯自洽（總和 1024），且幾何分析顯示覆蓋不完全覆蓋整個正方形是合理的。無明顯錯誤。

## 三、重算具體例題

**例 1 核對**：
$A(0,0), B(4,0), C(0,4)$。
$area2 = 16$。
$P(1.5, 1.5)$。
$e_{BC}$ (B->C): $(0-4)(1.5-0) - (4-0)(1.5-4) = -4(1.5) - 4(-2.5) = -6 + 10 = 4$。
$e_{CA}$ (C->A): $(0-0)(1.5-4) - (0-4)(1.5-0) = 0 - (-4)(1.5) = 6$。
$e_{AB}$ (A->B): $(4-0)(1.5-0) - (0-0)(1.5-0) = 6$。
$\lambda_A = 4/16 = 0.25$。
$\lambda_B = 6/16 = 0.375$。
$\lambda_C = 6/16 = 0.375$。
Sum = 1。
正確。

**例 3 核對**：
$w_A=1, w_B=2$。
$z_A=-1, z_B=1$。
Linear: $0.5(-1) + 0.5(1) = 0$。
Perspective:
$1/w_A = 1, 1/w_B = 0.5$。
$\sum \lambda / w = 0.5(1) + 0.5(0.5) = 0.75$。
$\sum \lambda z / w = 0.5(-1)(1) + 0.5(1)(0.5) = -0.5 + 0.25 = -0.25$。
$z_P = -0.25 / 0.75 = -1/3 = -0.333$。
正確。
