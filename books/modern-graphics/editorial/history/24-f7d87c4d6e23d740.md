# 第24章 渲染誤差、降噪與效能驗證

## 學習目標與先備知識
本章建立量化評估渲染品質與效能的嚴格框架。讀者需具備第22章路徑追蹤基礎及第14章線性色彩處理。重點在於：
1. 定義「正確性」：以高樣本參考圖或解析解為基準。
2. 定義「誤差」：區分偏誤（Bias）、變異數（Variance）與均方誤差（MSE）。
3. 定義「效能」：以時間為單位，但必須區分單次渲染時間與統計穩定性。

本節使用線性 RGB 空間進行計算。最終輸出前的 sRGB 轉換不影響線性誤差的相對比較，但視覺評估需在 sRGB 域進行。所有測試皆基於合成場景，確保可重現性。

## 問題與直覺
在 CPU 路徑追蹤中，我們無法獲得「真實」物理光場。我們能獲得的是蒙特卡洛估計 $\hat{I}$。其品質由兩個維度決定：
- **準確度**：$\hat{I}$ 是否接近真值 $I_{true}$？
- **精確度**：多次運行結果的一致性（噪聲大小）。

直覺上，增加每像素樣本數（Samples per Pixel, spp）會降低噪聲。但效能與品質存在權衡。我們需要一套指標來客觀判斷：
1. **MSE**：衡量整體差異。
2. **相對偏差**：檢測系統性錯誤（如漏光、能量不守恒）。
3. **噪聲指標**：檢測隨機波動。
4. **時間記錄**：評估計算成本。

關鍵原則：**未執行的程式不得假設其輸出或效能**。所有結論必須基於實際代碼執行結果或明確標註為「預期」。

## 數學與幾何推導
設參考圖為 $R$，測試圖為 $T$，像素數量為 $N$。
1. **均方誤差 (MSE)**：
   $$ MSE = \frac{1}{N} \sum_{i=1}^{N} (T_i - R_i)^2 $$
   MSE 同時包含偏誤與變異數貢獻。若 $R$ 為真值，$MSE = \text{Bias}^2 + \text{Variance}$。

2. **平均絕對偏差 (MAE)**：
   $$ MAE = \frac{1}{N} \sum_{i=1}^{N} |T_i - R_i| $$
   MAE 對離群值較不敏感，適合檢測局部錯誤。

3. **結構相似指數 (SSIM) 概念**：
   雖然本章不實作 SSIM，但需注意：純 MSE 可能忽略結構資訊。例如，高頻噪聲與模糊圖像可能具有相同的 MSE，但視覺差異巨大。在合成驗證中，若 $R$ 是平滑解析解，MSE 足夠；若 $R$ 是複雜場景，需結合視覺檢查。

4. **取樣噪聲估計**：
   若 $T$ 是多樣本平均結果，其標準誤差 (SE) 與樣本數 $n$ 成反比：$SE \propto 1/\sqrt{n}$。
   通過比較 $n$ 與 $2n$ 的 MSE 變化，可驗證是否遵循蒙特卡洛收斂速率。若 $MSE_{2n} \approx \frac{1}{2} MSE_n$（在偏誤可忽略時），則證明噪聲主導誤差。

5. **效能指標**：
   $$ \text{Samples/sec} = \frac{N \times n}{\text{Time}} $$
   此指標比 FPS 更具可比性，因為它歸一化了解析度與樣本數。

## 逐步手算例題
**案例1：偏誤與噪聲分離**
假設真值 $R=1.0$。
- 實驗 A：100 次取樣，結果皆為 $1.1$。
  $MSE = \frac{1}{100} \sum (1.1-1.0)^2 = 0.01$。
  $MAE = 0.1$。
  此處純為**偏誤**（Bias = 0.1），無噪聲。
- 實驗 B：100 次取樣，結果在 $0.5$ 到 $1.5$ 均勻分佈，平均為 $1.0$。
  均勻分佈 $[a, b]$ 的變異數為 $\frac{(b-a)^2}{12}$。
  $Var = \frac{(1.5-0.5)^2}{12} = \frac{1}{12} \approx 0.0833$。
  $MSE \approx 0.0833$。
  此處純為**噪聲**（變異數），無偏誤。

**結論**：實驗 B 的 MSE 高於實驗 A，但實驗 B 更接近無偏估計。若目標是「準確平均」，實驗 B 較好；若目標是「單次預測最小化平方錯誤」且已知偏誤，實驗 A 可能誤導。在渲染中，我們追求**無偏**且**低變異數**。

**案例2：收斂速率驗證**
假設噪聲主導。
- $n=16$ spp，$MSE_{16} = 0.04$。
- $n=64$ spp，$MSE_{64}$ 預期約為 $0.04 \times (16/64) = 0.01$。
若實測 $MSE_{64} = 0.005$，表示有系統性錯誤（偏誤）隨樣本數減少，或算法存在其他收斂機制。

## 實作與程式
Python 3.10+，使用 NumPy。此程式比較兩種不同樣本數下的渲染結果，並計算 MSE 與時間。
*註：此處不執行完整路徑追蹤器，而是模擬一個具有已知噪聲特性的函數，以驗證評估指標的計算邏輯。讀者應將此框架套用到自己的路徑追蹤器上。*

```python
import numpy as np
import time

def render_simulated(scene_id, spp, seed):
    """
    模擬渲染函式。
    返回: (image, elapsed_time)
    image: (H, W, 3) float32 array
    """
    H, W = 16, 16  # 低解析度以加快測試
    np.random.seed(seed)
    
    # 模擬真值：常數 0.5
    R = np.full((H, W, 3), 0.5)
    
    # 模擬帶噪聲的估計
    # 噪聲標準差隨 spp 減少：sigma = 1.0 / sqrt(spp)
    sigma = 1.0 / np.sqrt(spp)
    noise = np.random.normal(0, sigma, (H, W, 3))
    T = R + noise
    
    # 模擬計算時間（純虛構，僅用於演示結構）
    # 真實環境中應使用 time.perf_counter()
    simulated_time = 0.01 * (100 / spp)
    
    return T, simulated_time

def calculate_metrics(test_img, ref_img):
    """
    計算 MSE 和 MAE。
    """
    diff = test_img - ref_img
    mse = np.mean(diff ** 2)
    mae = np.mean(np.abs(diff))
    return mse, mae

def run_experiment():
    # 生成高樣本參考圖（作為近似真值）
    ref_img, _ = render_simulated(scene_id=1, spp=1024, seed=42)
    
    # 測試不同 spp 的結果
    for spp in [1, 4, 16, 64]:
        # 多次運行以獲得穩定的 MSE 平均
        mse_list = []
        mae_list = []
        total_time = 0.0
        runs = 5
        
        for i in range(runs):
            seed = 100 + i
            test_img, t = render_simulated(scene_id=1, spp=spp, seed=seed)
            mse, mae = calculate_metrics(test_img, ref_img)
            mse_list.append(mse)
            mae_list.append(mae)
            total_time += t
        
        avg_mse = np.mean(mse_list)
        avg_mae = np.mean(mae_list)
        avg_time = total_time / runs
        samples_per_sec = (16 * 16 * 3 * spp) / avg_time
        
        print(f"spp={spp:3d} | Avg MSE: {avg_mse:.6f} | Avg MAE: {avg_mae:.4f} | Avg Time: {avg_time:.4f}s | Rate: {samples_per_sec:.1f} spp/s")

if __name__ == "__main__":
    run_experiment()
```

## 測試與預期結果
執行上述程式，預期輸出趨勢：
1. **MSE 隨 spp 增加而減小**：從 $spp=1$ 到 $spp=64$，MSE 應大致按 $1/spp$ 比例下降。
2. **MAE 同樣減小**：但下降幅度略緩於 MSE（因為絕對值對大噪聲較不敏感）。
3. **時間隨 spp 增加而增加**：線性關係。
4. **spp/s 速率穩定**：若無其他開銷，速率應恆定。若速率下降，表示存在緩存未命中或內存瓶頸。

*注意：此為模擬數據，僅驗證指標計算邏輯。實際路徑追蹤器的噪聲結構更為複雜。*

## 除錯與常見陷阱
1. **參考圖偏差**：若參考圖本身樣本數不足，其誤差會被計入測試圖的誤差。解決方案：使用解析解或極高樣本數（如 10k spp）的參考圖。
2. **色彩空間混淆**：務必在線性 RGB 空間計算 MSE。若在 sRGB 空間計算，高亮度區域的誤差會被低估，低亮度區域被高估。
3. **噪聲與模糊**：簡單的 Box 模糊降噪會增加 MSE（因為引入偏誤），但可能改善視覺品質。評估時需區分「統計誤差」與「主觀品質」。
4. **時間計量**：包含 I/O 和數據轉換的時間會扭曲渲染效能評估。應精確計時核心計算區塊。
5. **隨機種子**：跨 seed 比較時，必須固定所有其他參數。不同 seed 的結果應具有相似的統計特性，但單像素值不同。

## 養殖數位分身案例
在養場監控合成场景中，我們需要驗證水體散射模型的實現是否正確。
1. **基準測試**：在無魚體、單色光源下，渲染一池靜水。理論上，深度 $d$ 處的衰減應符合 Beer-Lambert 定律 $I = I_0 e^{-\sigma d}$。
2. **誤差分析**：計算渲染結果與解析解的 MSE。若 MSE 隨水深增加而呈現非預期模式，可能暗示散射係數 $\sigma$ 或折射率 $n$ 錯誤。
3. **降噪驗證**：水體散射計算成本高。比較 1 spp 與 64 spp 的結果，確認噪聲是否隨樣本數減少。若 64 spp 的 MSE 未顯著下降，可能存在未收斂的隨機採樣或算法錯誤。
4. **效能記錄**：記錄不同水深與散射係數下的渲染時間，建立效能模型，用於後續全場景渲染的資源估計。

## 習題
1. **手算**：給定參考像素 $R=[1.0, 2.0]$ 和測試像素 $T=[1.1, 1.8]$，計算 MSE 和 MAE。
2. **程式測試**：修改 `run_experiment`，使 `render_simulated` 引入一個常數偏誤 $+0.05$。觀察 MSE 在 $spp \to \infty$ 時的極限值。這说明了什麼？
3. **反例/除錯**：假設你的路徑追蹤器在處理金屬表面時出現黑色斑塊。設計一個測試案例，通過 MSE 分析判斷這是偏誤（能量損失）還是噪聲（隨機取樣失敗）。
4. **整合應用**：寫一個函式，輸入兩張影像和對應的渲染時間，輸出比較報告（包含 MSE、MAE、時間、spp/s）。用於比較兩個不同配置（如：BVH vs 暴力求交）的效能與品質。

## 習題解答
1. 
   $diff = [0.1, -0.2]$
   $diff^2 = [0.01, 0.04]$
   $MSE = (0.01 + 0.04) / 2 = 0.025$
   $MAE = (|0.1| + |-0.2|) / 2 = 0.15$

2. 
   當 $spp \to \infty$，噪聲項趨近於 0。
   $T_i \to R_i + 0.05$
   $MSE \to \frac{1}{N} \sum (0.05)^2 = 0.0025$
   這說明 MSE 存在一個非零的下限，代表**偏誤**。僅增加樣本數無法消除偏誤，必須修正算法。

3. 
   - **設計**：渲染一個理想漫反射金屬球（Lambertian），背景黑色。
   - **測試**：比較 1 spp 和 1000 spp。
   - **判斷**：
     - 若 1000 spp 的圖像中，黑色斑塊仍然存在且位置固定，則為**偏誤**（可能因法線錯誤或 BRDF 錯誤導致能量未正確採樣）。
     - 若 1000 spp 的圖像中，斑塊消失或變成均勻噪聲，則為**噪聲**（可能因重要性取樣不足）。
     - MSE 比較：偏誤情況的 MSE 不會隨 spp 顯著下降；噪聲情況的 MSE 會按 $1/spp$ 下降。

4. 
   函式邏輯：
   ```python
   def compare_renders(img1, time1, img2, time2, spp1, spp2, W, H, C):
       mse1, mae1 = calculate_metrics(img1, ref) # 假設 ref 已知或互相比較
       mse2, mae2 = calculate_metrics(img2, ref)
       rate1 = (W*H*C*spp1) / time1
       rate2 = (W*H*C*spp2) / time2
       report = {
           "MSE1": mse1, "MAE1": mae1, "Rate1": rate1,
           "MSE2": mse2, "MAE2": mae2, "Rate2": rate2
       }
       return report
   ```
   *注意：若無參考圖，可計算兩圖之間的差異以評估一致性，但無法評估絕對準確度。*
