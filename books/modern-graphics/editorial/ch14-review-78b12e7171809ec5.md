# 審稿結論

本稿涵蓋 UV、透視正確插值、接縫與取樣模式，但存在多項會直接造成錯誤輸出或誤導實作的問題：手算的 \(v\) 值錯誤、雙線性取樣在邊界會越界、預期顏色計算錯誤、週期接縫處理敘述錯誤、微分足跡方向顛倒，以及習題 3 的數值分析與修法不正確。此外，實驗尚未真正完成「把 checker 貼上魚體」及接縫、上下翻轉、透視插值的完整測試。

## 一、必須修正的實質錯誤

### 1. UV 角點與影像索引公式在端點越界

**原句／公式：**

> \(x_{\text{pix}}=\lfloor uW\rfloor\)  
> \(y_{\text{pix}}=\lfloor(1-v)H\rfloor\)

當 \(u=1\) 時得到 \(x_{\text{pix}}=W\)；當 \(v=0\) 時得到 \(y_{\text{pix}}=H\)，兩者都超出合法索引：

\[
0\le x_{\text{pix}}<W,\qquad 0\le y_{\text{pix}}<H.
\]

**修法：**

若是最近鄰且採 clamp，可寫：

\[
x_{\text{pix}}=\min(W-1,\lfloor uW\rfloor),
\]

\[
y_{\text{pix}}=\min(H-1,\lfloor(1-v)H\rfloor).
\]

但雙線性取樣最好統一採 texel-center 約定：

\[
x=uW-\frac12,\qquad y=(1-v)H-\frac12,
\]

再依 repeat 或 clamp 分別處理四個取樣 tap。必須清楚區分：

- UV 區間的邊界；
- texel 中心 \((i+\tfrac12)/W\)；
- 陣列索引 \(i\)。

目前正文、程式與預期結果混用了不同約定。

### 2. 例題 1 的 \(v\) 值算錯，程式註解與預期輸出也隨之錯誤

**原句：**

> 程式應輸出 `Perspective Correct UV: (0.2093, 0.2093)`

給定：

\[
(w_0,w_1,w_2)=(1,2,3),
\]

\[
UV_0=(0,0),\quad UV_1=(1,0),\quad UV_2=(0,1),
\]

\[
(\lambda_0,\lambda_1,\lambda_2)=(0.5,0.3,0.2).
\]

分母為：

\[
D=\frac{0.5}{1}+\frac{0.3}{2}+\frac{0.2}{3}
=\frac{43}{60}.
\]

\(u\) 分子為：

\[
N_u=0+\frac{0.3}{2}+0=\frac{3}{20},
\]

所以：

\[
u=\frac{3/20}{43/60}=\frac9{43}\approx0.209302.
\]

\(v\) 分子則為：

\[
N_v=0+0+\frac{0.2}{3}=\frac1{15},
\]

所以：

\[
v=\frac{1/15}{43/60}=\frac4{43}\approx0.093023.
\]

**正確結果：**

\[
UV_p=\left(\frac9{43},\frac4{43}\right)
\approx(0.2093,0.0930).
\]

線性插值則是：

\[
UV_{\text{linear}}=(0.3,0.2).
\]

**修法：**

- 將預期輸出改成 `(0.2093, 0.0930)`。
- 同時斷言 \(u\) 與 \(v\)，目前只檢查 \(u\)，因此沒有抓出錯誤：

```python
assert np.allclose(
    [u_pc_verify, v_pc_verify],
    [9.0 / 43.0, 4.0 / 43.0],
    atol=1e-6,
)
```

### 3. 雙線性取樣函式在 \(u=1\) 或 \(v=0\) 時會索引越界

**原程式：**

```python
x = u * W
y = (1.0 - v) * H

x0 = int(np.floor(x))
y0 = int(np.floor(y))
...
if x < 0 or x > W or y < 0 or y > H:
```

若 \(u=1\)，則 \(x=W\)，但條件 `x > W` 為假，之後：

```python
c00 = tex[y0, x0]
```

會存取 `tex[..., W]`。同理，\(v=0\) 時會存取 `tex[H, ...]`。

此外，超界分支在重新夾制後仍使用：

```python
x0 = floor(x)
```

若夾到 `W - 0.5` 尚不會越界，但整體規則與前述 `x=u*W` 的 texel-center 解釋仍不一致。

**修法：**

先明確選擇 addressing mode，再處理座標。Clamp 版本可採：

```python
def sample_texture_bilinear_clamp(tex, u, v):
    h, w, channels = tex.shape
    if channels != 3:
        raise ValueError("預期 RGB 貼圖")

    u = float(np.clip(u, 0.0, 1.0))
    v = float(np.clip(v, 0.0, 1.0))

    x = u * w - 0.5
    y = (1.0 - v) * h - 0.5

    x0_raw = int(np.floor(x))
    y0_raw = int(np.floor(y))
    fx = x - x0_raw
    fy = y - y0_raw

    x0 = min(max(x0_raw, 0), w - 1)
    x1 = min(max(x0_raw + 1, 0), w - 1)
    y0 = min(max(y0_raw, 0), h - 1)
    y1 = min(max(y0_raw + 1, 0), h - 1)

    c00 = tex[y0, x0]
    c01 = tex[y0, x1]
    c10 = tex[y1, x0]
    c11 = tex[y1, x1]

    return (
        c00 * (1-fx) * (1-fy)
        + c01 * fx * (1-fy)
        + c10 * (1-fx) * fy
        + c11 * fx * fy
    )
```

Repeat 版本則要對每個 tap 的整數索引取模，不能只把最終浮點 UV 或部分索引隨意夾制。

### 4. 目前的顏色預期是依錯誤 \(v\) 計算，且只給模糊範圍

**原句：**

> \(v=0.2093\) 對應 \(y\approx6.32\)

正確 \(v=4/43\)，依目前程式的座標規則：

\[
x=8\cdot\frac9{43}=\frac{72}{43}\approx1.6744,
\]

\[
y=8\left(1-\frac4{43}\right)
=\frac{312}{43}\approx7.2558.
\]

目前程式會把 \(y_1\) 夾成 7，使上下兩列實際相同。第 7 列中：

- \((x=1,y=7)\)：白；
- \((x=2,y=7)\)：黑。

因此依現有程式，輸出每個 RGB 分量約為：

\[
1-f_x=1-\left(\frac{72}{43}-1\right)
=\frac{14}{43}\approx0.32558.
\]

也就是預期約：

```text
Sampled Color (Linear RGB): [0.32558 0.32558 0.32558]
```

線性錯誤插值 \(UV=(0.3,0.2)\) 依現有程式則得到約：

\[
0.52
\]

的灰階值。

但這只是依目前不一致的取樣規則重算；建議先修正取樣座標約定，再重新列出精確預期結果。

### 5. 週期接縫不能「先取分數部分再插值」

**原句：**

> 若使用 Wrap，插值計算需先對 \(u,v\) 執行分數部分處理，或確保取樣函數處理溢出。

這兩種操作不等價。若一條週期接縫兩端是 \(u=0.9\) 與 \(u=0.1\)，直接插值會經過 \(0.5\)，即繞過整張貼圖；先各自取分數部分也無法修復，因為它們原本就位於 \([0,1)\)。

**正確作法：**

1. UV 展開資料應在接縫處複製渲染頂點。
2. 對跨週期的三角形使用同一個連續分支，例如把 \(0.1\) 表示為 \(1.1\)。
3. 先在連續值 \(0.9\rightarrow1.1\) 間插值。
4. 最後在取樣器套用 repeat，使 \(1.0\equiv0.0\)。

應將原句改為：

> 週期接縫附近必須先選擇連續的 UV 分支，再插值；repeat 只在取樣階段套用。不可逐頂點先取小數部分，否則可能沿錯誤方向跨越整張貼圖。

### 6. 「UV 定義在頂點上」敘述過度簡化，索引語意需修正

**原句：**

> UV 座標是定義在頂點上的屬性。

以及：

> 頂點索引必須重複。即一個 3D 頂點可能對應多個 UV 頂點。

更精確的說法是 UV 通常定義在**面角／render vertex** 上。同一幾何位置在接縫、硬法線或不同材質邊界可擁有多組屬性。

典型 GPU 單一索引格式中，position、normal、UV 共用一個索引，所以必須複製完整渲染頂點；不能只說「UV 頂點」重複。OBJ 則可分別索引位置、UV 與法線，但匯入 GPU buffer 時通常仍要展開成唯一屬性組合。

建議補上：

\[
\text{render vertex key}
=(i_{\text{position}},i_{\text{normal}},i_{\text{uv}}).
\]

這也能與第 7 章索引資料結構銜接。

### 7. 微分足跡的遠近與大小關係寫反

**原句：**

> 當三角形在屏幕上覆蓋較小區域時，UV 變化緩慢，取樣精細。當三角形很大或遠離相機時，一個像素可能對應貼圖中很大的區域（UV 變化快）。

對固定 UV 範圍而言：

- 投影後三角形越小，UV 對螢幕像素的變化通常越快；
- 投影後三角形越大，單一螢幕像素涵蓋的 UV 區域通常越小；
- 「很大」不能與「遠離相機」並列成同一方向。

此外：

> 若足跡大於 1 像素/UV單位

維度也不清楚。Jacobian

\[
J=
\begin{bmatrix}
\partial u/\partial x_s & \partial u/\partial y_s\\
\partial v/\partial x_s & \partial v/\partial y_s
\end{bmatrix}
\]

的量綱是 UV 單位／螢幕像素。轉成 texel／pixel 後可估計：

\[
\rho_x=
\sqrt{
\left(W\frac{\partial u}{\partial x_s}\right)^2+
\left(H\frac{\partial v}{\partial x_s}\right)^2
},
\]

\[
\rho_y=
\sqrt{
\left(W\frac{\partial u}{\partial y_s}\right)^2+
\left(H\frac{\partial v}{\partial y_s}\right)^2
},
\]

\[
\rho=\max(\rho_x,\rho_y),\qquad
\ell=\max(0,\log_2\rho).
\]

本章即使不實作 mipmap，也應至少正確交代此維度與 LOD 關係。

### 8. 習題 3 對小 \(w\) 的分析錯誤

**原題與解答：**

> 三個頂點 \(w\) 值極小（如 \(10^{-6}\)），導致分母接近零……

但若三個 \(w_i=10^{-6}\) 且重心權重和為 1：

\[
\sum_i\frac{\lambda_i}{w_i}=10^6,
\]

分母不是接近零，而是很大。分子也同比例變大，比例在精確算術下會正常抵消。

真正危險的情況包括：

- \(w_i\) 接近零而 \(x_i/w_i,y_i/w_i\) 放大；
- 三角形跨越 \(w=0\)；
- \(w_i\) 異號造成分母抵消；
- 在近裁切面之前就直接投影；
- 浮點溢位或有效位數損失。

**原修法：**

> 對 \(w\) 進行正規化，即除以 \(\min(w_i)\) 或 \(\max(w_i)\)

此法不應作為一般修正。任意改動各頂點 \(w\) 會破壞投影插值關係。

**正確修法：**

- 在齊次裁剪空間先對近平面及有效 clip half-space 裁切；
- 不光柵化穿越 \(w=0\) 的未裁切三角形；
- 檢查

\[
D=\sum_i\lambda_i/w_i
\]

是否有限且遠離零；
- epsilon 應依數值尺度設定，不應任意把 \(w\) 映射到 \([1,100]\)。

題目本身也應改成「某些 \(w_i\) 接近零或異號」而非「三個 \(w\) 都是 \(10^{-6}\)」。

### 9. 球面旋轉習題答案不應保留兩個互斥結果

**原句：**

> 對應 \(\phi'=\pi/2\) 或 \(3\pi/2\)。

全書已固定右手系與主動正旋轉，因此應給唯一答案。題目採：

\[
P(\phi,\theta)=
(\sin\theta\cos\phi,\cos\theta,\sin\theta\sin\phi).
\]

初始：

\[
P(0,\pi/2)=(1,0,0).
\]

標準右手主動 \(Y\) 軸旋轉：

\[
R_y(\alpha)=
\begin{bmatrix}
\cos\alpha&0&\sin\alpha\\
0&1&0\\
-\sin\alpha&0&\cos\alpha
\end{bmatrix}.
\]

取 \(\alpha=\pi/2\)：

\[
R_y(\pi/2)(1,0,0)^T=(0,0,-1)^T.
\]

因參數式中 \(z=\sin\theta\sin\phi\)，所以：

\[
\theta'=\frac{\pi}{2},\qquad
\phi'=\frac{3\pi}{2},
\]

\[
(u',v')=
\left(\frac34,\frac12\right).
\]

另外，稿中「原點位於正前方」不合適；此點明確位於 \(+X\)，而相機局部看向 \(-Z\)。

### 10. 接縫的目標不是「UV 連續」

**原句：**

> 需確保 UV 在接縫處連續，避免渲染時出現裂縫。

接縫正是 UV 不連續的位置。應確保的是：

- 幾何位置一致；
- 接縫兩側貼圖內容相容；
- repeat 邊界或紋理 padding 正確；
- mipmap 與雙線性過濾不從錯誤區域滲色。

建議改為：

> 接縫兩側的 UV 可以不連續，但對應的貼圖內容與邊界 padding 必須相容，使過濾後的表面外觀盡量連續。

## 二、實驗與測試完整性不足

### 1. 未完成指定的魚體貼圖實驗

章目要求：

> 把 checker 貼上魚體；測接縫、上下翻轉及透視插值。

目前程式只計算單一虛擬像素，沒有：

- 魚體或簡化魚形網格；
- 三角形光柵化；
- 影像輸出；
- 接縫兩側比較；
- 上下翻轉的可判定非對稱貼圖；
- 透視正確與錯誤插值的並排輸出。

至少應使用由數個三角形組成的簡化魚身，輸出 PPM，並加入：

1. 非上下對稱測試貼圖，例如上半紅、下半藍；
2. 接縫三角形，例如連續 UV 使用 \(0.9,1.0,1.1\)；
3. 相同畫面分別採 affine UV 與 perspective-correct UV；
4. 自動斷言關鍵像素或數值。

純 checker 常具有對稱性，未必能可靠檢出上下翻轉。

### 2. Wrap 測試不充分

**原測試：**

> 若將 \(uv_1\) 改為 \((2.0,0.0)\)……

這只是一個修改建議，沒有明確輸入、預期 UV 或預期顏色。應加入至少：

\[
-0.2\bmod1=0.8,\quad 1.0\bmod1=0,\quad 2.0\bmod1=0.
\]

並測試週期接縫中點，例如連續插值 \(0.9\) 與 \(1.1\) 的中點應為 \(1.0\)，repeat 後為 \(0.0\)，而不是錯誤地變成 \(0.5\)。

解答中使用：

這不足以驗證邊界，也沒有解決原函式的端點越界。依章節要求，應提供完整函式與斷言。

## 三、座標、法線、色彩與邊界核對

- **座標系：** V 向上、影像 Y 向下的主約定正確，但端點映射不正確；球面旋轉答案亦未落實右手系。
- **維度：** UV 為無量綱參數；微分 Jacobian 為 UV／pixel，乘 \(W,H\) 後才是 texel／pixel。現稿「像素/UV單位」需修正。
- **法線：** 本章未進行法線計算，無直接法線公式錯誤；但魚體實驗若加入背面剔除，須維持外向法線與逆時針繞序。本章不必硬加法線內容。
- **色彩：** 將 checker 宣告為線性 RGB 可以成立；若未從 sRGB 檔案載入，就不需解碼。建議明說陣列數值是人工建立的線性值。
- **索引：** 接縫處應說明複製完整渲染頂點或建立 position/UV 的分離索引。
- **邊界：** \(u=1,v=0\) 越界是目前最直接的程式缺陷；repeat 與 clamp 必須分開定義。
- **退化情況：** `perspective_correct_uv` 應檢查 \(w_i\neq0\)、輸入有限、重心權重和近似 1，以及分母不接近零。
