# 審稿結果

本版已修正先前多數核心問題：深度語義、像素中心、輸出檔案、量綱、同步更新與手算均大致正確。剩餘問題主要是初始化宣稱與實作不符、姿態標註不存在、遮擋測試不足、習題解答仍不可直接實作，以及正文未達最低字數。

## 一、必須修正的實質問題

### 1. 初始化沒有實作所宣稱的最小間距

**原句：**

```python
# 確保最小間距，簡化處理：隨機生成後若過近則重試或接受
pos = self.rng.uniform(-self.bounds/2, self.bounds/2)
```

**問題：**

程式既沒有檢查距離，也沒有重試。「重試或接受」不是確定的演算法，與前文所稱處理完全重合退化不符。若接受過近位置，就沒有「確保最小間距」。

**修法：**

二選一：

- 刪除「確保最小間距」宣稱，明示隨機初始化仍可能產生近重合點；
- 實作有最大重試次數的 rejection sampling，失敗時明確拋出例外。

若使用 ID 決定退化方向，應是確定性的方向，不宜稱「基於 ID 的隨機擾動」，否則需另交代 seed。

---

### 2. 前文宣稱有精確姿態，但資料結構沒有姿態

**原句：**

> 我們知道每一幀中每條魚的精確位置、姿態、深度及 ID。

但 `Fish` 只有：

```python
self.pos = pos
self.vel = vel
```

**問題：**

速度不等於完整姿態；速度為零時甚至不能決定朝向，也沒有 roll 或骨架姿勢。manifest 也只輸出位置與速度。

**修法：**

改成：

> 本簡化模型提供位置、速度、近似深度及 ID，不提供完整魚體姿態。

若要輸出朝向，至少需定義局部前向軸，從非零速度建立旋轉，並處理零速度與 up 平行等退化情況。

---

### 3. 深度與 ID 的遮擋核心缺少確定性測試

**目前測試：**

> `id_map` 中非零值應在 $[1,5]$ 之間。

**問題：**

這只能檢查 ID 值域，不能驗證 z-buffer 是否保留最近物體。章目核心包含深度／ID 標註及遮擋，應有可手算測試。

**建議測例：**

設定兩條魚投影中心相同：

- 魚 A：相機座標 $(0,0,-2)$，map ID 為 1；
- 魚 B：相機座標 $(0,0,-4)$，map ID 為 2。

中心重疊像素應滿足：

$$
\text{depth\_map}=2,\qquad \text{id\_map}=1.
$$

交換魚列表順序後結果仍應相同。另應測試 near 外、far 外及完全位於影像外的魚不產生像素。

---

### 4. 單魚測試的「中心像素」說法不夠精確

**原句：**

> 中心像素 $(399,299)$ 或 $(400,300)$ 附近應被標記。

**問題：**

投影中心為 $(400,300)$，依全書像素中心規則，附近四個像素中心為：

$$
(399.5,299.5),\ (400.5,299.5),\
(399.5,300.5),\ (400.5,300.5).
$$

不存在中心恰為 $(400,300)$ 的單一像素。因半徑為 20，這四個像素都應被覆蓋。

**修法：**

明確驗證例如：

```python
assert id_map[299, 399] == 1
assert depth_map[299, 399] == 2.0
```

並說明陣列索引 `[299,399]` 的像素中心是 $(399.5,299.5)$。

### 5. 習題 2解答仍不是有效程式或完整演算法

**原句：**

```python
acc_chase = k_chase * (p_j* - p_0)
```

**問題：**

`p_j*` 不是合法 Python 識別字；`k_chase` 未定義，也沒有說明追擊力應在速度限制前加入哪個位置。驗收條件也可能受最近獵物切換影響。

**修法：**

至少提供可定位的完整片段：

```python
if i == 0 and n > 1:
    prey_indices = range(1, n)
    target_j = min(
        prey_indices,
        key=lambda j: np.linalg.norm(old_pos[j] - p_i)
    )
    acc_chase = k_chase * (old_pos[target_j] - p_i)
    total_acc += acc_chase
```

並給出 `k_chase`、固定初始狀態及「預期」驗收結果。若獵物會切換，應記錄對當前最近獵物的距離，不能把它誤當成固定追蹤對象的距離。

### 6. 習題 4解答仍未完成輸出流程

**原句：**

> 將結果存入列表並回傳，或在 `run_simulation` 中計算並附加至 manifest。

**問題：**

「或」留下兩種未完成方案，沒有提供要求格式的實際答案。也未處理 near/far 外的魚。

**修法：**

提供完整函式或至少完整迴圈，明確規定：

- 只輸出 $z_{near}\le z\le z_{far}$ 的中心；
- `id` 是內部 0-based ID，與 ID map 的 1-based 值不同；
- 欄位包含 `u`、`v`、`depth_buffer`；
- 畫面外但通過深度裁切的中心是否保留。

### 7. JSON 與 `.npy` 的檔案語義仍需更完整

**原句：**

```json
"depth_encoding": "camera_forward_distance_m",
"background_depth": "infinity"
```

**問題：**

這基本合理，但資料清單尚未記錄：

- ID map 背景值 0；
- ID map 是 `fish.id + 1`；
- `.npy` dtype；
- 相機固定與世界軸對齊；
- `focal_length` 同時代表 $f_x=f_y$；
- 每幀是更新前還是更新後狀態。

這些資訊會影響下游正確解讀。

**修法：**

manifest 增加 `id_encoding`、`camera_convention`、`frame_state` 等欄位。這不是要求建立複雜規格，而是讓資料可稽核。

---

### 8. 「避免顯式迴圈」與實作內容矛盾

**原句：**

> 能使用 NumPy 進行向量化的矩陣乘法與陣列操作。

程式對魚對與每個圓盤像素都使用 Python 迴圈。小型教學程式可以如此，但不應讓讀者以為已向量化或適合大量資料。

**修法：**

將先備敘述改成「能使用 NumPy 陣列與基本線性代數」；並明示本例為可讀性採 $O(N^2)$ 鄰居搜尋與逐像素圓盤填色，不宣稱效能。

以下內容正確：

### 法線、色彩與索引界線

本章使用圓盤代理，沒有表面法線或材質色彩，不需加入法線推導。ID 與 depth 是資料陣列，不應做 sRGB 轉換。ID map 的 1-based 像素值與 `Fish.id` 的 0-based 狀態值必須持續明確區分。
