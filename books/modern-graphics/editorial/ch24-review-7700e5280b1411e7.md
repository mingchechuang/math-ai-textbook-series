# 審稿結果

## 一、必須修正的實質錯誤

### 1. 模擬時間公式與預期趨勢完全相反

**原程式：**

```python
simulated_time = 0.01 * (100 / spp)
```

**原預期：**

> 時間隨 spp 增加而增加：線性關係。  
> spp/s 速率穩定。

程式中的時間與 `spp` 成反比。`spp` 越大，回傳時間反而越短：

- `spp=1`：1 秒
- `spp=100`：0.01 秒

這與文字宣稱的線性增加相反，也會使計算出的速率約隨 $\mathrm{spp}^2$ 增加。

**修法：**

若只是合成成本模型，應至少寫成

```python
simulated_time = 0.01 * spp
```

但本章實驗核心包含「時間記錄」，較好的做法是分離兩件事：

1. 噪聲模擬只負責產生影像；
2. 用 `time.perf_counter()` 計量實際程式區塊。

例如：

```python
start = time.perf_counter()
test_img = render_simulated(scene_id=1, spp=spp, seed=seed)
elapsed = time.perf_counter() - start
```

由於這只是 NumPy 噪聲模擬，其時間不代表路徑追蹤效能，正文必須明說。不得把虛構時間列為實測效能。

---

### 2. `samples/sec` 錯把 RGB 通道數算成樣本數

**原程式：**

```python
samples_per_sec = (16 * 16 * 3 * spp) / avg_time
```

一般渲染中的 `spp` 是每個像素的相機／路徑樣本數，不是每通道樣本數。因此總樣本數通常是

$$
W H\,spp,
$$

不是

$$
W H C\,spp.
$$

**修法：**

```python
samples_per_sec = (16 * 16 * spp) / avg_time
```

若要計算每秒處理的純量通道值，必須另取名稱，例如 `channel_values_per_sec`，不能標成 `samples/sec`。

輸出標籤也應由 `"spp/s"` 改成 `"samples/s"`；`spp/s` 容易被理解為每秒增加的每像素樣本數。

---

### 3. 使用帶噪參考圖，使預期 MSE 不會純粹按 $1/spp$ 收斂

**原程式：**

```python
ref_img, _ = render_simulated(scene_id=1, spp=1024, seed=42)
```

此參考圖仍含方差 $1/1024$ 的噪聲。測試圖與參考圖獨立時，差值的期望平方誤差約為

$$
\mathbb E[(T-R_{\mathrm{ref}})^2]
=
\frac1{spp}+\frac1{1024},
$$

而不是單純的 $1/spp$。因此原文：

> MSE 應大致按 $1/spp$ 比例下降

在高 spp 時會受到參考圖噪聲底限影響。

**修法：**

這個模擬本來就知道解析真值 $0.5$，應直接使用：

```python
ref_img = np.full((16, 16, 3), 0.5, dtype=np.float64)
```

若要教導有限樣本參考圖，則須推導並說明上述誤差底限，最好把兩種實驗分開。

---

### 4. MSE 的維度定義與程式不一致

**原文：**

> 設像素數量為 $N$。  
> $MSE=\frac1N\sum_{i=1}^N(T_i-R_i)^2$

但 $T_i,R_i$ 若是 RGB 像素，平方結果是三維向量；程式 `np.mean` 則對 $HWC$ 所有純量一起平均。

**修法：**

明確定義 $N=HWC$ 為純量通道值總數：

$$
\operatorname{MSE}
=
\frac1{HWC}
\sum_{y=0}^{H-1}
\sum_{x=0}^{W-1}
\sum_{c=0}^{C-1}
(T_{yxc}-R_{yxc})^2.
$$

或者定義每像素 RGB 平方範數並除以三；兩者可等價，但不能把 RGB 像素直接當純量。

---

### 5. 偏誤—變異數分解缺少期望與估計器定義

**原句：**

> 若 $R$ 為真值，$MSE=\text{Bias}^2+\text{Variance}$。

這個等式是對隨機估計器重複實驗取期望後成立：

$$
\mathbb E[(\hat I-I)^2]
=
(\mathbb E[\hat I]-I)^2+\operatorname{Var}(\hat I).
$$

單張影像相對參考圖的經驗 MSE 不能直接唯一分解為偏誤與變異數。偏誤估計至少需要多個獨立 seed：

$$
\bar I=\frac1K\sum_{k=1}^K\hat I_k,
$$

$$
\widehat{\operatorname{Bias}}=\bar I-R,
$$

再從跨 seed 波動估計變異數。

應補充影像各通道平均版本，並說明有限 $K$ 仍有估計誤差。

---

### 6. 手算案例 1 混淆「個別樣本」與「估計器輸出」

**原文：**

> 實驗 B：100 次取樣，結果在 $0.5$ 到 $1.5$ 均勻分佈，平均為 $1.0$。  
> $MSE\approx0.0833$。

如果這 100 個值是組成一次蒙特卡洛估計的樣本，而且其平均恰為 $1.0$，則平均估計器的輸出是 $1.0$，該次估計對真值的平方誤差為零。$1/12$ 是**單一均勻隨機變數**的方差，不是 100 樣本平均的方差。

若每次估計由 100 個獨立樣本平均，則

$$
\operatorname{Var}(\bar X)
=
\frac{1/12}{100}
=
\frac1{1200}
\approx0.000833.
$$

若原意是「100 次獨立渲染，每次只產生一個值」，則必須明寫為 100 個獨立估計器輸出。

此外：

> 實驗 B 更接近無偏估計

無偏不代表平方風險必然更小。依稿中數字，A 的 MSE 為 $0.01$，B 的單次輸出 MSE 為約 $0.0833$，A 反而有較低平方風險。應改為「B 無偏但方差較高；A 有偏但方差為零」，避免把無偏性等同於整體品質較佳。降噪器通常正是以引入偏誤換取方差降低。

---

### 7. 案例 2 對實測偏離的推論不成立

**原句：**

> 若實測 $MSE_{64}=0.005$，表示有系統性錯誤（偏誤）隨樣本數減少，或算法存在其他收斂機制。

由單一觀測值低於 $0.01$，不能推論存在系統性錯誤。可能原因包括：

- 有限 seed 的隨機波動；
- 16 spp 的 $0.04$ 本身只是帶噪估計；
- 兩組使用不同隨機數；
- 參考圖含噪；
- 方差常數並非固定；
- 使用分層或低差異取樣；
- 裁切、降噪等操作改變誤差模型。

應以多個獨立 seed 報告平均值、標準差或信賴區間，再判斷收斂率。單點結果不能「證明噪聲主導」或「證明系統性錯誤」。

---

### 8. Box 模糊不一定增加 MSE

**原句：**

> 簡單的 Box 模糊降噪會增加 MSE（因為引入偏誤）

模糊確實可能引入偏誤及破壞邊緣，但它也可能大幅降低噪聲方差，因而使總 MSE 降低。正確說法應為：

> Box 模糊通常引入空間偏誤並損失高頻細節，但是否提高 MSE 取決於偏誤增加量與方差降低量；不能只由「有偏」推斷 MSE 必然增加。

這也正是本章應討論「降噪假細節／過度平滑」的核心。

---

### 9. Beer–Lambert 案例把吸收解析解擴張成完整散射驗證

**原文：**

> 驗證水體散射模型……深度 $d$ 處的衰減應符合 Beer-Lambert 定律  
> 若 MSE……可能暗示散射係數 $\sigma$ 或折射率 $n$ 錯誤。

單純的

$$
I=I_0e^{-\sigma d}
$$

適合驗證均勻介質中沿固定路徑的消光／吸收測試。若場景包含多重散射、介面折射、入射角、背景光或水面反射，像素值一般不等於此一簡式。折射率也不直接出現在該公式中。

**修法：**

將測試限制為：

- 無散射或明確只測透射；
- 均勻消光係數；
- 已知直線路徑長度；
- 無水面介面或預先排除 Fresnel 因子；
- 固定入射輻射。

若要驗證散射，需另設可比較的解析案例或高樣本參考，不可直接由 Beer–Lambert 誤差判定折射率錯誤。

---

### 10. 「理想漫反射金屬球（Lambertian）」材質概念矛盾

**原習題解答：**

> 渲染一個理想漫反射金屬球（Lambertian）

Lambertian 是理想漫反射模型；理想金屬主要是導體反射，不能同時稱為理想 Lambertian 金屬。

**修法：**

依測試目的選一種：

- 「理想 Lambertian 漫反射球」；或
- 「具有已知導體 Fresnel 參數的金屬球」。

若錯誤只出現在金屬 BRDF，應使用簡化金屬測試場景，而不是 Lambertian 球。

## 二、程式與實驗設計問題

### 1. 隨機數應避免修改全域狀態

**原程式：**

```python
np.random.seed(seed)
noise = np.random.normal(...)
```

建議改為：

```python
rng = np.random.default_rng(seed)
noise = rng.normal(0.0, sigma, size=(H, W, 3))
```

這樣不同實驗不會互相污染全域亂數狀態。

### 2. `scene_id` 未使用

`render_simulated(scene_id, spp, seed)` 接受 `scene_id` 卻完全不使用。應刪除參數，或讓它確實決定真值場景；否則不利於可稽核性。

### 3. 缺少參數與影像邊界檢查

至少應檢查：

- `spp` 是正整數；
- `seed` 的接受型別；
- 兩影像 shape 相同；
- 影像值皆有限；
- 渲染時間為有限正數；
- `H,W,C` 應由影像 shape 取得，不應另由呼叫者傳入。

### 4. 習題 4 的函式不能獨立執行

**原碼：**

```python
mse1, mae1 = calculate_metrics(img1, ref)
```

`ref` 沒有作為參數，也沒有在函式內定義，違反「完整定義、不能引用尚未存在模組／變數」的要求。

應改成：

```python
def compare_renders(ref, img1, time1, spp1, img2, time2, spp2):
    ...
```

而且品質比較與效能比較須分開解讀：BVH 與暴力求交若演算法等價、使用相同射線，影像理應在數值容差內一致；若 seed 不同，影像差異不能直接歸因於 BVH。

### 5. 缺少真正的降噪實作與假細節測試

章名與核心包含「降噪」及「降噪假細節」，但正文沒有任何降噪程式。至少應提供一個可獨立閱讀的簡單濾波器，並使用以下合成圖測試：

- 常數區域：量測方差是否降低；
- 黑白階梯邊緣：量測邊緣是否變寬；
- 單像素亮點：檢查是否被消除或擴散；
- 無訊號純噪聲：檢查是否生成不存在的結構。

須明確說明簡單濾波只作教學，不代表現代路徑追蹤降噪器。

## 三、色彩與統計敘述

### 1. sRGB 敘述過度絕對

**原句：**

> 最終輸出前的 sRGB 轉換不影響線性誤差的相對比較

非線性轉換可能改變兩方法的 MSE 排序，因此不能說不影響「相對比較」。應改為：

> 物理數值誤差應在線性 RGB 計算；顯示時再做曝光、色調映射與 sRGB 編碼。顯示域指標屬於另一種評估，可能得到不同排序。

### 2. MAE 並非特別適合「檢測局部錯誤」

全域平均 MAE 仍可能把小面積嚴重錯誤稀釋。若要檢測黑斑、漏光等局部問題，應搭配：

- 最大絕對誤差；
- 分位數；
- 誤差圖；
- 區域遮罩 MSE／MAE；
- 固定像素跨 seed 統計。
