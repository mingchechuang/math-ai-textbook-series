### 1. 程式宣稱完成光柵化與 PPM，實際上沒有實作

**原句：**

> 對魚體三角形進行光柵化，比較透視插值與線性插值的差異。  
> 輸出 PPM 影像……

**原程式：**

```python
def rasterize_triangle(...):
    ...
    pass
```

以及：

```python
# 檢查是否在三角形內
# ...
# 實際應實現 Edge Function
```

程式沒有：

- 邊函數；
- 三角形內外判定；
- 重心座標；
- 呼叫 `perspective_uv`；
- 呼叫 `sample_bilinear` 填入 `img`；
- PPM 寫檔；
- 實際呼叫 `rasterize_triangle`。

`img` 始終是全黑陣列，而且連全黑影像也沒有輸出。這違反「完整可獨立閱讀的小程式」及指定實驗要求。

**修法：**

必須完整實作光柵化並輸出，例如：

```python
def edge(a, b, p):
    return (
        (b[0] - a[0]) * (p[1] - a[1])
        - (b[1] - a[1]) * (p[0] - a[0])
    )
```

再由有向面積計算重心座標，逐像素插值 UV、取樣貼圖並寫入影像。最後提供完整的 PPM writer，例如：

```python
def write_ppm(path, image):
    h, w, channels = image.shape
    if channels != 3:
        raise ValueError("預期 RGB 影像")
    with open(path, "wb") as f:
        f.write(f"P6\n{w} {h}\n255\n".encode("ascii"))
        f.write(image.astype(np.uint8).tobytes())
```

不能保留 `pass` 或要求讀者自行整合後仍稱為完整實驗。

### 2. 所謂「兩個三角形組成魚體」其實未形成連續魚形網格

**原資料：**

```python
ndc_L = [
    [-1.0, -1.0],
    [ 0.0,  1.0],
    [-1.0,  1.0]
]

ndc_R = [
    [0.0,  1.0],
    [1.0, -1.0],
    [0.0, -1.0]
]
```

兩三角形只共享 \((0,1)\) 一個點，沒有共享邊，因此不是由兩三角形組成的連續魚體。其形狀也只是兩個分離的半區域，不能合理稱為「左鰭」與「右身」。

**修法：**

若用兩三角形組成簡化魚身，應共享一條邊，例如：

\[
A=(-0.8,0),\quad B=(0,0.6),\quad
C=(0.8,0),\quad D=(0,-0.6),
\]

使用：

\[
(A,B,D),\qquad (B,C,D).
\]

若要尾鰭，再增加尾部三角形。若要示範 UV 接縫，接縫兩側可具有相同位置但不同的渲染頂點記錄。

### 3. 魚體三角形內的 \(w\) 都相同，無法展示透視與線性插值差異

**原程式：**

```python
w_L = np.array([1.0, 1.0, 1.0])
w_R = np.array([2.0, 2.0, 2.0])
```

每個三角形內部的三個 \(w_i\) 完全相同，因此：

\[
\frac{\sum_i\lambda_i A_i/w}
{\sum_i\lambda_i/w}
=\sum_i\lambda_i A_i.
\]

也就是每個三角形內，透視正確插值恰好退化為一般線性插值。兩個三角形使用不同常數 \(w\) 也不能產生三角形內的透視扭曲。

**修法：**

至少讓同一三角形內的 \(w\) 不同，例如：

```python
w_body = np.array([1.0, 2.0, 3.0])
```

並分別輸出：

- `fish_pc.ppm`：透視正確；
- `fish_affine.ppm`：直接線性；

才能視覺比較。

### 4. 接縫測試的「顏色應不同」在目前 checker 上是錯的

**原句：**

> `Seam Correct (u=1.0)` 與 `Seam Wrong (u=0.5)`……兩者取樣位置不同，顏色應不同。

對 \(8\times8\) checker、\(v=0.5\)：

#### \(u=1.0\)

\[
x=7.5,\qquad y=3.5.
\]

Repeat 的四個 tap 是：

\[
(7,3),(0,3),(7,4),(0,4),
\]

其中兩白、兩黑，權重皆 \(1/4\)，結果是：

\[
(0.5,0.5,0.5).
\]

#### \(u=0.5\)

\[
x=3.5,\qquad y=3.5.
\]

四個 tap 是：

\[
(3,3),(4,3),(3,4),(4,4),
\]

同樣兩白、兩黑，結果也是：

\[
(0.5,0.5,0.5).
\]

因此目前程式的預期結果應是兩者相同，不能藉此檢出錯誤接縫。

**修法：**

使用非對稱貼圖，例如每一 column 使用不同顏色或灰階：

\[
c(x)=\frac{x}{W-1},
\]

或使用「方向色帶加 checker」的貼圖。如此 \(u=0\) 與 \(u=0.5\) 才容易區分。

### 5. 應列出目前透視與線性取樣的具體預期值

**原句：**

> `Color PC` 與 `Color Lin` 在 Checkerboard 中可能相同或不同，取決於具體紋素位置。

貼圖、UV 與取樣規則均已固定，不是「可能」，可以手算。

#### 透視結果

\[
u=\frac9{43},\qquad v=\frac4{43}.
\]

紋素座標：

\[
x=8\frac9{43}-\frac12=\frac{101}{86},
\]

\[
y=8\left(1-\frac4{43}\right)-\frac12
=\frac{581}{86}.
\]

因此：

\[
x_0=1,\quad y_0=6,\quad
f_x=\frac{15}{86},\quad f_y=\frac{65}{86}.
\]

白色 tap 為 \((2,6)\) 與 \((1,7)\)，故灰階值：

\[
f_x(1-f_y)+(1-f_x)f_y
=
\frac{15\cdot21+71\cdot65}{86^2}
=
\frac{4930}{7396}
\approx0.66658.
\]

預期：

```text
Color PC: [0.66658 0.66658 0.66658]
```

#### 線性結果

\[
(u,v)=(0.3,0.2),
\]

\[
x=1.9,\qquad y=5.9,\qquad f_x=f_y=0.9.
\]

白色 tap 為 \((1,5)\) 與 \((2,6)\)，所以：

\[
(1-0.9)^2+0.9^2=0.82.
\]

預期：

```text
Color Lin: [0.82 0.82 0.82]
```

如此才能確認透視與線性取樣確實不同。

### 6. 習題 2 的題目與答案不一致，答案保留作者自我修正文字

**原題：**

> 測試 \(u=0.9,v=0.5\) 與 \(u=1.1,v=0.5\)……比較兩者是否一致？

**原解答：**

> \(u=0.9\) 與 \(u=1.1\) 在 Repeat 模式下取樣相同……不，……等等……

這段包含互相矛盾的敘述及編修過程，不可作為正式解答。實際上：

\[
0.9\bmod1=0.9,\qquad1.1\bmod1=0.1,
\]

兩個座標一般不相同。對某些對稱 checker 可能偶然產生相同顏色，但不代表座標相等。

**修法二選一：**

1. 題目改成比較 \(u=0\) 與 \(u=1\)，驗證週期等價；或
2. 保留 \(0.9\) 與 \(1.1\)，要求說明它們位於接縫兩側、通常不會取到相同值，而中點 \(1.0\equiv0.0\)。

解答必須直接給出唯一結論，刪除「不、等等、修正」等編修痕跡。

### 7. `perspective_uv` 的有限值檢查仍不完整

**原程式：**

```python
if not np.all(np.isfinite(ws)) or np.any(np.abs(ws) < 1e-12):
    raise ValueError(...)
denom = np.sum(lams / ws)
if abs(denom) < 1e-12:
    raise ValueError(...)
```

尚未檢查：

- `lams` 是否有限；
- `denom` 是否為 `nan` 或 `inf`；
- 重心座標總和是否近似 1。

建議補為：

```python
if not np.all(np.isfinite(lams)):
    raise ValueError("barycentric coordinates must be finite")
if not np.isclose(np.sum(lams), 1.0, atol=1e-8):
    raise ValueError("barycentric coordinates must sum to one")

denom = np.sum(lams / ws)
if not np.isfinite(denom) or abs(denom) < 1e-12:
    raise ValueError("invalid perspective denominator")
```

epsilon 是數值容差，不應被描述為物理閾值。

### 8. 透視推導中的「世界空間重心座標」用語不夠準確

**原句：**

> 設原三角形（世界空間）中像素 P 的重心座標為 \(\beta_i\)。

螢幕像素不一定直接對應「世界空間中的像素」。更準確的說法是：由視線與三角形平面相交得到表面點 \(P\)，\(\beta_i\) 是該表面點相對於投影前三角形的仿射重心座標。

此外：

> 透視投影保持了直線映射

透視投影保持直線為直線，但不保持沿線的仿射比例。這正是需要透視修正的原因。建議改成：

> 透視投影保持共線性，但一般不保持仿射比例；因此投影前後的重心權重需用 \(1/w_i\) 修正。

公式本身正確。

## 二、邊界、索引、法線與色彩核對

### 邊界

`sample_bilinear` 的 Repeat tap 逐一取模，方向正確。Clamp 分支將座標夾到 \([-0.5,W-0.5]\) 並重複邊緣 tap，也能實現 edge clamp。建議補測：

- \(u=0\)、\(u=1\)；
- \(u<0\)、\(u>1\)；
- \(W=1\)、\(H=1\)。

### 索引

接縫處複製完整渲染頂點的說法正確。不過目前程式沒有 index buffer，亦沒有實際展示共享幾何位置與不同 UV 的兩份渲染頂點；應在魚體資料中落實。

### 法線與繞序

本章沒有法線運算，但若程式採用有向邊函數，必須說明三角形在 NDC 的繞序。現在兩組三角形的順逆時針未被檢查，未來加入背面剔除時可能出錯。應統一為從外向法線看逆時針，或在計算有向面積後依符號一致處理。

### 色彩

`generate_checker_texture` 明確標示為線性 RGB，符合全書約定。輸出 PPM 時若直接把線性值乘 255，檔案數值仍是線性編碼；若要作一般顯示影像，應先做線性 RGB 到 sRGB 的分段轉換。兩種做法皆可，但必須標明輸出編碼。
