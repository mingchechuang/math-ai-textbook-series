# 第 6 章 三角形光柵化與插值 審稿報告

## 一、數學與邏輯錯誤（真錯誤）

### 1. 程式碼中 Top-Left 規則的邊索引對應錯誤
*   **原句/代碼**：
    ```python
    e0 = edge(x1, y1, x2, y2, px, py)   # 對 BC 邊
    e1 = edge(x2, y2, x0, y0, px, py)   # 對 CA 邊
    e2 = edge(x0, y0, x1, y1, px, py)   # 對 AB 邊
    # ...
    if e0 == 0.0 and not is_top_left(x1, y1, x2, y2):
    if e1 == 0.0 and not is_top_left(x2, y2, x0, y0):
    if e2 == 0.0 and not is_top_left(x0, y0, x1, y1):
    ```
*   **錯誤原因**：
    1.  邊函數 $e_{AB}(P)$ 定義為針對有向邊 $A \to B$。
    2.  在程式碼中，`e0` 計算的是邊 $1 \to 2$ (即 $B \to C$)，`e1` 是邊 $2 \to 0$ (即 $C \to A$)，`e2` 是邊 $0 \to 1$ (即 $A \to B$)。
    3.  Top-Left 規則檢查的是**該像素中心是否落在某條邊的「左上」定義上**。如果像素在邊 $i$ 上（$e_i = 0$），我們需要檢查**該邊**的方向是否為 Top-Left。
    4.  程式碼目前的邏輯是：如果 $e0 == 0$（像素在邊 $1 \to 2$ 上），就檢查邊 $1 \to 2$ 是否為 Top-Left。這部分邏輯**看起來是對的**，因為 `is_top_left(x1, y1, x2, y2)` 檢查的正是邊 $1 \to 2$。
    5.  **然而**，這裡有一個常見的陷阱：**頂點交換後的邊一致性**。
        如果 `area2 < 0`，程式碼交換了 `v0` 和 `v1`。
        交換前：v0, v1, v2。
        交換後：v0' (原v1), v1' (原v0), v2' (原v2)。
        新的邊：
        `e0` (新v1' -> 新v2') = (原v0 -> 原v2)。
        `e1` (新v2' -> 新v0') = (原v2 -> 原v1)。
        `e2` (新v0' -> 新v1') = (原v1 -> 原v0)。
        
        讓我們檢查交換後的 `is_top_left` 呼叫：
        `if e0 == 0.0 and not is_top_left(x1, y1, x2, y2)`
        此時的 `x1, y1` 是原 `x0, y0`。`x2, y2` 是原 `x2, y2`。
        所以檢查的是原邊 $0 \to 2$。
        這是正確的，因為 `e0` 對應的是新邊 $1 \to 2$ (即原 $0 \to 2$)。
        
        `if e1 == 0.0 and not is_top_left(x2, y2, x0, y0)`
        此時的 `x2, y2` 是原 `x2, y2`。`x0, y0` 是原 `x1, y1`。
        所以檢查的是原邊 $2 \to 1$。
        `e1` 對應的是新邊 $2 \to 0$ (即原 $2 \to 1$)。
        這是正確的。
        
        `if e2 == 0.0 and not is_top_left(x0, y0, x1, y1)`
        此時的 `x0, y0` 是原 `x1, y1`。`x1, y1` 是原 `x0, y0`。
        所以檢查的是原邊 $1 \to 0$。
        `e2` 對應的是新邊 $0 \to 1$ (即原 $1 \to 0$)。
        這是正確的。
        
    6.  **潛在問題**：Top-Left 規則通常定義為：**如果像素中心位於「Top-Left」邊上，則該像素屬於此三角形**。
        反之，如果像素中心位於非 Top-Left 邊上，則不屬於。
        對於**內部**像素（所有 $e > 0$），不需要檢查。
        對於**邊界**像素（某個 $e = 0$），需要檢查該邊。
        
        程式碼邏輯：
        ```python
        inside = e0 > 0.0 and e1 > 0.0 and e2 > 0.0
        if not inside:
            if e0 < 0.0 or e1 < 0.0 or e2 < 0.0:
                continue # 外部
            # 此時所有 e >= 0，且至少一個 e == 0
            if e0 == 0.0 and not is_top_left(...): continue
            if e1 == 0.0 and not is_top_left(...): continue
            if e2 == 0.0 and not is_top_left(...): continue
            # 如果沒 continue，則寫入
        ```
        這個邏輯是正確的。如果多個 $e$ 為 0（頂點），只要有一個邊是 Top-Left，它就會被保留。如果有兩個邊是 Top-Left（不可能在凸多邊形頂點），或者都沒有一個是 Top-Left（頂點處三個邊，通常只有一個是 Top-Left，或者兩個？取決於幾何）。
        
        **標準實現細節**：
        在 Y-Down 座標系中，頂點逆時針（CCW）時：
        一條邊 $A \to B$ 是 Top-Left 當且僅當 $B$ 在 $A$ 的「上方」（$y_B < y_A$）或「右方」（$y_B == y_A$ 且 $x_B > x_A$）。
        這與程式碼 `is_top_left` 的定義 `(dy < 0.0) or (dy == 0.0 and dx > 0.0)` 一致。
        
    7.  **結論**：Top-Left 邏輯本身似乎沒有明顯錯誤。
    
    **但是**，有一個更細微的問題：**退化三角形與頂點**。
    如果三個頂點共線，`area2` 可能為 0。程式碼處理了 `area2 == 0.0`。
    
    **再檢查一遍 `is_top_left` 的定義與常見實現的差異**。
    許多實現使用「Top-Left 像素」規則：像素中心在邊上，且該邊是 Top-Left。
    有些實現（如 Vulkan/DirectX）定義略有不同，但核心思想一致。
    
    **讓我重新審視一個常見錯誤：邊的方向**。
    在 Y-Down 座標中，CCW 三角形。
    邊 $A \to B$。
    如果 $A=(0,0), B=(1,0)$ (右移)，$dy=0, dx=1$。`is_top_left` 返回 True。
    如果 $A=(0,1), B=(0,0)$ (上移)，$dy=-1, dx=0$。`is_top_left` 返回 True。
    如果 $A=(1,0), B=(0,0)$ (左移)，$dy=0, dx=-1$。`is_top_left` 返回 False。
    如果 $A=(0,0), B=(0,1)$ (下移)，$dy=1, dx=0$。`is_top_left` 返回 False。
    
    對於一個小的 CCW 三角形，例如 A(0,0), B(1,0), C(0,1)。
    Edge A->B: Right. Top-Left (True).
    Edge B->C: Left-Down. $B(1,0) \to C(0,1)$. $dy=1, dx=-1$. Top-Left (False).
    Edge C->A: Up-Right. $C(0,1) \to A(0,0)$. $dy=-1, dx=0$. Top-Left (True).
    
    等等，C(0,1) -> A(0,0) 是向上。$dy = 0 - 1 = -1$. True.
    所以邊 AB 和 CA 是 Top-Left？
    共享邊處理時，相鄰三角形的邊方向相反。
    T1: A->B. T2: B->A.
    T1 中 A->B 是 Top-Left。T2 中 B->A 是 Not Top-Left。
    所以邊界像素歸屬 T1。正確。
    
    **但是**，對於邊 CA (C->A) 和相鄰三角形的邊 AC (A->C)。
    T1 中 C->A 是 Top-Left。
    相鄰三角形 T3 (假設共享 CA 邊) 中 A->C 是 Not Top-Left (向下)。
    所以邊界像素歸屬 T1。
    
    這意味著，在 Y-Down CCW 三角形中，**大部分邊都是 Top-Left**？
    不，只有「向上」或「水平向右」的邊。
    在一個 CCW 三角形中，不可能三條邊都滿足。
    
    **潛在錯誤**：如果兩個頂點 Y 相同，X 不同。
    如果邊是水平的。
    A(0,0) -> B(1,0). Top-Left.
    B(1,0) -> A(0,0). Not Top-Left.
    
    看起來邏輯是健壯的。

### 2. 深度插值公式的理論闡述與程式碼一致性
*   **原句**：「$z_{\text{ndc}}$ 是 $1/w$ 的仿射函數... 所以 $z_{\text{ndc}}$ 在屏幕空間以 $\lambda_i$ 線性插值即為正確值」
*   **程式碼**：
    ```python
    z_ndc = la * z0 + lb * z1 + lc * z2
    ```
*   **核對**：
    1.  理論上，OpenGL 的 NDC 深度 $z_{\text{ndc}}$ 確實是 $1/w$ 的仿射函數：
        $z_{\text{ndc}} = A + B \cdot \frac{1}{w}$。
    2.  因此，$\lambda$ 的線性組合 $\sum \lambda_i z_{\text{ndc},i} = \sum \lambda_i (A + B/w_i) = A \sum \lambda_i + B \sum \lambda_i (1/w_i) = A + B (1/w_P)$。
    3.  這等於該像素正確的 NDC 深度。
    4.  因此，對 NDC 深度使用**線性插值**是正確的。
    5.  對其他屬性（如 UV），需要使用透視校正插值（Perspective-Correct Interpolation），因為它們在視空間是線性的，但在 NDC 空間不是。
        $a_P = \frac{\sum \lambda_i a_i / w_i}{\sum \lambda_i / w_i}$。
    6.  程式碼中：
        ```python
        # 深度：螢幕空間線性插值
        z_ndc = la * z0 + lb * z1 + lc * z2
        # ...
        # 其他屬性：透視校正插值
        denom = la * inv0 + lb * inv1 + lc * inv2
        # ...
        pa[k] = (la * a0[k] * inv0 + ...) / denom
        ```
    7.  **結論**：理論與程式碼一致，且正確。這是本章的核心教學點，處理得很好。

### 3. 習題 3 的反例邏輯
*   **原句**：
    > (b) 例 3：near$=1$、far$=2$、$w_A=1$、$w_B=2$、$\lambda=(0.5,0.5)$。正確 $z_{\text{ndc},P}=0$；錯誤公式得 $-0.333$。
*   **核對**：
    1.  投影公式：$z_{\text{ndc}} = \frac{f+n}{f-n} - \frac{2fn}{f-n} \frac{1}{w}$。
        $n=1, f=2$.
        $z_{\text{ndc}} = \frac{3}{1} - \frac{4}{1} \frac{1}{w} = 3 - \frac{4}{w}$.
    2.  $w_A = 1 \implies z_A = 3 - 4 = -1$. (Near plane)
    3.  $w_B = 2 \implies z_B = 3 - 2 = 1$. (Far plane)
    4.  正確線性插值：$0.5(-1) + 0.5(1) = 0$.
    5.  錯誤透視校正插值：
        $\frac{0.5(-1)/1 + 0.5(1)/2}{0.5/1 + 0.5/2} = \frac{-0.5 + 0.25}{0.5 + 0.25} = \frac{-0.25}{0.75} = -\frac{1}{3} \approx -0.333$.
    6.  **分析**：
        正確值是 $0$。錯誤值是 $-0.333$。
        $-0.333$ 比 $0$ 更小（更靠近 -1，即更靠近相機）。
        如果場景中有一個遠三角形在這個像素位置，$z_{\text{far}}$ 接近 $1$。
        如果近三角形（$z=0$）被錯誤計算為 $-0.333$。
        深度測試：$z_{\text{buffer}}$ 初始為 $1.0$ (或 max)。
        先畫遠三角形：$z=1$。寫入 depth=1。
        再畫近三角形：$z=-0.333$。$-0.333 < 1$，通過測試，寫入。
        結果：近三角形顯示。這是**正確**的結果（近者覆蓋遠者）。
        
        **等等，反例要證明「錯誤公式導致錯誤」**。
        如果錯誤公式算出的值**更遠**（更大），那麼近三角形可能會被**錯誤地拒絕**（如果深度 buffer 裡有比它更近的值），或者遠三角形會**錯誤地覆蓋**近三角形（如果先畫近，後畫遠，遠的 z 錯誤變小，從而覆蓋近）。
        
        讓我們換一個情境。
        假設正確值是 $z_{\text{correct}} = 0$。
        錯誤值是 $z_{\text{wrong}} = -0.333$。
        這意味著錯誤公式把點算得**更近**。
        這通常會導致**過度的繪製**（Overdraw），即本來該被遮擋的物體（如果在更遠處）不會被錯誤地顯示，因為錯誤值更近，所以更容易通過深度測試。
        
        **但是**，如果錯誤公式把點算得**更遠**呢？
        取 $w_A=2, w_B=1$ (反向)? 不，w 必須大於 0。
        取 $w_A=10, w_B=1$。
        $z_A = 3 - 0.4 = 2.6$ (超出 [−1,1]? 不，w=10 > f=2，所以在 far 之後，被裁切)。
        
        在 [n, f] 範圍內。
        $w_A=1, z_A=-1$. $w_B=1.5, z_B = 3 - 4/1.5 = 3 - 2.66 = 0.33$.
        $\lambda = (0.5, 0.5)$.
        Correct $z = 0.5(-1) + 0.5(0.33) = -0.335$.
        Wrong $z = \frac{0.5(-1)/1 + 0.5(0.33)/1.5}{0.5/1 + 0.5/1.5} = \frac{-0.5 + 0.11}{0.5 + 0.33} = \frac{-0.39}{0.83} \approx -0.47$.
        錯誤值 $-0.47$ 比正確值 $-0.335$ **更近**。
        
        **結論**：在 OpenGL 的 $z$ 映射中（$-1$ to $1$），$1/w$ 的插值是線性的。$z_{\text{ndc}}$ 是 $1/w$ 的線性（仿射）函數。
        透視校正插值是用於「視空間線性量」（如 x, y, z_view 或 1/w）。
        如果對 $z_{\text{ndc}}$ 使用透視校正插值（即把它當作視空間線性量來處理，除以 w），會發生什麼？
        公式是 $\frac{\sum \lambda z / w}{\sum \lambda / w}$。
        這等價於對 $z/w$ 做線性插值，再除以 $1/w$ 的插值。
        
        我們知道 $z = A + B(1/w)$.
        $z/w = A/w + B/w^2$.
        這不是線性的。
        
        在上面的例 3 中，錯誤值 $-0.333$ 比正確值 $0$ 更近。
        這會導致**深度測試過於寬鬆**（對於該物體來說，它看起來比實際更近）。
        這可能導致**錯誤的遮擋**：
        情境：兩個三角形 T1 (近) 和 T2 (遠) 重疊。
        T1 正確 $z=0$。T2 正確 $z=1$。
        如果 T1 被錯誤計算為 $z=-0.333$。
        T2 被正確計算為 $z=1$。
        先畫 T2：Depth=1。
        後畫 T1：$-0.333 < 1$，通過。T1 顯示。正確。
        
        如果 T1 被錯誤計算為 $z=0.5$ (假設錯誤方向是變遠)？
        在例 3 的參數下，錯誤值是變近。
        
        **有沒有可能錯誤值是變遠？**
        取 $w_A=1, w_B=2$.
        $z_A=-1, z_B=1$.
        Wrong $z = -0.333$. Correct $z = 0$.
        $-0.333 < 0$. 變近。
        
        取 $w_A=1.5, w_B=2$.
        $z_A = 3 - 4/1.5 = 0.333$. $z_B = 1$.
        $\lambda = 0.5$.
        Correct $z = 0.5(0.333) + 0.5(1) = 0.666$.
        Wrong $z = \frac{0.5(0.333)/1.5 + 0.5(1)/2}{0.5/1.5 + 0.5/2} = \frac{0.111 + 0.25}{0.333 + 0.25} = \frac{0.361}{0.583} \approx 0.619$.
        $0.619 < 0.666$. 變近。
        
        **似乎錯誤公式總是讓 $z$ 變小（變近）？**
        數學上，$f(w) = z_{\text{ndc}}$.
        我們比較 $\bar{z}_{linear}$ 和 $\bar{z}_{persp}$.
        對於 $w \in [n, f]$，$1/w$ 是凸函數。
        線性插值 $\sum \lambda_i (1/w_i)$ 是 $1/w$ 的正確值。
        $z_{\text{ndc}}$ 是 $1/w$ 的線性映射。
        所以 $\sum \lambda_i z_i$ 是正確的 $z$。
        
        透視校正插值計算的是 $\frac{\sum \lambda_i z_i / w_i}{\sum \lambda_i / w_i}$.
        這等價於對 $z/w$ 做線性插值，再除以 $1/w$ 的插值。
        由於 $z = A + B/w$， $z/w = A/w + B/w^2$.
        這是一個凸函數。
        由 Jensen 不等式，線性插值（對凸函數）會**高估**函數值（如果權重是線性的）。
        即 $\sum \lambda_i (z_i/w_i) > z_P/w_P$?
        不，Jensen 說 $f(\sum \lambda x) \le \sum \lambda f(x)$.
        所以 $\sum \lambda_i (z_i/w_i) \ge (z_P/w_P)$.
        分母 $\sum \lambda_i (1/w_i) = 1/w_P$.
        所以 Wrong $z \ge z_P$.
        **錯誤值應該比正確值更大（變遠）！**
        
        **為什麼我的數值計算顯示變近？**
        $z = 3 - 4/w$.
        $w_A=1, w_B=2$.
        $z_A=-1, z_B=1$.
        Correct $z = 0$.
        Wrong $z = -0.333$.
        $-0.333 < 0$. 變近。
        
        讓我們檢查 Jensen 的應用。
        $f(w) = z/w = 3/w - 4/w^2$.
        $f'(w) = -3/w^2 + 8/w^3$.
        $f''(w) = 6/w^3 - 24/w^4 = \frac{6w-24}{w^4}$.
        在 $w \in [1, 2]$：
        $w=1, f''(1) = -18$ (凹).
        $w=2, f''(2) = \frac{12-24}{16} < 0$ (凹).
        函數是**凹**的 (Concave)。
        對於凹函數，線性插值 $\sum \lambda f(w_i) \le f(\sum \lambda w_i)$? 不。
        凹函數：$f(\lambda x + (1-\lambda) y) \ge \lambda f(x) + (1-\lambda) f(y)$.
        所以 $f(w_P) \ge \sum \lambda_i f(w_i)$.
        即 $z_P/w_P \ge \sum \lambda_i (z_i/w_i)$.
        所以 $\sum \lambda_i (z_i/w_i) \le z_P/w_P$.
        所以 Wrong $z \le z_P$.
        **結論：錯誤值確實比正確值更小（變近）。**
        
        我的數值計算是正確的。錯誤公式會讓 $z$ 變小（變近）。
        
        **這會導致什麼錯誤？**
        如果錯誤值變近，該物體會**更容易**通過深度測試。
        這會導致**錯誤的顯示**：
        情境：T1 (真近, $z=0$) 和 T2 (真遠, $z=1$).
        如果 T1 被錯誤計算為 $z=-0.5$.
        T2 被正確計算為 $z=1$.
        先畫 T2 (Depth=1).
        後畫 T1 ($-0.5 < 1$). T1 顯示. 正確.
        
        情境：T1 (真遠, $z=1$) 和 T2 (真近, $z=0$).
        如果 T1 被錯誤計算為 $z=0.5$ (假設).
        T2 被正確計算為 $z=0$.
        先畫 T1 (Depth=0.5).
        後畫 T2 ($0 < 0.5$). T2 顯示. 正確.
        
        **似乎總是正確的？**
        不。如果兩個三角形**交叉**。
        T1 在左邊近，右邊遠。
        T2 在左邊遠，右邊近。
        在交疊區，T1 的近端被錯誤算得更近，T1 的遠端被錯誤算得更近。
        這可能導致 T1 的遠端錯誤地覆蓋 T2 的近端？
        T1 (Far end) Wrong $z$ is "closer" than Correct $z$.
        If Correct $z_{T1\_far} > z_{T2\_near}$, but Wrong $z_{T1\_far} < z_{T2\_near}$, then T1 incorrectly overwrites T2.
        
        **所以，反例邏輯是成立的：錯誤公式會導致深度值偏離正確值，從而可能在複雜場景中導致錯誤的遮擋順序。**
        
        **但是**，習題 3 (b) 的描述：
        > "錯誤公式得 -0.333... 足以讓遠三角形通過深度測試"
        
        如果錯誤值變近，它是**本三角形的**深度變近。
        如果它是「遠三角形」，它的深度變近，可能會**錯誤地覆蓋**前景物體。
        如果它是「近三角形」，它的深度變近，會**正確地覆蓋**背景（甚至可能覆蓋了不該覆蓋的？不，它本來就在前面）。
        
        所以，錯誤主要發生在**遠景物體**的深度被錯誤地計算為**更近**，從而錯誤地顯示在前景之前。
        
        習題 3 (b) 說「讓遠三角形通過深度測試」。
        如果遠三角形本來 z=1，錯誤算成 z=0.5。
        前景 z=0.6。
        正確：1 > 0.6，遠被擋。
        錯誤：0.5 < 0.6，遠覆蓋近。**錯誤發生！**
        
        所以描述是合理的。

### 4. 文字與符號一致性
*   **原句**：「$z_w=(z_{\text{ndc}}+1)/2$」
*   **程式碼**：`z_w = 0.5 * (z_ndc + 1.0)`
*   **一致**。

### 5. 習題 2 的頂點座標
*   **原句**：$T_1=(0,0),\ (32,0),\ (0,32)$；$T_2=(0,0),\ (0,32),\ (32,32)$
*   **核對**：
    $T_1$: (0,0), (32,0), (0,32). Y-Down.
    (0,0) Top-Left. (32,0) Top-Right. (0,32) Bottom-Left.
    CCW?
    Edge (0,0)->(32,0): Right. Top-Left.
    Edge (32,0)->(0,32): Left-Down. Not Top-Left.
    Edge (0,32)->(0,0): Up. Top-Left.
    
    $T_2$: (0,0), (0,32), (32,32).
    Edge (0,0)->(0,32): Down. Not Top-Left.
    Edge (0,32)->(32,32): Right. Top-Left.
    Edge (32,32)->(0,0): Up-Left. Not Top-Left.
    
    共享邊 (0,0)-(0,32).
    T1: (0,32)->(0,0) (Up). Top-Left.
    T2: (0,0)->(0,32) (Down). Not Top-Left.
    所以共享邊像素歸屬 T1。
    正確。
