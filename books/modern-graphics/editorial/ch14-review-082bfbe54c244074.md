# 審稿結論

本版已修正共享頂點 \(w\)、上下翻轉測試、PPM 輸出與多數邊界敘述，數學手算亦大致正確。但接縫測試中的關鍵斷言必然失敗：目前線性 ramp 在 \(u=1.0\) 與 \(u=0.5\) 都取到 \(0.5\)。此外，魚體影像沒有使用指定的 checker，魚體三角形繞序也與全書逆時針約定相反。

## 一、必須修正的錯誤

### 1. 接縫測試的 `assert not np.allclose(...)` 必然失敗

**原程式：**

```python
seam_tex = generate_stripe_texture(8, 8)
seam_ok = sample_bilinear(seam_tex, 1.0, 0.5, wrap=True)
seam_bad = sample_bilinear(seam_tex, 0.5, 0.5, wrap=True)
assert np.allclose(seam_ok, sample_bilinear(seam_tex, 0.0, 0.5,
                                            wrap=True))
assert not np.allclose(seam_ok, seam_bad)
```

貼圖定義為：

\[
g(x)=\frac{x}{W-1},\qquad W=8.
\]

#### \(u=1.0\)

\[
x=1.0(8)-0.5=7.5.
\]

Repeat 後取 column 7 與 0，各權重 \(0.5\)：

\[
S(1.0)=\frac12(1)+\frac12(0)=0.5.
\]

#### \(u=0.5\)

\[
x=0.5(8)-0.5=3.5.
\]

取 column 3 與 4：

\[
S(0.5)
=\frac12\frac37+\frac12\frac47
=\frac12.
\]

因此：

\[
S(1.0)=S(0.5)=0.5.
\]

`assert not np.allclose(seam_ok, seam_bad)` 會失敗，程式不可能到達最後的預期訊息。

**修法：**

改用非線性且非對稱的 column 值，例如：

```python
def generate_seam_test_texture():
    values = np.array([0.0, 0.05, 0.15, 0.30,
                       0.50, 0.65, 0.80, 1.0],
                      dtype=np.float32)
    tex = np.zeros((8, 8, 3), dtype=np.float32)
    for x, g in enumerate(values):
        tex[:, x, :] = g
    return tex
```

此時：

\[
S(1.0)=\frac{1+0}{2}=0.5,
\]

而：

\[
S(0.5)=\frac{0.30+0.50}{2}=0.40,
\]

可可靠區分正確與錯誤中點。

另一種做法是不要比較兩個中點，而直接比較 \(u=0.9\) 與 \(u=1.1\)。目前習題 2 的這組測試可以區分，但它不是「正確中點與錯誤中點」的直接比較。

---

### 2. 正文宣稱 ramp 能區分 \(u=1.0\) 與 \(u=0.5\)，結論錯誤

**原句：**

> 程式比較連續分支 \(0.9\to1.1\) 的中點 \(u=1.0\)，與錯誤分支 \(0.9\to0.1\) 的中點 \(u=0.5\)；Repeat 下兩者取樣不同。

對目前線性 ramp 而言兩者均為 \(0.5\)，如上所算。這段預期結果必須連同程式一起修改，不能只改斷言。

應明確列出新測試貼圖下的手算值，避免再次因貼圖對稱性產生假陰性。

---

### 3. 魚體沒有貼上指定的 checker

章節實驗要求是：

> 把 checker 貼上魚體；測接縫、上下翻轉及透視插值。

但魚體光柵化實際使用：

```python
tex_seam = generate_stripe_texture(16, 16)
```

`generate_checker_texture` 只用於單點數值測試，沒有貼到魚身影像上。

**修法：**

至少輸出一組 checker 魚體影像：

```python
fish_checker_pc.ppm
fish_checker_affine.ppm
```

非對稱條紋可保留為接縫定位測試；方向貼圖可保留為 V 翻轉測試。三者目的應分開：

- checker：魚體貼圖與透視差異；
- 非對稱接縫貼圖：週期分支；
- 上紅下藍：V 翻轉。

---

### 4. 魚體三角形繞序與全書逆時針約定相反

全書約定從外向法線看為逆時針。現有第一個三角形：

```python
(A_ndc, B_ndc, D_ndc)
```

其中：

\[
A=(-0.8,0),\quad B=(0,0.6),\quad D=(0,-0.6).
\]

有向面積為：

\[
(B-A)\times(D-A)
=(0.8)(-0.6)-(0.6)(0.8)
=-0.96.
\]

第二個三角形 \((B,C,D)\) 同樣為負，因此在 NDC 的 \(Y\) 向上座標中皆為順時針。

目前 rasterizer 接受兩種繞序，所以仍會畫出來；但資料本身不符合全書模型前面逆時針的約定，也會在日後加入背面剔除時被剔除。

**修法：**

改為：

```python
body_tri_1 = (A_ndc, D_ndc, B_ndc)
body_tri_2 = (B_ndc, D_ndc, C_ndc)
```

並同步調整 UV 與 \(w\) 的傳入順序：

```python
uv_A, uv_D, uv_B
w_A, w_D, w_B
```

以及：

```python
uv_B, uv_D, uv_C
w_B, w_D, w_C
```

可加入：

```python
assert edge_function(A_ndc, D_ndc, B_ndc) > 0
assert edge_function(B_ndc, D_ndc, C_ndc) > 0
```

### 5. `perspective_uv` 未檢查 UV 本身是否有限

目前已檢查 \(w\)、重心座標與分母，但沒有檢查 `uv0`、`uv1`、`uv2`。若 UV 含 `nan` 或 `inf`，結果仍會靜默傳播。

建議加入：

```python
uvs = np.asarray([uv0, uv1, uv2], dtype=float)
if uvs.shape != (3, 2) or not np.all(np.isfinite(uvs)):
    raise ValueError("UVs must be finite 2D coordinates")
```

這是數值邊界完整性問題，雖不影響目前固定例題，但應與既有防護一致。

## 三、程式與預期結果

### 已改善部分

- 共享幾何頂點 \(B,D\) 現在使用一致的 clip \(w\)。
- 已正確說明後寫入者覆蓋先寫入者。
- 已明說未實作 top-left 規則。
- 上紅下藍貼圖可檢出 V 翻轉。

- PPM 輸出清楚標成線性 RGB 量化，而非一般 sRGB 顯示檔。
- 未聲稱實際執行程式。

### 尚應補強

魚體中心像素：

```python
assert np.any(img_pc[H_img // 2, W_img // 2] != 0)
```

位於共享邊附近，會由後畫三角形覆寫。雖然修正後兩側共享 \(w\) 與 UV 一致，結果應相容，但它不是很好的「魚身已繪製」測試。建議另外選取明確位於左右三角形內部的兩個像素。

此外，應對 PPM 檔案存在與大小的檢查留作讀者執行待辦；審稿不能聲稱檔案已實際產生。

## 四、索引、法線、色彩與邊界

- **索引：** 理論上的 render-vertex key 正確；程式使用展開三角形而非 index buffer，已不再誤稱真正索引網格。
- **法線：** 本章沒有法線變換。接縫處複製完整渲染頂點的說法可接受；硬邊兩側法線可不同。
- **色彩：** 線性 RGB 與輸出編碼界線正確。
- **邊界：** Repeat 與 Clamp 的四 tap 處理正確；\(W=H=1\) 測試合理。
- **共享邊：** 已正確承認非嚴格邊測試會重複涵蓋，不應再宣稱等同 top-left。
- **座標系：** UV 的 \(v\) 向上、影像 row 向下及 NDC \(Y\) 向上的轉換正確；但魚體繞序需依上述修正。

## 五、引用界線

來源清單仍未直接支撐透視屬性插值、雙線性 addressing 與微分 LOD；G8 又明示尚未逐節查核。這不必然構成拒稿理由，因正文已有自行推導，但應保留以下界線：

- 來源清單不代表逐條獨立查證；
- 不宣稱官方範例已執行；
- G1、G5 的變換內容不應被當作所有紋理取樣公式的直接依據；
- 程式與輸出仍須人工實跑驗證。

## 六、可選文風建議

1. 透視推導中的 \(\beta_i\) 公式重複兩次，可刪除一次。
2. 「屏幕」可統一為「螢幕」。
3. 「這個式子可以從相似三角形推導而得」可改成「可由相似三角形或齊次重心關係推導」，因正文沒有完整展開該推導。
4. 菱形模型宜稱「低面數魚身代理」，避免暗示包含魚尾、魚鰭等完整魚形。
