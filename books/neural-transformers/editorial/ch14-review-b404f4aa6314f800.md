## 二、已正確修復的部分

### 1. Softmax VJP 現已正確

逐字原句：

> $$  
> \frac{\partial L}{\partial S} = A \odot \left( G_A - \text{sum}(A \odot G_A, \text{axis}=T_k, \text{keepdims=True}) \right)  
> $$

這個公式正確。對每個 batch、每個 query，`sum` 沿最後的 key 軸進行，輸出 shape 為 $(B,T_q,1)$，再廣播回 $(B,T_q,T_k)$。例14.2所算的兩列 $dS$ 各自和為零，也符合 Softmax 對共同平移不變所導出的必要性質。

這部分不需再改。

### 2. $dK$ 公式與手算現已正確

逐字原句：

> $$  
> \frac{\partial L}{\partial K} = \frac{1}{\sqrt{d_k}} \left( \frac{\partial L}{\partial S} \right)^T Q  
> $$

以及程式：

> `dK = np.matmul(np.swapaxes(dScores, -1, -2), Q) / scale_factor`

兩者均正確。手算得到 $(3,2)$，與 $K$ 同 shape。這項已充分修復。

### 3. 前反向縮放因子已一致

逐字原句：

> `'scale_factor': scale_factor`

反向再讀取：

> `scale_factor = cache['scale_factor']`

這已修復上一稿前向允許自訂 scale、反向卻固定使用 $\sqrt{d_k}$ 的錯誤。

## 三、仍須修正的程式錯誤

### 1. batch broadcasting 的前反向契約仍不一致

逐字原句：

> `Q: (..., Tq, dk)`  
> `K: (..., Tk, dk)`  
> `V: (..., Tk, dv)`

前向使用：

> `scores = np.matmul(Q, np.swapaxes(K, -1, -2)) / scale_factor`

原因：

`np.matmul` 對前導軸採 broadcasting。因此，例如：

- `Q.shape == (2, 5, 4)`
- `K.shape == (1, 3, 4)`
- `V.shape == (1, 3, 6)`

前向可以產生 `(2,5,6)`。可是反向的 `dK`、`dV` 會帶有廣播後的 batch 大小2，沒有沿 batch 軸求和回 `(1,3,4)` 與 `(1,3,6)`。這違反本卷「廣播的反向需 sum 到原 shape」及「梯度與參數同 shape」的規則。

`dY` 檢查也依賴原始 $Q$：

> `if dY.shape != Q.shape[:-1] + (V.shape[-1],):`

若 $Q$ 本身也是被廣播的一方，此預期 shape 不等於真正 output shape。例如 $Q$ 為 `(1,Tq,dk)`、$K,V` 為 `(B,Tk,...)` 時，output batch 是 $B$，但這裡仍要求 batch 為1。

最小修法：

本章不必實作完整廣播反向；最小且安全的做法是明確禁止不同前導 batch shape：

```python
if Q.shape[:-2] != K.shape[:-2] or Q.shape[:-2] != V.shape[:-2]:
    raise ValueError("Q, K, V must have identical leading batch shapes")
```

並把 `dY` 檢查改成依 output 或注意力 shape：

```python
expected_dy_shape = attn_weights.shape[:-1] + (V.shape[-1],)
if dY.shape != expected_dy_shape:
    raise ValueError("dY shape mismatch")
```

若作者堅持支持 broadcasting，則必須保存原 shape 並實作 `sum_to_shape`，對 `dQ,dK,dV` 分別 reduction 回原輸入 shape；不能只依靠 `matmul` 自動廣播。

### 2. 有限差分內含一次錯誤且多餘的前向呼叫

逐字原句：

> `Y_plus, _ = scaled_dot_product_attention(param, K if name!='K' else K, V if name!='V' else V, mask)`

緊接著才按 `name` 再算一次：

> `if name == 'Q': ...`  
> `elif name == 'K': ...`  
> `elif name == 'V': ...`

原因：

第一行無論檢查哪個參數，都把 `param` 放在 $Q$ 的位置。檢查 $K$ 時，等同先呼叫：

```python
scaled_dot_product_attention(K, K, V, mask)
```

檢查 $V$ 時則先呼叫：

```python
scaled_dot_product_attention(V, K, V, mask)
```

在目前手算的非對稱 shape 中，這可能在真正的 `elif` 分支執行前就因 mask 或最後維度不合而拋錯。即使 shape 偶然相容，這也是無意義的額外前向，會掩蓋測試邏輯。

最小修法：

刪除整行多餘呼叫，只保留依 `name` 選擇正確參數位置的三個分支。更簡潔的做法是建立局部函式：

```python
def loss(q, k, v):
    y, _ = scaled_dot_product_attention(q, k, v, mask)
    return np.sum(y)
```

然後各自擾動 $Q,K,V$。

### 3. `stable_softmax` 仍無法拒絕全 `-inf` 行

逐字原句：

> `x_max = np.max(x, axis=axis, keepdims=True)`  
> `x_shifted = x - x_max`

以及：

> `if np.any(sum_exp == 0):`

原因：

若一列全為 `-np.inf`，則 `x_max` 也是 `-np.inf`，計算 `-inf - (-inf)` 會得到 `NaN`。其後 `sum_exp` 是 `NaN`，而 `NaN == 0` 為 False，因此現有檢查不會攔截，仍會回傳 NaN。

函式註解承認：

> 若輸入含 NaN 或全列為 -inf，會導致未定義行為或錯誤，需在上游檢查。

但上游只檢查布林 mask 的全 False 行，沒有檢查 $Q,K,V$ 或 `scores` 中的非有限值。因此「需在上游檢查」目前並未真正實作。

最小修法：

在減最大值前檢查：

```python
if np.any(np.isnan(x)) or np.any(np.isposinf(x)):
    raise ValueError("softmax input contains NaN or +inf")
if np.any(np.all(np.isneginf(x), axis=axis)):
    raise ValueError("softmax row has no finite logit")
```

對部分 `-inf`、部分有限值的合法遮罩列應允許。也可直接檢查每列至少有一個有限元素：

```python
if np.any(~np.any(np.isfinite(x), axis=axis)):
    raise ValueError("each softmax row needs a finite logit")
```

同時明定是否拒絕所有非有限 $Q,K,V$；較簡單的策略是在 attention 入口拒絕 `NaN` 和無限輸入。

### 4. `d_k=0` 未被拒絕

逐字原句：

> `dk = Q.shape[-1]`  
> `scale_factor = np.sqrt(dk)`

若最後一軸長度為0，預設 scale 為0，後面的檢查雖會拒絕，但錯誤訊息是 `scale_factor must be finite and non-zero`，沒有明確表達非法維度。更重要的是，自訂非零 scale 時，空的 $d_k$ 可能繞過此語義要求。

最小修法：

在 shape 驗證中加入：

```python
if Q.shape[-1] <= 0:
    raise ValueError("dk must be positive")
if K.shape[-2] <= 0:
    raise ValueError("Tk must be positive")
```

$T_q=0$ 是否允許也要明定；為避免空 reduction，核心教學實作可直接拒絕。

### 5. `scale_factor` 應要求正值，而不只是非零

逐字原句：

> `if scale_factor == 0 or not np.isfinite(scale_factor):`

負 scale 在代數上能計算，但不再符合本章「除以正的尺度」之定義，且會反轉分數排序。

最小修法：

```python
if not np.isscalar(scale_factor):
    raise TypeError(...)
if not np.isfinite(scale_factor) or scale_factor <= 0:
    raise ValueError("scale_factor must be finite and positive")
```

### 2. 浮點 mask 習題沒有定義合法域與全遮罩判定

逐字原句：

> 假設 mask 浮點數中，負值極小表示遮罩

以及：

> `scores = scores + mask`

原因：

「負值極小」不是精確契約。`-1e9` 在數學上仍是有限 bias，不是禁止注意；若原 logits 更大或使用低精度，語義可能改變。程式也無法由任意浮點矩陣可靠判斷哪些元素是遮罩，更無法檢測「全遮罩」。

最小修法：

把它明確區分為：

- 布林 allowed mask：負責禁止元素和全遮罩拒絕；
- additive bias：任意有限數，可改變 logits，但不代表禁止；
- 若要用浮點 hard mask，只接受元素為 `0` 或 `-np.inf`，並檢查每列至少有一個有限位置。

梯度驗證還要明說 mask/bias 是常數，不對其求梯度。

### 3. 習題4對梯度的敘述仍錯誤且過度絕對

逐字原句：

> 導致梯度在大部分方向上為零，僅在最大分數對應的 Key 上有梯度。

原因：

Softmax 導數為

$$
\frac{\partial A_i}{\partial S_j}=A_i(\delta_{ij}-A_j).
$$

當 $A$ 趨近 one-hot 時，不只是非最大位置梯度趨近零；最大位置的自身導數 $A_m(1-A_m)$ 也趨近零。不能說「僅在最大 Key 上有梯度」。對完整 loss 而言，$dV=A^TdY$ 可能主要流向最大權重的 value，但 $dS$、$dQ$、$dK$ 是另一回事，必須區分。

最小修法：

改成：

> 分布更尖銳時，Softmax 對 logits 的 Jacobian 許多分量可能很小，使 $dS$、進而 $dQ,dK$ 的部分方向梯度變弱；但具體梯度仍取決於上游 $dA$。

## 六、定義與能力敘述

### 1. Shape 約定前後不一致

逐字原句：

> $Q, K \in \mathbb{R}^{B \times T \times d_k}$，$V \in \mathbb{R}^{B \times T \times d_v}$。

但正式定義使用 $T_q$ 與 $T_k$。

原因：

本章特別要求非對稱長度，開頭卻先把三者寫成同一 $T$，容易讓讀者誤以為只支持 self-attention 的等長情形。

最小修法：

統一改為：

$$
Q\in\mathbb{R}^{B\times T_q\times d_k},\quad
K\in\mathbb{R}^{B\times T_k\times d_k},\quad
V\in\mathbb{R}^{B\times T_k\times d_v}.
$$

### 2. 方差命題結論仍略過度

逐字原句：

> 從而避免 Softmax 過度飽和。

方差維持1只能說降低因 $d_k$ 增大而造成尺度擴張的風險，不能保證不飽和；均值、相關性、訓練後投影分布和極端值都會影響 Softmax。

最小修法：

將「避免」改成「降低僅因維度增加而過度飽和的風險」。

### 3. 注意力權重仍被說成「貢獻」

逐字原句：

> 僅表示在當前模型表示下該 Token 對當前預測的貢獻較大。

原因：

權重較大不必然代表對最終預測貢獻較大，因為 value 的方向與大小、輸出投影、殘差及後續層都會影響結果。作者已正確否認因果解釋，但「貢獻較大」仍過強。

最小修法：

改為「表示該 query 對該 key/value 位置分配了較大的混合權重；不能單由權重判定最終貢獻或因果關係」。
