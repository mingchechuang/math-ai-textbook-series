## 二、主要必要修正：測試仍非完整可重現

逐字原句：

> `Q = np.random.randn(2, 3, 4).astype(np.float64)`  
> `K = np.random.randn(2, 3, 4).astype(np.float64)`  
> `V = np.random.randn(2, 3, 4).astype(np.float64)`

以及：

> `dY = np.random.randn(2, 3, 4).astype(np.float64)`

後面才建立：

> `rng = np.random.default_rng(14)`

原因：

第一組正常前向、梯度 shape、三路有限差分、全遮罩及廣播測試都使用全域 `np.random`。只有後面的非對稱測試使用固定局部生成器。因此每次執行 `run_tests()` 時，測試3的有限差分資料不同，固定的 $10^{-5}$ 門檻並不對應一組明確可重現的案例。

這不表示解析梯度錯誤；解析梯度已重算為正確。但章級程式應讓失敗案例可重現。使用全域隨機狀態也會使結果受到先前其他程式是否消耗過 RNG 的影響。

最小修法：

把局部生成器移到 `run_tests()` 開頭：

```python
def run_tests():
    rng = np.random.default_rng(14)
```

然後把所有：

```python
np.random.randn(...)
```

改成：

```python
rng.standard_normal(...)
```

例如：

```python
Q = rng.standard_normal((2, 3, 4))
K = rng.standard_normal((2, 3, 4))
V = rng.standard_normal((2, 3, 4))
dY = rng.standard_normal((2, 3, 4))
```

全遮罩與廣播測試也使用同一個局部 `rng`。這只使章內輸入生成可重做，不代表跨 NumPy 版本、不同 BLAS 或不同平台逐位一致，正文不需作更強承諾。

## 三、測試2名稱仍超出實際證據範圍

逐字原句：

> `# 測試 2: 梯度驗證`

其內容是：

> `assert dQ.shape == Q.shape`  
> `assert dK.shape == K.shape`  
> `assert dV.shape == V.shape`

原因：

這只驗證梯度 shape，不驗證數值。真正的數值梯度核對在測試3。測試2所建立的隨機 `dY` 也沒有被測試3使用；`finite_diff_check` 內部重新使用 `np.ones_like(Y)`。

這不是反向公式錯誤，但測試名稱把 shape 證據描述成完整梯度驗證，超出了實際範圍。

最小修法：

將註解改成：

```python
# 測試 2: 梯度 shape
```

文字段的：

> **測試2**：驗證梯度形狀與參數一致。

本身已正確，可保留。

若希望測試2確實成為數值梯度驗證，則讓 `finite_diff_check` 接受同一個 `dY`，並將標量目標改為：

```python
return np.sum(y * dY)
```

但這不是必要擴充；改名即可。

## 五、有限差分的證據方向應明示

逐字原句：

> `dY = np.ones_like(Y)`

及：

> `return np.sum(y)`

這兩者一致，故當前有限差分在數學上正確。其標量目標是：

$$
L(Q,K,V)=\sum_{b,t,r}Y_{btr}.
$$

但「有限差分驗證 $Q,K,V$ 的梯度」容易被讀成對任意上游梯度的全面驗證。實際上，這只核對全一 $G_Y$ 所對應的一個 VJP 方向。

最小修法：

在 docstring 補一句：

> 本函式核對標量目標 `sum(Y)`，故上游梯度固定為全一張量。

或者把函式擴充為接受 `dY`：

```python
def finite_diff_check(Q, K, V, mask=None, dY=None, eps=1e-5):
```

並以 `np.sum(y * dY)` 作標量目標。後者較全面，但前者已足以滿足本章小型有限差分要求。

## 七、反例與常見陷阱仍有過度確定的效能結論

逐字原句：

> Softmax 輸入差異過大，導致權重極端二值化，梯度極小，訓練收斂緩慢。

原因：

在命題假設下，$d_k=512$ 的未縮放內積標準差約為22.6，確實提高 Softmax 尖銳和 logits 梯度變弱的風險。但不能由標準差單獨推出每一列都會「極端二值化」，更不能未經訓練實驗便斷言「訓練收斂緩慢」。

這也與正文較謹慎的：

> 可能使 Softmax 權重過於尖銳

不一致。

最小修法：

改成：

> 在命題的尺度假設下，未縮放分數的標準差約22.6，較容易產生尖銳權重並使傳向 logits 的部分梯度變弱，增加優化困難。

如此不需要任何實測收斂率支持。

## 八、習題1仍可避免一維轉置歧義

逐字原句：

> $Q=[1,0],K=[1,1],V=[1]$

最小修法：

改成明確二維矩陣：

$$
Q=\begin{bmatrix}1&0\end{bmatrix},\quad
K=\begin{bmatrix}1&1\end{bmatrix},\quad
V=\begin{bmatrix}1\end{bmatrix}.
$$

並明列 shapes 為 $(1,2),(1,2),(1,1)$。答案不需改變。

## 九、核心程式的其他核對結果

### 1. Shape 與廣播

逐字原句：

> `if Q.shape[:-2] != K.shape[:-2] or Q.shape[:-2] != V.shape[:-2]:`

此檢查正確執行了「不支持前導軸 broadcasting」的章內策略。反向因而不需 reduction 回原 shape。

### 2. Mask

逐字原句：

> `mask_float = np.where(mask, 0.0, -np.inf)`

布林 `True=Allowed` 的轉換正確。全 False row 在進入 Softmax 前已拒絕。合法 masked 位置得到 $A=0$，因而：

$$
G_S=A\odot(\cdots)=0.
$$

### 3. 非有限值

$Q,K,V$ 被要求全部有限，`stable_softmax` 拒絕 `NaN`、`+inf` 及全 `-inf` row。部分 `-inf` row 合法。策略清楚且不會讓 NaN 靜默流入。

### 4. 自訂 scale

前向把 `scale_factor` 存入 cache，反向使用同一數值。這已避免前後 scale 不一致。要求 scale 為有限正數亦合理。

### 5. $dK$ 轉置

程式：

> `dK = np.matmul(np.swapaxes(dScores, -1, -2), Q) / scale_factor`

正確產生 `(..., Tk, dk)`，與 $K$ 同 shape。
