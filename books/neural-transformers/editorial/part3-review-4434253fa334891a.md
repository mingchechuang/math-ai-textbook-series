# 必須修訂

## 1. 第16章類別 docstring 與實際 `dv` 介面矛盾

### 原句

```python
"""自足多頭注意力前向。

張量約定：
  X:    (B, T, D)
  Q,K,V:(B, T, D) 投影後 -> 拆分 (B,H,T,dh)
  S,A:  (B, H, T, T)
  O_h:  (B, H, T, dh)
  O:    (B, T, D)
"""
```

### 原因

類別不是只有預設 $d_v=d_h$；建構子公開接受 `dv`，測試也正式覆蓋 `dv=3`。一般情形是：

$$
Q,K\in\mathbb R^{B\times T\times D},
$$

$$
V\in\mathbb R^{B\times T\times Hd_v},
$$

$$
O_h\in\mathbb R^{B\times H\times T\times d_v},
\qquad
O\in\mathbb R^{B\times T\times Hd_v}.
$$

docstring 現在將 V、$O_h$、O 都寫死成預設 shape。這不只是風格問題；讀者若依 docstring 建立 V 或檢查 `W_O`，在 `dv!=dh` 時會使用錯誤維度。

### 最小修法

改成：

```python
"""自足多頭注意力前向與反向。

張量約定：
  X:      (B,T,D)
  Q,K:    (B,T,D) -> (B,H,T,dh)
  V:      (B,T,H*dv) -> (B,H,T,dv)
  S,A:    (B,H,T,T)
  O_h:    (B,H,T,dv)
  O:      (B,T,H*dv)
  Y:      (B,T,D_out)
預設 dv=dh，此時 H*dv=D。
"""
```

同時把「前向」改成「前向與反向」，因為類別目前已包含完整 backward。

## 2. 第16章邊界條件仍錯寫一般 `W_O` shape

### 原句

> 「`D_out ≠ D`：若在 `__init__` 指定 `D_out`，`Y.shape == (B,T,D_out)`，`W_O.shape == (D, D_out)`。」

### 原因

實際程式是：

```python
self.W_O = rng.normal(
    0, 1/np.sqrt(H*self.dv),
    (H*self.dv, self.D_out)
)
```

所以一般契約是：

$$
W_O\in\mathbb R^{Hd_v\times D_{\text{out}}}.
$$

只有 `dv=dh` 時才有 $Hd_v=D$，因而得到 `(D,D_out)`。本章已把 `dv` 作為正式介面，不能在邊界條件無條件寫成 D。

### 最小修法

改為：

> `Y.shape==(B,T,D_out)`；一般 `W_O.shape==(H*dv,D_out)`，預設 `dv=dh` 時才化為 `(D,D_out)`。

## 3. 第14章 backward 對非法或非有限 `dY` 沒有明確拒絕

### 原句

```python
expected_dy_shape = attn_weights.shape[:-1] + (V.shape[-1],)
if dY.shape != expected_dy_shape:
    raise ValueError("dY shape mismatch")
```

### 原因

存在兩個問題：

1. 傳入 Python list 時會在 `dY.shape` 產生 `AttributeError`，不是章內定義的介面錯誤。
2. 傳入含 NaN 或 infinity 的上游梯度時，`dQ,dK,dV` 會靜默成為非有限值。

第16章已嚴格檢查：

```python
not isinstance(dY, np.ndarray)
...
not np.isfinite(dY).all()
```

因此第14章作為第16章明列的反向先備，接口反而較弱。第14章測試文字聲稱「錯誤上游梯度形狀均被拒絕」，但沒有涵蓋型別與非有限上游。

### 最小修法

```python
if not isinstance(dY, np.ndarray):
    raise TypeError("dY must be a NumPy array")
if dY.shape != expected_dy_shape:
    raise ValueError("dY shape mismatch")
if not np.all(np.isfinite(dY)):
    raise ValueError("dY must contain only finite values")
```

測試增加：

```python
rejects(lambda: scaled_dot_product_attention_bwd(
    [[[1.0]]], c), TypeError)

bad_dy = np.ones_like(y)
bad_dy[0, 0, 0] = np.nan
rejects(lambda: scaled_dot_product_attention_bwd(
    bad_dy, c), ValueError)
```

## 4. 第15章新增的位置與 `causal` 契約沒有故障測試

### 原句

現已新增：

```python
if not isinstance(causal, (bool, np.bool_)):
    raise TypeError(...)
```

以及：

```python
if not np.issubdtype(pos.dtype, np.integer) ...
if np.any(pos < 0):
```

但 `run_checks()` 沒有測試這些新分支。

### 原因

章稿明文列出正常／邊界／故障測試，且位置 dtype 是 causal 與 cache 的核心接口。現稿雖然實作正確，但測試沒有證明預期故障路徑已被納入驗收。尤其本輪修正正是為避免：

- 浮點位置被截斷；
- bool 冒充位置；
- 負絕對位置；
- `"False"` 被 Python 視為 truthy causal 設定。

### 最小修法

在 `run_checks()` 增加：

```python
for bad_call in (
    lambda: make_allowed(
        np.array([0.5]), np.array([0]),
        np.array([True]), True),
    lambda: make_allowed(
        np.array([True]), np.array([0]),
        np.array([True]), True),
    lambda: make_allowed(
        np.array([-1]), np.array([0]),
        np.array([True]), True),
    lambda: make_allowed(
        np.array([0]), np.array([0]),
        np.array([True]), "False"),
):
    try:
        bad_call()
    except (TypeError, ValueError):
        continue
    raise AssertionError("非法位置或causal設定被接受")
```

最好分開寫預期例外型別，使測試不會把錯誤分支誤當正確拒絕。

## 5. 第16章 `_last_dS` 沒有初始化或在失敗／新 forward 時清除

### 原句

建構子只有：

```python
self._cache = None
```

forward 開頭只有：

```python
self._cache = None
```

backward 中才建立：

```python
self._last_dS = dS.copy()
```

### 原因

在第一次 backward 前存取 `_last_dS` 會得到 `AttributeError`。更重要的是，若已成功 backward 一次，接著再執行新的 forward，`_last_dS` 仍保存上一個計算圖的梯度。若新 forward 或其後 backward 失敗，呼叫端可能誤讀舊值。

既然 `_last_dS` 已成為章內 mask-gradient 驗收接口，就應有清楚生命週期。

### 最小修法

建構子加入：

```python
self._last_dS = None
```

forward 開頭加入：

```python
self._cache = None
self._last_dS = None
```

若 backward 在計算中失敗，也不應留下半舊半新的狀態；可先局部計算，所有有限性檢查完成後才賦給 `_last_dS`。
