我先按章內定義重算，再核對程式與測試。結論是：遮罩的數學定義、兩個手算例題和有效 token 平均公式大致正確；但程式尚不能實作它宣稱支援的矩形 cache 情境，因果性測試也沒有把「禁止未來」與「禁止 PAD」分開驗證。另有兩處習題反例條件或文字寫反。這些是可局部修正的問題，不必重寫本章。

**重算核對。** 例題一只允許分數 $2,1$，權重確為 $1/(1+e^{-1})\approx0.7311$ 與 $e^{-1}/(1+e^{-1})\approx0.2689$；輸出約 $12.689$。例題二的 query 位置 $4,5$ 對 key 位置 $0,\ldots,5$，允許矩陣確為兩列 `[1,1,1,1,1,0]`、`[1,1,1,1,1,1]`。習題一的輸出 $5$、習題二的兩列矩陣也正確。程式的 `axis=1` 是單筆資料分數矩陣的 key 軸；`masked_token_mean` 只對有效位置求和並除以有效目標數，沒有重複平均。小命題在其明列的「各位置投影僅依該位置表示」等假設下成立；正文也適當限制了它不能排除前處理或切分洩漏。

以下列出須修的逐字原句、原因及最小修法：

1. **矩形注意力的宣稱與 query 取法不符。** 原句：「以下 NumPy 程式自足地建立允許遮罩，執行單頭注意力，並支援 padding key 與絕對位置。」程式原句：`q = x[:tq]`。`make_allowed` 雖以絕對位置建立 $(T_q,T_k)$ 遮罩，`attention` 卻一律取 **key 序列開頭**的 $T_q$ 筆作 query。例如章內 cache 例子的 query 是絕對位置 `[4,5]`、key 是 `[0,1,2,3,4,5]`；傳入六筆 `x` 時，程式實際使用 `x[0:2]`，不是 `x[4:6]`。因此矩形遮罩的手算正確，程式卻不能用它核對該例的輸出；`T_q>T_k` 時還會有矩陣形狀問題。最小修法是讓 `attention` 分別接收形狀 $(T_q,D)$ 的 query 輸入及 $(T_k,D)$ 的 key/value 輸入，並核對遮罩形狀；或者明確把程式限定為「query 是 key 序列前綴」，撤回其 cache 支援宣稱，另提供一個實際核對後綴 query 的小測試。前一種修法較能達成本章目標。

2. **現有「改未來」測試只證實 PAD 遮蔽。** 原句：「`# 因果性：改變未來 token，不應影響位置 0、1 的輸出。`」以及 `key_valid = np.array([True, True, False])`、`x_changed[2] = ...`。被改的第 2 個位置同時是 PAD key，故即使移除因果條件、只保留 key padding mask，前兩列輸出仍不變。這不能獨立發現因果 mask 遺漏的故障。最小修法是另設三個**均有效**的 token，對位置 0 或 1 的輸出比較修改位置 2 前後的結果；再加入一個故障對照：關掉 causal 限制並選擇會使早期輸出改變的輸入。原 PAD 測試可保留，用來專測 padding。

3. **非有限檢查不足以兌現故障測試的承諾。** 原句：「**故障測試**：全遮罩 query 列、零有效目標 token、形狀不相符和非有限輸入應引發 `ValueError`，而非產生可被忽略的 NaN。」程式只在點積前檢查 `np.isfinite(x)`。有限但極大的 `float64` 輸入仍可使 `q @ k.T` 溢位成無窮；後續減去列最大值可能產生 NaN，而程式沒有檢查 `scores`、`probs` 或輸出。此外，`allowed` 若為一維或零維，`allowed.shape[1]` 會先引發 `IndexError`，不是文中預期的 `ValueError`。最小修法是在讀取遮罩兩軸前檢查 `allowed.ndim == 2` 及其與 query/key 長度相符，並在點積後明確拒絕非有限的**允許位置分數**，或清楚界定可接受的輸入數值範圍。增加畸形遮罩和有限極大輸入的預期故障測試；不要把目前沒有涵蓋的情況寫成已由檢查保證。

4. **反例題漏了使 PAD 可讀的條件。** 原句：「有人把 padding mask 套到 query 軸，因此 PAD query 不輸出；但沒有遮蔽 padding key。請構造一個長度為 2、補齊到 3 的序列，解釋位置 0 如何讀取位置 2 的 PAD value。」若同時套用本章的因果 mask，位置 0 不可能讀取未來位置 2；解答的「位置 0 的 query 仍可注意位置 2 的 key」因此缺少前提。最小修法是在題目明說**此反例不使用因果 mask，例如雙向注意力**；或改問 PAD 前方的有效 query 在未遮 key 時如何受影響，並相應指定可讀的配對。

5. **習題六的列欄不等號寫反。** 原句：「方形遮罩的『矩陣列號不大於欄號』不能表達 cache 外部的歷史位置。」若「列號」指 query 行索引、「欄號」指 key 列索引，通常下三角形允許的是**欄號不大於列號**。本題給出的正確絕對位置結果 `[1,1,1,1]` 沒錯，但這句會把讀者對 `tril` 的方向教反。最小修法是將引號內改為「key 欄號不大於 query 列號」，再說明這種局部索引規則不可直接替代 cache 中的絕對位置比較。

6. **程式題三的解答尚未完整回答「修改程式」。** 題目原句：「修改程式，讓 `make_allowed` 另可接收 padding query mask，並用清楚的回傳值或獨立函式實作『padding query 輸出歸零』。」解答只說「可讓 `make_allowed` 只負責 query–key 是否配對，另設獨立的輸出函式」，沒有交代題目要求新增的參數應如何接收或回傳；現有 `zero_padding_queries` 雖展示了清零，但沒有完成題目指定的介面修改。最小修法是讓題目直接要求「沿用 `make_allowed`，另以 `zero_padding_queries` 實作並測試」，使題解對題；若保留「另可接收」要求，解答就需給出明確介面與最小可用修改，且不能將無效 query 直接變成全遮罩列。
