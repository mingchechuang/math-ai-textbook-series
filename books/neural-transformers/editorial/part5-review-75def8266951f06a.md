本輪只審第25至30章。我先按各章公式與程式路徑重算，再核對測試是否真的能支持正文的敘述；沒有執行程式，也不把程式中的斷言當作通過紀錄。六章都有自足的小命題證明、兩個以上逐步手算，以及手算、程式、反例、整合四類習題與解答。第30章亦完整列出模型、資料、loss、optimizer和訓練 loop，不能以「省略完整 Transformer」為由拒稿。以下是仍須修正的可定位問題。

## 先行重算：可保留的部分

第25章採本卷的列式批次約定，$X:(B,D_{\text{in}})$、$A:(D_{\text{in}},r)$、$B:(r,D_{\text{out}})$，所以$(XA)^TG$與$X^TGB^T$分別是$(r,D_{\text{out}})$及$(D_{\text{in}},r)$。手算例一得到$[25,-7]$；習題中$D_{\text{in}}=3,r=2,D_{\text{out}}=4$時，LoRA的14個參數確實多於原矩陣的12個。這些並非問題。

第26章的單樣本蒸餾梯度$(q-p)/T$與第27章雙向對比損失的手算方向、有效配對數分母均正確。第28章「甲池於週一巡查。」的Python半開字元區間$[0,8)$正確。第29章在其**可信、唯讀handler且日誌成功追加**的限定假設下，受保護狀態保持性證明成立；雜湊鏈也已明說不能抵禦重寫全鏈或截斷尾端。第30章完整前向以位置$j\leq i$遮罩，逐token cache則只累積過去及當前key；在同權重、eval及無dropout的比較條件下，這兩條路徑的設計相符。這些疑慮不應阻擋稿件。

## 必須修正的問題

### 1. 第26章習題B2把「硬標籤也使用溫度」的梯度少除了一次$T$

**原句：**「若約定硬標籤項也用同一個溫度 $T$，第二項改為 $\alpha\,(q_{soft}-y)/N$。」

**重算與原因：** 若該項定義為$\alpha\,\mathrm{CE}(y,\mathrm{softmax}(z_s/T))$，先對縮放後的logits $z_s/T$微分得到$q_{\text{soft}}-y$，再對原學生logits微分必須乘鏈式法則的$1/T$。按$N$筆樣本平均後，第二項應為$\alpha(q_{\text{soft}}-y)/(TN)$。現句會令照答案實作的讀者在$T\ne1$時得到錯誤梯度，且中心差分會顯示不合。

**最小修法：** 把該式改成$\alpha(q_{\text{soft}}-y)/(TN)$；若作者意圖同時乘$T^2$，須先在**損失定義**明寫該額外係數，再相應修改梯度。原答案前一種「硬標籤項採$T=1$」的公式不需改。

### 2. 第26章對極端溫度的「有限KL」承諾超出程式所能保證

**原句：**「$T$ 很小，例如 $T=10^{-3}$ 而 logits 是 $\pm20$……KL 由 `np.where` 守住零機率項，仍可算出有限值。」

**原句：**「以 `np.where` 先判斷再乘，才能保證 `kl_per_sample` 不會出現 NaN。」

**重算與原因：** `softmax_temp`只檢查原始`z`及`T`有限且為正，接著做`s = z / T`。兩者各自有限，不保證商仍有限：足夠小的有限正$T$可使`s`溢為`inf`；此時`logsumexp`中的`s - m`可能出現`inf-inf`，成為NaN。即使商未溢位，`np.where`也不是「先判斷再乘」：NumPy會先計算兩個分支所用的運算式，再按遮罩選值。就稿中$[500,-500]$的例子而言，穩定logsumexp算出的`logp`第二項是有限的$-1000$，並**不是**答案所稱的`-inf`。`p`可因`exp(-1000)`下溢為零，但`logp`仍可有限；保留零機率項為零的策略合理，解釋卻須與實際運算一致。

**最小修法：** 在`s=z/T`後立即檢查有限性，無法表示就明確拒絕；對`st`、`ss`亦採同一策略。把「仍可算出有限值」限縮為所給、縮放後仍有限的例子，把「先判斷再乘」改為「選取零機率項的輸出為零，但兩分支運算仍會求值」，並修正B3的`logp=-inf`說法。若要保證不產生無效中間運算，改用有效索引計算，而非只依賴`np.where`。

### 3. 第26章逐輸出通道函式沒有實現正文宣稱的故障契約

**原句：**「（一）輸入含 `np.nan` 或 `np.inf`：預期 `quantize_symmetric` 與 `softmax_temp` 都拋出 `ValueError`。」

**原句：**「逐通道量化一個 $(4,3)$ 權重矩陣，預期 `scale` 形狀為 $(1,3)$，且每一欄的最大誤差 $\le$ 該欄尺度的一半。」

**相關程式：** `quantize_per_column(W, bits)`直接計算`qmax`、`np.max(np.abs(W), axis=0, keepdims=True)`、`W / scale`，沒有與逐張量函式相同的`bits`及非有限輸入檢查，也沒有矩陣shape或零長reduction檢查。

**原因：** 對有限、非空$(4,3)$矩陣，所寫`axis=0`與$(1,3)$廣播是正確的；問題不在軸。問題是同章把非有限輸入「應拒絕」寫成量化契約，卻只有逐張量入口實現。逐通道入口遇NaN、Inf或無法reduction的空輸入，可能由NumPy運算警告或其他例外處理，不能聲稱由該函式按契約明確拒絕。

**最小修法：** 為`quantize_per_column`補二維、非空維度、位元數及有限值檢查，並加入直接呼叫該函式的正常、零欄、非有限及非法位元數測試；或把正文的拒絕承諾明確限於`quantize_symmetric`，另定逐通道入口策略。

### 4. 第26章存在不能由稿件支持的來源取得聲稱

**原句：**「[N1]……（2026-10-06 取得摘要頁，未完整閱讀）。」

**原句：**「[N3]……（已取得 2.14 API 全文；非本機版本或執行證據）。」

**原因：** 本次提交沒有可核對的取得紀錄，稿件本身亦不能證實作者在指定日期取得摘要頁或已取得API全文。這不同於列出可定位網址；它們是對查閱行為與能力的具體陳述。本審稿也未查閱這些網址，不能代作者確認。第27章參考來源的「目前僅有摘要頁取得紀錄」有同一問題；第25、28、30章較保守的「背景／延伸入口、未完整核對」寫法則可保留。

**最小修法：** 沒有獨立取得紀錄時，刪除取得日期、「已取得全文」及「取得紀錄」，只保留作品、網址及「未逐條／未完整核對」的範圍聲明。這不是要求刪除來源網址。

### 5. 第27章文字時間戳的語義與生成方式須對齊

**原句：**「若整段文字只有一個輸入時間，把該時間複製到每個非 PAD token 只是一種資料表示，不能解讀為每個詞都在不同實體時刻發生。」

**相關程式：** `tx = tau + delay + 0.1 * np.arange(L, dtype=np.float32)`。

**原因：** 文字先被描述為稍後輸入的日誌，正文又提醒整段文字共用一個輸入時間；程式卻給相鄰token相差$0.1$秒的時間戳，並把這些值投入逐token時間池化。若這是有意合成的「token逐項出現時間」，資料契約未說明其物理或合成語義；若日誌只有一次輸入時間，這些人工錯開的時間會使後方token的池化權重改變，與正文示範的表示方式不同。這不使shape錯誤，也不否定平移不變性的數學命題，但會令讀者誤讀對齊對象。

**最小修法：** 二選一：令所有非PAD token共用同一合成輸入時間；或明寫$0.1$秒是生成器**刻意指定的合成token時間**，不代表現實逐詞事件時間，並解釋為何要以它加權。PAD遮罩仍須保留。

### 6. 第29章習題2的答案不能接在章內既有程式後執行

**原句：**「請寫出註冊這些工具的程式碼片段。」

**相關答案：** `gateway.register_tool("get_sensor_data", …, handler_func=get_dissolved_oxygen)`。

**原因：** 主程式已先把名為`get_dissolved_oxygen`的handler登錄在另一名稱之下，所以改名註冊本身並非重複；但答案新設的`get_sensor_data`契約只檢查`sensor_id`為最長五字的字串，而其handler會接受符合長度但非DO格式的ID，再按mock資料回傳。更重要的是，答案給`get_historical_report`、`render_export_preview`註冊匿名mock，沒有提供「可信初始化時固定allowlist」的獨立建構步驟；若直接沿用章內全域`gateway`，先前測試已改動日誌與角色並新增工具，整合答案所聲稱的權限矩陣並不是一個可獨立核對的初始化狀態。這是習題解答自足性及契約一致性問題，不是主程式允許寫入工具的證據。

**最小修法：** 在答案以一個新建gateway及明列的mock handlers示範矩陣，對感測ID補與所委派handler一致的格式限制；並說明此段只由可信初始化程式執行。毋須重寫第29章主程式。

### 7. 第30章manifest測試不能證明「視窗跨集合」會被攔截

**原句：**「故意將同一文件的視窗分到不同集合時，manifest驗證預期拒絕。」

**相關程式：** `bad_manifest = manifest + [dict(manifest[0], split="test")]`，隨後呼叫`validate_manifest(bad_manifest)`。

**重算與原因：** `make_windows`產生`(x, y, doc.doc_id)`，但`validate_manifest`只接受逐**文件**的列，檢查同一`doc_id`是否出現在不同split。故障注入複製的是同一文件的manifest列，不是把實際視窗分配到另一集合。因此這個斷言可證「manifest中同一文件標了兩種split會被拒絕」，卻不能證「實際建立的視窗沒有跨集合」；一個錯誤的視窗分配實作即使留下乾淨manifest，仍可通過現有測試。

**最小修法：** 將測試敘述限縮為「重複文件跨split的manifest拒絕」；另加一項窗口來源核對：逐一比較train、val、test `pairs`內的`doc_id`集合與manifest所允許的split，並故意把一個train窗口插入test `pairs`，預期核對失敗。這能直接測到所宣稱的故障。

### 8. 第30章工具「引用」仍缺少回傳時的原文覆核

**原句：**「工具回傳文件id及字元span。拒絕請求會在工具呼叫前中止；已發生的唯讀查詢則記入事件。」

**相關程式：** `audited_answer`只在`hit["doc_id"] == cited_doc_id`時回傳`{"status": "有來源片段", "citation": hit, ...}`。

**原因：** `ReadOnlyMock.lookup`從當下記憶體文字取得子字串，所以正常路徑中`start:end`是合法的；這點不能誤判為已產生虛構座標。但`audited_answer`沒有獨立驗證回傳hit的區間、文字及指定版本，也沒有版本欄位。章稿同時主張「來源片段保留文件識別及起訖位置；找不到來源就拒答」，習題解答更要求span與原文相符。若mock結果被替換、資料更新，或以其他工具實作接入，相同`doc_id`本身不足以核驗引用。現有回答只宜稱為「本次lookup回傳的命中片段」，不能當作具版本約束的引用驗證。

**最小修法：** 對本例增加固定版本欄位，並在`audited_answer`回傳前按`doc_id`、版本、$0\leq start<end\leq|text|$及`text[start:end] == span`覆核；未通過就拒答。若不增加覆核，則限縮正文的「可核驗來源」主張，並列為待擴充邊界。

## 不列為拒稿理由的範圍問題

第26章所寫的8位元「四分之一」是**每參數理論位元數**比較，章內隨即區分實際儲存、反量化與速度；不應誤判成聲稱其`int64` NumPy示範已節省四分之三記憶體。第27章把全缺失模態的池化暫存為零，同時回傳有效遮罩，並在`pair_loss`先篩共同有效索引；這符合其明示規則，不是把全缺失偷偷送入對比loss。第29章`pass`只用在兩個例外類別的空類別體，不是未完成的程式占位；`HANDLER_CALL_COUNT`亦已標為測試狀態，不能拿它反駁受保護業務狀態的限定命題。第30章位置偏移故障測試依賴隨機初始化後的輸出差異，屬預期測試而非數學必然；正文沒有聲稱已通過，故不以此單獨拒稿。

整體上，第25、28章的核心推導與故障路徑可保留，第27、29、30章的架構邊界大體清楚；但第26章的可操作梯度答案和數值承諾必須修正，第30章兩項「測到甚麼／引用核驗到哪一層」的主張亦須與實作一致。上述均有局部修法，不要求重寫六章。
