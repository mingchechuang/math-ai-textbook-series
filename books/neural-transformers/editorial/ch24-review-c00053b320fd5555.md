### 1. PPL 例題

第一位置：

$$
\operatorname{LSE}([0,1,2,3])
=3+\ln(1+e^{-1}+e^{-2}+e^{-3})
\approx3.44019.
$$

第二、三位置 NLL 分別為 $\ln(1+3e^{-110})$ 與 $\ln(1+3e^{-101})$，都是極小正數。第四位置為 $\ln4\approx1.38629$。因此：

$$
\mathrm{MeanNLL}\approx1.20662,\qquad
\mathrm{PPL}\approx3.3422.
$$

PPL 手算與測試仍正確。

### 2. ECE 例題必須以四筆正確計算

表中高信心箱 ID 1–7 的 correctness 是：

$$
[1,0,1,1,0,1,0].
$$

共有四筆正確，不是三筆。高信心箱：

$$
\bar p_2=\frac57,\qquad
\mathrm{Acc}_2=\frac47.
$$

所以：

$$
|\mathrm{Acc}_2-\bar p_2|
=\left|\frac47-\frac57\right|
=\frac17,
$$

加權貢獻：

$$
\frac7{10}\cdot\frac17=0.10.
$$

低信心箱：

$$
\bar p_1=\frac{0.7}{3},\qquad
\mathrm{Acc}_1=0,
$$

加權貢獻：

$$
\frac3{10}\cdot\frac{0.7}{3}=0.07.
$$

因此正確 ECE 是：

$$
\mathrm{ECE}=0.10+0.07=0.17.
$$

本稿的例題正文及 `test_normal` 已改成 `.17`，這項修正是正確的。上一輪以 `.27` 核准是建立在錯誤重算上，本輪不能盲從該舊判定。

## 二、目前的直接阻擋錯誤

### 1. 測試與預期結果仍宣稱 ECE 是 0.27

**逐字原句：**

> `ECE` (bins [0, 0.5, 1.0]): 0.27 (約)

但例題目前寫：

> `ECE = ... = 0.17.`

程式也寫：

```python
assert np.isclose(compute_ece(p, c, [0, .5, 1])[0], .17)
```

**原因：**

同一組資料在同一章內出現兩個不同預期值。正確值是 $0.17$，因為高信心箱有四筆正確。這不是純文字風格問題，而是測試規格自相矛盾：

- 手算答案：$0.17$；
- 程式 assertion：$0.17$；
- 測試章預期輸出：$0.27$。

讀者無法判斷執行結果應符合哪一個規格。

**最小修法：**

把「測試與預期結果」中的：

> `ECE`: 0.27 (約)

改成：

> `ECE`: 0.17 (約)

並全文搜尋舊值 `0.27`，確認沒有其他殘留。這是本輪唯一必然改變正式驗收結果的直接數值錯誤。

## 三、其他數學與程式核對

### 1. ECE 命題

本稿對 $q_b=0$ 的處理正確：

$$
\mathrm{ECE}_{\mathrm{true,binned}}
=\sum_{b:q_b>0}q_b|\delta_b|.
$$

零機率箱不需要定義條件期望；其樣本箱計數幾乎處處為零。對 $q_b>0$ 且 $N_b=n>0$ 的箱，Jensen 推導成立：

$$
E[|X_b|\mid N_b=n]\geq|\delta_b|.
$$

利用 $E[N_b]=Nq_b$ 可得：

$$
E[Y_b]\geq q_b|\delta_b|.
$$

證明方向正確。將 $Y_b$ 改寫成正式分段公式仍會更清楚，但現有散文已明確規定空箱貢獻為零，不構成新的阻擋錯誤。

### 2. PPL overflow

目前政策為：

```python
if mean_nll > np.log(np.finfo(float).max):
    return np.inf, float(mean_nll)
```

這使呼叫端可以保留有限 Mean NLL，同時知道 PPL 超出 `float64` 範圍。對 `[1000,0]`、label 1，Mean NLL 約為 $1000$，預期回傳 `inf`；新增邊界測試與介面一致。

### 3. ID/OOD 閾值

新增 assertions 與資料吻合：

- validation selected point：接受一筆、錯誤零筆、coverage $0.5$、risk $0$；
- ID selected point：接受兩筆、錯誤零筆、coverage $2/3$、risk $0$；
- OOD selected point：接受一筆、錯誤一筆、coverage $1/3$、risk $1$。

這些是從固定 logits 靜態可重算的預期值，不是虛構實測。

### 4. Classwise ECE

習題答案已加入：

- 正常案例；
- $N=0$；
- $C=0$；
- row sum 非一；
- label 越界；
- NaN probability。

函式 shape 正確：

- `probs`：$(N,C)$；
- `labels`：$(N,)$；
- 每類 confidence：$(N,)$；
- 每類 correctness：$(N,)$；
- macro ECE：對類別 ECE 作 mean。

測試明示未執行，符合證據契約。

## 四、shape、broadcast、mask 與 reduction

PPL 路徑的 shape 為：

- logits：$(N,L,V)$；
- labels：$(N,L)$；
- valid mask：$(N,L)$；
- log-softmax 沿 $V$ 軸；
- gather 結果：$(N,L)$；
- NLL 只在有效 token 上求和；
- 最後只除一次有效 token 數。

`safe_labels` 避免 padding 標籤 `-1` 被 NumPy 解釋成最後一類索引。無效位置即使不進入 loss，也仍要求 logits 有限，政策明確。

ECE 沿事件軸聚合；group-level ECE 沒有被平均成 split-level ECE。PPL 也沒有平均 group PPL。Risk–coverage 使用相同 shape 的 confidence/correctness 布林 reduction。沒有發現新的 broadcast 或 reduction 錯誤。

本章不涉及反向傳播，沒有梯度需要檢查；也沒有 cache、position 或 attention mask，不應因缺少不相關測試退稿。

## 六、概率、loss 與 OOD 解讀

PPL 使用：

$$
\exp\left(\frac{\text{有效 token 總 NLL}}
{\text{有效 token 數}}\right),
$$

符合核心契約。程式不先算 softmax 再任意加 epsilon 取 log，也不平均不同長度樣本的 PPL。

OOD 段已將過強結論修正為：

> 「模型與告警群的 token 分布匹配較差；是否屬於語義泛化失敗，仍須控制詞彙、模板、長度、tokenizer、上下文與標註規則。」

這符合 PPL 能直接支持的範圍。正文也沒有由 token confidence 推論整段答案的事實正確性或安全性。

手設表格仍未列 calibration event count，但正文已明言 token、calibration event、decision count 不可混用，程式結果也分別記錄 `tokens`、`events`、`decisions`。此處建議補表，但不是本輪數值正確性的主要阻擋項。

## 七、非阻擋但建議同步修正

### 1. 穩定 log-softmax 的輸入契約

**原句：**

```python
Input: logits (N, L, V)
```

函式本身沒有 `np.asarray` 或三維檢查。可選擇：

- 明確只接受三維 ndarray；
- 或改成接受任意至少一維 array-like，沿最後軸計算。

這屬介面精煉，`compute_global_ppl` 呼叫前已轉成三維 ndarray，因此目前主流程不受影響。

### 2. Selective Risk 公式

正文公式的求和索引與 indicator 重複，但數值正確。用

$$
a_i(\tau)=\mathbb I(s_i\geq\tau)
$$

改寫會更容易和程式對照，但不影響現有結果。

### 3. 測試標題

「Logits 溢位」實際測的是極端有限 logits 下的穩定 log-softmax，以及 PPL 指數化超出浮點範圍。建議拆成兩項，避免概念混淆。

### 4. 小結措辭

「揭示模型在分布偏移下的脆弱性」可弱化成「量化模型在指定合成偏移下的表現差異」，以免把單一小資料結果一般化。
