# 一、先行重算與已正確部分

## 1. one-hot CE 與 NLL

對 one-hot 標籤 $y_i$，只有正確類別 $c_i$ 的分量為 1：

$$
-\sum_{c=1}^Cy_{ic}\ln q_{ic}
=-\ln q_{i,c_i}.
$$

稿中推導正確。若某個 $q_{i,c_i}=0$，結果為 $+\infty$；其他類別即使 $q=0$，因其標籤權重為 0，也不貢獻 CE。程式用布林索引避免 $0\cdot(-\infty)$，方向正確。

## 2. 例題 4.3

有效 NLL 為

$$
2.0+0.5+0.5=3.0,
$$

有效 token 數為 3，所以

$$
\overline L=1.0,\qquad PP=e^1\approx2.71828.
$$

兩個 batch 的 perplexity 算術平均約為

$$
\frac{e^2+e^{0.5}}2
\approx\frac{7.38906+1.64872}{2}
\approx4.51889.
$$

稿中 $4.519$ 正確，也確實構成不能平均 batch perplexity 的反例。

## 3. 整合習題

有效 NLL：

$$
1.0+0.5+2.0=3.5.
$$

有效 token 數為 3，因此

$$
\overline L_{\rm nats}=\frac{3.5}{3}=1.166666\ldots
$$

轉換為 bits：

$$
\frac{1.166666\ldots}{\ln2}\approx1.68315.
$$

困惑度：

$$
e^{7/6}\approx3.21127.
$$

稿中數值可接受。

## 4. KL 證明

目前證明正確使用

$$
\sum_{x\in S}Q(x)\leq1
$$

而不是錯誤地直接寫成 1，等號條件也完整。此部分已通過，不應再沿用早先版本的批評。

# 二、必須修正的數學錯誤

## 1. 自回歸鏈式法則不需要馬可夫性，也不等於所寫的條件獨立

**原句：**

> `此時樣本並非無條件獨立，而是馬可夫性質下的條件獨立。`

**問題：**

$$
p(x_{1:T})=\prod_{t=1}^Tp(x_t\mid x_{<t})
$$

是任何聯合分布都具有的機率鏈式法則，不需要馬可夫假設。這裡條件包含完整歷史 $x_{<t}$，並沒有聲明只依賴固定長度的近期狀態。一般 decoder-only Transformer 正是可以依賴整個可見上下文，不應稱為馬可夫性質下的條件獨立。

若要引入一階馬可夫假設，才會進一步簡化為

$$
p(x_t\mid x_{<t})=p(x_t\mid x_{t-1}),
$$

但本章沒有這個假設。

**最小修法：**

把原句改為：

> 此分解來自機率鏈式法則，不要求各 token 無條件獨立，也不額外假設固定階數的馬可夫性。模型以先前 token 作為條件預測下一個 token。

## 2. 序列 Total NLL 公式漏掉負號

**原句：**

> `$$\text{Total NLL}(\theta)=-\sum_{i=1}^N\ln p_\theta(x_i)\quad\text{(或}\sum_{t=1}^T\ln p_\theta(x_t|x_{<t})\text{)}$$`

**問題：**

括號中的序列版本是正的 log-likelihood，不是負對數似然。正確的序列 Total NLL 應為

$$
-\sum_{t=1}^T\ln p_\theta(x_t\mid x_{<t}).
$$

這會直接影響後續「最小化 NLL」的方向，屬於必修符號錯誤。

**最小修法：**

在序列和式前補上負號。最好拆成兩行，避免括號造成誤讀。

## 3. 最小化 Total NLL 與 Mean NLL 等價需要分母固定

**原句：**

> `最小化 Total NLL 或 Mean NLL 均等價於最大化似然（MLE）。`

**問題：**

當 $N_{\text{valid}}$ 是固定、正且不依賴 $\theta$ 的常數時，總和與平均只差正比例常數，極小點才相同。若資料選擇、拒答或 mask 取決於模型參數，分母可能改變，不能直接宣稱等價。

**最小修法：**

補成：

> 在有效集合預先固定且 $N_{\text{valid}}>0$ 時，Total NLL 與 Mean NLL 只差固定正比例常數，因此具有相同的最優參數。

## 4. 線性損失的梯度理由不正確

**原句：**

> `線性差值（如 $1-p$）在優化上存在問題：當 $p$ 接近 1 時，梯度變得很小，模型無法有效地區分「非常確定」與「完全確定」。`

**問題：**

若直接對 $p$ 微分，

$$
\frac{d(1-p)}{dp}=-1,
$$

梯度並不在 $p\to1$ 時變小。若 $p$ 由 sigmoid／softmax logits 產生，才會因機率映射的導數而出現不同梯度行為；但交叉熵對正確類別 logit 的梯度在 $p\to1$ 時同樣趨近 0，因此原句也不能用來區分兩者。

**最小修法：**

刪除「梯度變得很小」的理由，改成：

> 線性差值不具有對數似然的乘積轉加總性，也不像 $-\ln p$ 那樣對把真實事件賦予接近零機率的預測給予無界懲罰。

# 三、定義域仍可更精確

## 1. CE 的零機率規則沒有在總結中明列

**原句：**

> `若 $P(x)>0$ 且 $Q(x)=0$，則 $D_{KL}(P\|Q)=+\infty$。`

**問題：**

同一條件下交叉熵 $H(P,Q)$ 也為 $+\infty$。目前前面的「擴展實數約定」可間接推得，但本章核心要求明確處理 CE 與 KL 的域，最好直接寫出。

**最小修法：**

增加：

> 若 $P(x)>0$ 且 $Q(x)=0$，則該交叉熵項 $-P(x)\ln Q(x)=+\infty$，故 $H(P,Q)=+\infty$。

## 2. 「擴展實數系」列出 $-\infty$ 沒有必要且可能誤導

**原句：**

> `我們採用擴展實數系 $\mathbb{R}\cup\{+\infty,-\infty\}$。`

**問題：**

對合法離散概率而言，熵、CE、KL 與 NLL 的結果都在 $[0,+\infty]$，最終指標不應是 $-\infty$。$\ln0=-\infty$ 只是在中間運算出現。

**最小修法：**

改成「允許指標取擴展非負實數 $[0,+\infty]$；計算中約定 $\ln0=-\infty$」。

## 3. 困惑度的「隨機猜測」仍應限縮到均勻特例

**原句：**

> `若 $PP=100$，表示模型在平均意義上的預測困難度相當於在 100 個候選中隨機猜測。`

**問題：**

前一句已正確說只有均勻分布時才可精確解釋為候選數，後一句又容易被讀成一般等價。一般情況下 PP 是正確 token 幾何平均機率的倒數，不代表每一步真的在 100 個類別間均勻猜測。

**最小修法：**

改成：

> $PP=100$ 表示有效 token 的正確類別機率之幾何平均為 $1/100$；只有均勻候選的特殊模型中，才等同於每步在 100 個候選間均勻猜測。

# 四、程式介面與故障測試

## 1. `cross_entropy` 對 Python list 標籤會失敗

**原句：**

```python
if y_true.ndim == 1:
```

而轉換只發生在分支內：

```python
y_idx = np.asarray(y_true)
```

**問題：**

若使用者呼叫：

```python
cross_entropy([1, 0, 1], y_pred)
```

Python list 沒有 `.ndim`，函數會先拋出 `AttributeError`，根本到不了 `np.asarray`。這與 `_as_float_array` 所宣示的通用陣列介面不一致。

**最小修法：**

在判斷維度前先做：

```python
y_raw = np.asarray(y_true)
if y_raw.ndim == 1:
    y_idx = y_raw
else:
    y_true = _as_float_array(y_raw, "y_true")
```

並增加 list index labels 的故障／正常測試。

## 2. 概率上界仍接受略大於 1 的值

**原句：**

```python
if np.any(p > 1.0 + 1e-12):
```

**問題：**

例如一類分布 `[1.0000000000005]` 的值大於 1，但小於 $1+10^{-12}$；其總和誤差也小於 $10^{-9}$，因此會被接受。概率分量的合法域是 $[0,1]$，不應把大於 1 的值當成合法概率。浮點容差適合用於總和檢查，不適合重新定義單項域。

**最小修法：**

使用：

```python
if np.any(p > 1.0):
    raise ValueError(...)
```

與已改成精確拒絕負值的規則保持對稱。

## 3. `_as_float_array` 對複數輸入可能產生警告並丟失虛部

**原句：**

```python
if not np.issubdtype(a.dtype, np.number):
    ...
return a.astype(np.float64)
```

**問題：**

複數 dtype 屬於 `np.number`，因此可能被接受，再轉成 `float64` 丟棄虛部。概率與 NLL 不應接受複數。

**最小修法：**

明確拒絕複數：

```python
if not np.issubdtype(a.dtype, np.number) or np.iscomplexobj(a):
    raise TypeError(...)
```

## 4. Perplexity 的 overflow 閾值任意截短可表示範圍

**原句：**

```python
if mean_nll > 700: # ln(float_max) approx 709
    return np.inf
```

**問題：**

`float64` 在約 $709.78$ 前仍可表示有限的 `exp`。把 701 到 709 間的值提前回傳 `inf`，與本章「精確性」契約不一致。

**最小修法：**

使用 dtype 對應的界限：

```python
limit = np.log(np.finfo(np.float64).max)
if mean_nll > limit:
    return np.inf
```

此外，大量有限 NLL 在 `np.sum` 時也可能先 overflow。若要完整處理，可在和式非有限時依策略回傳 `inf`；至少應檢查 `sum_nll`。

## 5. 故障測試捕捉範圍過寬，可能把錯誤原因誤認為成功

**原句：**

```python
try:
    validate_probability(...)
    assert False, ...
except ValueError:
    pass
```

**核對：**

此例中的 `assert False` 產生 `AssertionError`，不會被 `except ValueError` 吃掉，所以基本邏輯可用。但它只檢查「某個 ValueError」，沒有核對錯誤來自預期條件。更清楚的做法是設旗標或寫小型 `expect_raises`。

這不是拒稿主因，但建議增加以下測試：

- `cross_entropy([1,0,1], y_pred)`；
- 錯誤 label batch 長度；
- `y_pred` 一維與三維；
- NaN；
- 空有效 mask；
- soft label；
- $p>1$ 的小幅越界；
- 複數輸入；
- 被 mask 的 PAD 位置含 NaN 時採何策略。

## 6. 測試輸出措辭可以保留

**原句：**

> `執行時應輸出 "All expected tests passed."`

這是預期結果，不是「已執行並通過」的宣稱，符合證據契約。程式中的 `print("... passed.")` 只有在使用者實際執行且前置 assert 沒失敗時才會出現，也不構成作者虛構執行。
