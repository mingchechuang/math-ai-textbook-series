## 一、重新核算

本次未執行程式，僅依公式與 NumPy 語義重算。

### 1. 例題 PPL

$$
\operatorname{LSE}([0,1,2,3])
=3+\ln(1+e^{-1}+e^{-2}+e^{-3})
\approx3.44019.
$$

另兩個極高信心位置的 NLL 分別為：

$$
\ln(1+3e^{-110}),\qquad \ln(1+3e^{-101}),
$$

皆為極小正數。加上均勻 logits 的 $\ln4$，得到：

$$
\mathrm{MeanNLL}\approx1.20662,
\qquad
\mathrm{PPL}\approx3.3422.
$$

手算與 `test_normal` 的容差設定相容。

### 2. ECE

低箱貢獻：

$$
\frac3{10}\left|0-\frac{0.7}{3}\right|=0.07.
$$

高箱貢獻：

$$
\frac7{10}\left|\frac37-\frac57\right|=0.20.
$$

總 ECE 為 $0.27$，正確。

### 3. 小型確定性資料

OOD routine 的 NLL 約為：

$$
\ln(1+e^{-1})\approx0.3133.
$$

OOD alert 的 NLL 約為：

$$
\ln(1+e^2)\approx2.1269.
$$

因此告警組總 NLL 高於常規組，對應 assertion 預期成立。Risk 非單調反例 `[.6,.9]`、correctness `[1,0]` 在 $\tau=0$ 時 risk 為 $1/2$，在 $\tau=.8$ 時 risk 為 $1$，也正確。

## 二、仍須修正的核心問題

### 1. 程式沒有產生整體 ID 與 OOD 指標

**原句：**

```python
for split in ("id", "ood"):
    for group in ("routine", "alert"):
        ...
        result[split, group] = {...}
```

**原因：**

目前只有四個 group-level 結果：

- ID/routine；
- ID/alert；
- OOD/routine；
- OOD/alert。

指定 lab 要求「保留集與合成偏移集比較、分群結果」。分群已部分完成，但整體 ID 與整體 OOD 並未由程式計算。測試只核對：

```python
result["ood", "alert"]["total_nll"] >
result["ood", "routine"]["total_nll"]
```

這是 OOD 內部兩群比較，不是 ID 對 OOD 比較。

**最小修法：**

在 `synthetic_eval` 中另建 `result[split, "all"]`。必須把該 split 所有事件重新聚合：

$$
\mathrm{MeanNLL}_{s}
=
\frac{\sum_g\mathrm{TotalNLL}_{s,g}}
{\sum_g\mathrm{Tokens}_{s,g}},
$$

再取指數。ECE 與 R-Curve 必須串接原始 confidence/correctness 後重算，不能平均群組 ECE 或群組 risk。新增 assertion 比較 ID/OOD 整體結果。

### 2. source 洩漏檢查實際上沒有測試跨窗口來源

**原句：**

```python
assert len({r[0] for r in records}) == len(records)
```

並稱：

> 「每個 source_id 僅屬一個 split。」

**原因：**

這個 assertion 要求所有 source ID 完全不重複。真實窗口資料中，同一 source 文件通常產生多個窗口；需要檢查的是同一 source 的所有窗口是否只落在一個 split。把每筆資料都設成不同 source，只是避開問題，沒有測試「重疊窗口不得跨集合」。

`time` 欄位也只被儲存，沒有參與切分或排序驗證。

**最小修法：**

讓同一 source 出現至少兩筆不同時間的記錄，確認它們同屬一個 split。另建立故障案例，使同一 source 同時屬於 ID 與 OOD，預期驗證函式拋出 `ValueError`。不要用 Python `assert` 當外部資料驗證，因為最佳化模式可停用 assert；應使用明確檢查及例外。

---

### 3. 沒有 validation split 的端到端閾值流程

**原句：**

```python
assert select_threshold(np.array([.8, .6]), np.array([1, 0]),
                        [0, .8, 1], .5) == .8
```

**原因：**

此測試能核對 `select_threshold` 的局部邏輯，但兩筆資料沒有被納入資料契約中的 validation split。章稿尚未示範：

1. 只在 validation 選 $\tau$；
2. 固定該 $\tau$；
3. 套用到 ID test；
4. 套用到 OOD test；
5. test 不回饋選擇。

這是本章資料洩漏核心，不應只由參數名稱 `val_confidence` 暗示。

**最小修法：**

加入 validation records，或建立明確命名的 validation 資料。用它選出 $\tau^\star$ 後，再以同一閾值評估 ID/OOD。若 validation 沒有可行候選，應報告不可達，不得改用 test 尋找閾值。

### 4. ECE 證明的空箱隨機變數仍未完整定義

**原句：**

> 「定義空箱的貢獻為零；非空箱的貢獻為 $\frac{N_b}{N}|X_b|$。」

後面卻寫：

$$
E\left[\frac{N_b}{N}|X_b|\right].
$$

**原因：**

$X_b=\mathrm{Acc}_b-\bar p_b$ 在 $N_b=0$ 時未定義，因此上述乘積還不是遍及整個樣本空間的隨機變數。文字意圖正確，但形式證明仍差一步。

**最小修法：**

定義：

$$
Y_b=
\begin{cases}
\frac{N_b}{N}|\mathrm{Acc}_b-\bar p_b|,&N_b>0,\\
0,&N_b=0.
\end{cases}
$$

然後證明：

$$
E[Y_b]\ge q_b|\delta_b|.
$$

最後使用 $\widehat{\mathrm{ECE}}=\sum_bY_b$。如此才是完整證明。

### 5. 小結仍將非負向上偏差寫成「正偏差」

**原句：**

命題標題已正確改為：

> 「有限樣本固定分箱 ECE 的非負向上偏差」

但小結仍寫：

> 「有限樣本下存在正偏差」

**原因：**

證明只有大於等於，未證明嚴格大於。小結與命題及章首契約不一致。

**最小修法：**

改成：

> 「在固定分箱及 i.i.d. 條件下，經驗 ECE 的期望不低於母體固定分箱 ECE。」

---

### 6. 「ECE 僅作為相對指標」仍不準確

**原句：**

> 「ECE 僅作為相對指標，用於比較同條件下的不同模型」

**原因：**

ECE 也能描述單一模型的分箱校準差距。反過來，即使資料和 bins 相同，不同模型的信心分布與箱占比不同，ECE 排序也不一定穩健。

**最小修法：**

改成：

> 「ECE 是依賴資料、樣本量及分箱規則的描述性估計量，可在相同評估程序下輔助比較，但不可單獨作為絕對品質或安全保證。」

小結中的「僅作為相對指標」也一併修改。

### 7. Selective Risk 公式與程式接口不一致

**原句：**

$$
R(\tau)=
\frac{\sum_{i:s_i\ge\tau}\mathbb I(\hat y_i\ne y_i)}
{\sum_{i:s_i\ge\tau}\mathbb I(s_i\ge\tau)}.
$$

**原因：**

受限求和中的每一筆已滿足 $s_i\ge\tau$，所以分母 indicator 永遠是一。程式則正確使用 `accepted` mask 對全部樣本做 reduction。公式雖數值正確，但冗餘且不利於 shape 對照。

**最小修法：**

定義：

$$
a_i(\tau)=\mathbb I(s_i\ge\tau),
$$

再寫：

$$
C(\tau)=\frac1N\sum_i a_i(\tau),
$$

$$
R(\tau)=
\frac{\sum_i a_i(\tau)\mathbb I(\hat y_i\ne y_i)}
{\sum_i a_i(\tau)}.
$$

### 8. `select_threshold` 的 tie-break 描述略微過強

**原句：**

> 「選擇較小的 $\tau$ 以保留較高 coverage」

**原因：**

較小閾值保證 coverage 不低，但若兩個 threshold 之間沒有任何 confidence，coverage 可能相同，未必嚴格較高。

**最小修法：**

改為「選擇較小的 $\tau$，以取得不低的 coverage」。

---

### 9. `synthetic_eval` 對 ECE 使用的第一個箱必然為空

**原句：**

```python
confidence = np.exp(np.max(lp, axis=-1))
ece, _ = compute_ece(confidence, correct, [0, 0.5, 1])
```

**原因：**

二分類最大 softmax probability 至少是 $0.5$，所以 $[0,0.5)$ 箱必空。程式沒有錯，但這個 synthetic lab 的 ECE 實際只使用一個非空箱，不能展示分箱局部校準。

**最小修法：**

改用 `[0, .75, 1]`，讓目前 confidence 有機會分散到不同箱；或明示此小資料第一箱必空，ECE 分箱正常性主要由例題 4.2 驗證。

### 10. 整體 PPL 的說明正確，但沒有對應程式測試

**原句：**

> 「若要取得整個集合的困惑度，須把各組的總損失與詞元數分別相加後才指數化。」

**原因：**

這是正確規則，但程式沒有實作，也沒有故障測試防止平均 group PPL。既然本章的核心陷阱就是錯誤平均 PPL，整合程式應直接測試。

**最小修法：**

新增 split-level 結果，並 assertion：

```python
split_ppl != np.mean(group_ppls)
```

可選擇 token 數不同的兩組，避免兩者偶然接近或相等。

### 11. `total_nll`、`ppl`、`ece` 的 scalar 型別不一致

**原句：**

```python
"tokens": int(np.sum(mask)),
"total_nll": mean_nll * mask.sum(),
"ppl": ppl,
"ece": ece,
```

**原因：**

後三者通常是 NumPy scalar，而 `tokens` 是 Python int。若後續輸出 JSON 或做嚴格 schema，可能失敗或出現不一致。

**最小修法：**

顯式使用：

```python
float(mean_nll * mask.sum())
float(ppl)
float(ece)
```

### 12. `compute_global_ppl` 的 array-like 政策仍不一致

```python
if logits.ndim != 3:
```

**原因：**

巢狀 list 可傳給 ECE，卻會使 PPL 在 `.ndim` 之前失敗。函式要嘛都只接受 ndarray，要嘛都先轉為 ndarray。

```python
logits = np.asarray(logits)
labels = np.asarray(labels)
valid_mask = np.asarray(valid_mask)
```

### 13. logits 的有限值政策未進入 docstring

**原句：**

```python
if not np.all(np.isfinite(logits)):
```

**原因：**

### 14. PPL overflow 仍由底層函式 `print`

**原句：**

```python
if not np.isfinite(perplexity):
    print(f"Warning: PPL overflow...")
```

**原因：**

底層函式直接列印有副作用，`np.exp` 也可能先發出 runtime warning。Mean NLL 即使很大仍可能是有效評估值，API 應有明確策略。

**最小修法：**

可回傳 `inf` 而不列印，文件中說明；或先檢查可表示範圍並拋 `OverflowError`。不要由核心函式直接輸出。

### 15. `compute_classwise_ece` 仍缺空維度防護及測試

**原句：**

```python
N, C = probs.shape
...
macro_ece = np.mean(eces)
```

**原因：**

$C=0$ 時 `eces` 為空並回傳 NaN；$N=0$ 時錯誤延遲到內層。新增的主程式測試也沒有呼叫 classwise ECE，因此程式題解答尚不完整。

**最小修法：**

```python
if N == 0 or C == 0:
```

並增加正常、空樣本、空類別、row sum 非一、label 越界測試。

## 三、shape、broadcast、mask、reduction 核對

PPL 核心 shape 正確：

- logits：$(N,L,V)$；
- labels/mask：$(N,L)$；
- advanced indexing 結果：$(N,L)$；
- log-softmax reduction：最後的 $V$ 軸；
- NLL reduction：有效 token 總和除有效 token 數一次。

`safe_labels` 能防止無效位置的 $-1$ 被 NumPy 解讀為最後一類；`np.where` 也不會用乘法讓無效位置污染總和。由於程式事前拒絕所有非有限 logits，mask 不豁免 padding 位置的 NaN，這項政策合理但須明示。

Risk–Coverage 中 confidence 與 correctness 同為 $(N,)$，threshold 逐值處理，沒有錯誤 broadcast。接受數為零回傳 NaN，也符合定義。

本章是評估章，不需要重複完整 Transformer 或訓練 loop；但整體 split 聚合、validation/test 閾值流程和來源洩漏故障測試仍屬本章評估 loop，不能省略。
