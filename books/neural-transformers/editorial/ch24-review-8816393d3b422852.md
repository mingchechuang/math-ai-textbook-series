## 三、仍須修正的阻擋項

### 1. PPL overflow 分支的註解與實際能力矛盾

**逐字原句：**

```python
# 明確拒絕不可表示的 PPL；mean_nll 仍可供呼叫端另行記錄。
if not np.isfinite(mean_nll) or mean_nll > np.log(np.finfo(float).max):
    raise OverflowError("PPL not representable; record mean NLL instead.")
```

**原因：**

函式一旦拋出 `OverflowError`，就不會回傳 `(perplexity, mean_nll)`。呼叫端不能從該函式取得區域變數 `mean_nll`，所以「mean_nll 仍可供呼叫端另行記錄」在目前介面下不成立。除非呼叫端重新計算，或從例外物件中取得數值，但程式沒有提供後者。

這屬於能力宣稱與實際 API 不一致。

**最小修法：**

三選一：

1. 把註解改為「呼叫端可改用另一個回傳 total NLL／count 的介面」，並實際提供該介面；
2. 允許回傳 `ppl=np.inf` 與有限 `mean_nll`；
3. 自訂例外並把 `mean_nll` 存入例外屬性。

最簡單的是回傳 `np.inf, mean_nll`，或刪除「仍可供呼叫端記錄」這句。

### 2. 新增的 `OverflowError` 沒有故障測試

**逐字原句：**

```python
if not np.isfinite(mean_nll) or mean_nll > np.log(np.finfo(float).max):
    raise OverflowError(...)
```

現有邊界測試卻是：

```python
z = np.array([[[1000., 0.]]])
compute_global_ppl(z, np.array([[0]]), ...)
```

**原因：**

真標籤為最高 logit 類別，NLL 接近零，因此不會觸發 PPL overflow。這只測到 log-softmax 減最大值的穩定性。

現有 helper 又只捕捉 `ValueError`：

```python
def expect_value_error(fn, *args):
```

故新增的 `OverflowError` 路徑完全沒有測試。

**最小修法：**

加入一般例外 helper：

```python
def expect_error(exc_type, fn, *args):
    try:
        fn(*args)
    except exc_type:
        return
    raise AssertionError("Expected exception")
```

並加入：

```python
expect_error(
    OverflowError,
    compute_global_ppl,
    np.array([[[1000., 0.]]]),
    np.array([[1]]),
    np.array([[True]])
)
```

此時真類別位於低 logit，Mean NLL 約為 $1000$，才能測到 PPL 不可表示分支。

### 5. `Y_b` 仍以散文而不是無歧義分段式定義

**逐字原句：**

> 「令箱貢獻 $Y_b$ 在 $N_b=0$ 時為 $0$，在 $N_b>0$ 時為 $\frac{N_b}{N}|X_b|$。」

**原因：**

本版對 $q_b=0$ 的處理已正確，散文定義也足以理解。但命題聲稱是完整證明，而 $X_b$ 只在 $N_b>0$ 時定義。正式分段式可徹底消除定義域歧義。

**最小修法：**

改為：

$$
Y_b=
\begin{cases}
\frac{N_b}{N}|\mathrm{Acc}_b-\bar p_b|,&N_b>0,\\
0,&N_b=0.
\end{cases}
$$

然後只在 $N_b=n>0$ 的條件下令 $X_b=\mathrm{Acc}_b-\bar p_b$。這是很小的文字修改，但可使證明完全閉合。

## 四、其餘應修但次要的問題

### 6. Selective Risk 公式仍有重複的求和限制

**逐字原句：**

$$
R(\tau)=
\frac{\sum_{i:s(x_i)\ge\tau}\mathbb I(\hat y_i\ne y_i)}
{\sum_{i:s(x_i)\ge\tau}\mathbb I(s(x_i)\ge\tau)}.
$$

**原因：**

求和索引已限制接受事件，分母 indicator 恆為一。公式數值正確，不是致命錯誤，但沒有與程式的 `accepted` mask 統一。

**最小修法：**

定義：

$$
a_i(\tau)=\mathbb I(s(x_i)\ge\tau),
$$

再寫：

$$
C(\tau)=\frac1N\sum_i a_i(\tau),
$$

$$
R(\tau)=
\frac{\sum_i a_i(\tau)\mathbb I(\hat y_i\ne y_i)}
{\sum_i a_i(\tau)}.
$$

### 9. OOD PPL 的語義結論仍過強

**逐字原句：**

> 「這表明模型對新異常模式缺乏泛化能力。」

**原因：**

高 PPL 直接表示模型給該群真實 token 較低概率，或與該 token 分布匹配較差。它不能單獨排除詞彙、模板、長度、tokenizer、上下文或標註規則差異。

**最小修法：**

改為：

> 「這表示模型與告警群的 token 分布匹配較差；是否屬於語義泛化失敗，仍須控制詞彙、模板、長度、tokenizer、上下文及標註規則。」

小結的：

> 「揭示模型在分布偏移下的脆弱性」

亦建議改成：

> 「量化模型在指定合成偏移下的表現差異。」

### 10. `compute_stable_log_softmax` 的 shape 契約不完整

**逐字原句：**

```

**原因：**

**最小修法：**

logits = np.asarray(logits, dtype=float)

    raise ValueError(...)
```

並把 docstring 改成沿最後軸計算；或者保留三維契約並明確要求 `ndim == 3`。
