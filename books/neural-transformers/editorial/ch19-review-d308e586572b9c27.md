新增程式：

```python
if (targets == self.PAD_ID).any():
    ...
    if violation.any():
```

以及：

```python
if torch.any(idx.eq(self.PAD_ID) & targets.ne(self.PAD_ID)):
    raise ValueError("PAD input positions must have PAD targets")
```

現在同時保證：

1. `idx` 的 PAD 只能是連續右側後綴；
2. `targets` 的 PAD 只能是連續右側後綴；

相符。歸納推理成立。

# 二、必須修正：attention 元素與張量 shape 混寫

## 逐字原句

> \(A_{ij} = \frac{\exp(S'_{ij})}{\sum_{k=0}^{T-1} \exp(S'_{ik})} \in \mathbb{R}^{B \times H \times T \times T}\)

\(A_{ij}\) 若表示固定 query、key 的單一權重，仍缺 batch 與 head 索引；若四個索引都固定，它是 scalar，不能寫成屬於四維張量空間。整體 \(A\) 才有 \((B,H,T,T)\) shape。

本卷要求每個 shape 與 reduction 軸精確，此處不能只視為簡寫。

## 最小修法

改成：

\[
A\in\mathbb R^{B\times H\times T\times T},
\]

且

\[
A_{b,h,i,j}
=
\frac{
\exp(S'_{b,h,i,j})
}{
\sum_{k=0}^{T-1}\exp(S'_{b,h,i,k})
}.
\]

並保留「softmax 沿最後的 key 軸 \(k\)」說明。

同理，前面的 score 分量若要完全一致，可寫：

\[
S'_{b,h,i,j}
=
\begin{cases}
\frac{Q_{b,h,i,:}\cdot K_{b,h,j,:}}{\sqrt{d_h}},&j\le i,\\
-\infty,&j>i.
\end{cases}
\]

# 三、必須修正：logits 的概率語義

## 逐字原句

> 「表示每個位置對詞彙表中每個詞元的未歸一化對數概率。」

logits 是未正規化實數分數。它們不必先被解釋成某個概率的對數。經 softmax 後才得到概率：

\[
p_v=\frac{e^{z_v}}{\sum_u e^{z_u}},
\]

經 log-softmax 後才得到：

\[
\log p_v=z_v-\log\sum_u e^{z_u}.
\]

## 最小修法

改成：

> 「Logits \(Z\in\mathbb R^{B\times T\times V}\) 是每個位置對各詞元的未正規化實數分數；沿詞彙軸套用 softmax 後得到條件機率。」

這也與後面的 `cross_entropy` 直接接收 logits 相符。

# 四、必須修正：`view` 不會靜默給出錯誤映射

## 逐字原句

> 「`.contiguous()` 不可省略，因為 `transpose` 後張量通常非連續，直接 `view` 會失敗或給出錯誤的記憶體映射」

在本程式的具體寫法中：

```python
out.transpose(1, 2).contiguous().view(...)
```

先 `.contiguous()` 是正確且清楚的。但 `view` 對不相容 stride 通常會拋錯，不應描述為可能靜默給出錯誤記憶體映射。另一方面，若改用 `reshape`，框架可在必要時複製，所以 `.contiguous()` 不是所有等價實作中都「不可省略」。

## 最小修法

改成：

> 「本程式後續使用 `view`，因此先呼叫 `.contiguous()`；transpose 後的 stride 通常與此 view 不相容，直接呼叫會拋錯。若改用 `reshape`，框架可在必要時建立副本。」

# 五、PAD embedding 梯度測試仍是假陽性

## 逐字原句

```python
x_grad = torch.randint(1, V, (2, 5))
```

接著：

```python
pad_grad = model.tok_emb.weight.grad[model.PAD_ID]
assert torch.all(pad_grad == 0)
```

`torch.randint(1,V,...)` 永遠不產生 PAD_ID 0，因此 PAD row 沒有被 embedding lookup 使用。即使完全刪除 `padding_idx=0`，未被索引的 row 梯度仍會是零。這項測試無法驗證作者聲稱的「PAD row 不由 lookup 更新」。

## 最小修法

使用真的包含 PAD，且符合新資料契約的資料：

```python
x_grad = torch.tensor([[1, 2, 0]], dtype=torch.long)
t_grad = torch.tensor([[2, 3, 0]], dtype=torch.long)
```

反向後驗證：

```python
assert torch.all(model.tok_emb.weight.grad[0] == 0)
assert torch.any(model.tok_emb.weight.grad[1] != 0)
```

第二項不可任意要求每個出現 token 都有非零梯度，但至少可選擇一個在固定非退化案例中應有梯度的 row。既有的 `.grad is not None`、shape 一致與 finite 檢查可保留。

另需在這個測試前呼叫：

```python
model.zero_grad(set_to_none=True)
```

以避免未來若前面測試加入 backward，梯度累積使測試意義改變。

# 七、因果測試仍可能把 token 改成 PAD

## 逐字原句

```python
x_mod[:, -1] = (x_mod[:, -1] + 1) % V
```

若最後 token 原本為 \(V-1\)，新值會是 0。它位於最右端，所以符合右側 padding 契約，但測試同時改變「詞元內容」與「是否為 PAD」兩件事。

## 最小修法

使修改後仍為非 PAD：

```python
x_mod[:, -1] = x_mod[:, -1] % (V - 1) + 1
```

對原值 \(1,\ldots,V-1\)，此式會得到另一個有效 token。

測試結果 `diff < 1e-5` 只能支援此實作在該案例下未洩漏未來，不能取代前面的歸納證明。稿中已有證明，只需補一句界定範圍。

# 九、習題仍掩蓋 transpose

## 逐字原句

> 「輸入 \(X\in\mathbb R^{1\times2\times4}\)」

此時 \(T=H=2\)，所以：

\[
(B,T,H,d_h)=(1,2,2,2),
\]

交換 T 與 H 後仍是：

\[
(B,H,T,d_h)=(1,2,2,2).

學生即使漏做 transpose，shape 字串也完全一樣，不能檢查本章最重視的軸順序。

改用 \(T=3\)：

- projection：\((1,3,4)\)
- reshape：\((1,3,2,2)\)
- transpose：\((1,2,3,2)\)
- scores：\((1,2,3,3)\)

並同步修改答案。這是教學測試設計問題，不影響模型程式本身，但修正成本很低。

# 十、反例敘述仍過強

## 逐字原句

> 「因果性測試將失敗。」

錯誤上三角 mask 確實允許未來依賴，但對任意隨機權重，未來路徑可能因投影為零、抵消或低於容差而沒有在單次測試中被觀察到。數學上應說「因果保證被破壞，存在反例」，而不是任意初始化都必然超過測試閾值。

## 最小修法

改成：

> 「上三角 mask 破壞因果保證；一般非退化權重下，該測試預期失敗。若要得到確定的故障測試，應固定一組使未來 value 對過去輸出具有非零貢獻的權重與輸入。」

## 另一原句

> 「Softmax 飽和，梯度不穩定。」

忘記縮放不保證必然飽和。最小修法是加入條件：

> 「在 Q/K 分量近似獨立、零均值且方差相近的常用近似下，未縮放 score 的方差隨 \(d_k\) 增長，可能使 softmax 過尖並使部分梯度變小或不穩定。」

# 十一、生成器及空 batch 邊界仍未驗證

## 逐字原句

```python
seq = torch.randint(1, vocab_size, (batch_size, seq_len + 1))
```

此函數要求：

- `vocab_size >= 2`
- `batch_size >= 1`
- `seq_len >= 1`

但入口沒有檢查。模型建構器只要求 `vocab_size>0`，所以模型可用 `vocab_size=1` 建構，但生成器會因空取樣範圍失敗。

## 最小修法

在生成器入口加入：

```python
if batch_size < 1 or seq_len < 1 or vocab_size < 2:
    raise ValueError(...)
```

forward 也沒有拒絕 \(B=0\)。若空 batch 不在支援範圍，應加入：

```python
if b < 1:
    raise ValueError("Batch size must be >= 1")
```

並提供故障測試。
