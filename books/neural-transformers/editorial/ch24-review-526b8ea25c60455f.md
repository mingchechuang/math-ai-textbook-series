## 三、仍須修正的阻擋問題

### 1. ECE 命題沒有處理 $q_b=0$ 時條件期望未定義

**原句：**

$$
\mathrm{ECE}_{\mathrm{true,binned}}
=\sum_{b=1}^Bq_b\left|E[A-S\mid S\in I_b]\right|
$$

並定義：

$$
\delta_b=E[A-S\mid S\in I_b].
$$

**原因：**

若某箱的母體機率 $q_b=P(S\in I_b)=0$，條件事件機率為零，通常不能直接定義該條件期望。不能僅因前面處理了樣本空箱 $N_b=0$，就認為母體零機率箱也已處理。這是兩個不同問題：

- $N_b=0$：有限樣本中沒有觀測落箱；
- $q_b=0$：母體本身永遠不落箱。

目前公式對 $q_b=0$ 的箱包含未定義量 $0\cdot|\delta_b|$。

**最小修法：**

只對 $q_b>0$ 的箱定義 $\delta_b$，並把母體 ECE 寫成：

$$
\mathrm{ECE}_{\mathrm{true,binned}}
=\sum_{b:q_b>0}q_b|\delta_b|.
$$

對 $q_b=0$ 的箱直接規定母體貢獻為零。證明中也分成：

- 若 $q_b=0$，則 $N_b=0$ 幾乎處處，故 $E[Y_b]=0$；
- 若 $q_b>0$，才使用條件分布及 Jensen 不等式。

否則命題仍有定義域缺口。

---

### 2. 空箱貢獻仍只用散文描述，沒有正式 piecewise 定義

**原句：**

> 「令箱貢獻 $Y_b$ 在 $N_b=0$ 時為 $0$，在 $N_b>0$ 時為 $\frac{N_b}{N}|X_b|$。」

**原因：**

推導方向已正確，但命題要求完整證明。由於 $X_b$ 本身只在 $N_b>0$ 時定義，最好不要在同一句中把它當作全樣本空間上的隨機變數。

**最小修法：**

明列：

$$
Y_b=
\begin{cases}
\frac{N_b}{N}|\mathrm{Acc}_b-\bar p_b|,&N_b>0,\\
0,&N_b=0.
\end{cases}
$$

之後直接對 $Y_b$ 取期望，不必宣稱空箱中的 $X_b$ 有定義。

### 3. Selective Risk 公式仍有重複限制，未按程式 reduction 書寫

**原句：**

$$
R(\tau)=
\frac{\sum_{i:s(x_i)\ge\tau}\mathbb I(\hat y_i\ne y_i)}
{\sum_{i:s(x_i)\ge\tau}\mathbb I(s(x_i)\ge\tau)}.
$$

**原因：**

求和範圍已限制 $s(x_i)\ge\tau$，分母中的 indicator 必為一。雖然結果等於接受數，但不利於核對程式中的 `accepted` mask，也沒有統一表示 numerator 與 denominator 的 reduction 範圍。

**最小修法：**

定義：

$$
a_i(\tau)=\mathbb I(s(x_i)\ge\tau),
$$

並改為：

$$
C(\tau)=\frac1N\sum_{i=1}^Na_i(\tau),
$$

$$
R(\tau)=
\frac{\sum_{i=1}^Na_i(\tau)\mathbb I(\hat y_i\ne y_i)}
{\sum_{i=1}^Na_i(\tau)}.
$$

分母為零時仍按現有政策定義為未定義。

### 4. 新增的 `OverflowError` 沒有故障測試

**原句：**

```python
if not np.isfinite(mean_nll) or mean_nll > np.log(np.finfo(float).max):
    raise OverflowError("PPL not representable; record mean NLL instead.")
```

**原因：**

這是新增的重要失敗政策，但現有 helper 只捕捉 `ValueError`：

```python
def expect_value_error(fn, *args):
```

而 `[1000,0]`、label 0 的邊界測試產生接近零的 NLL，只測穩定 softmax，不會觸發 PPL overflow。

**最小修法：**

加入一般化 helper：

```python
def expect_error(exc_type, fn, *args):
```

再以真標籤位於低 logit 的例子測試，例如 logits `[1000,0]`、label 1，此時 NLL 約為 $1000$，預期拋出 `OverflowError`。

同時把測試章的「Logits 溢位」改稱「極端有限 logits」，避免把穩定 softmax 與 PPL 指數化 overflow 混為一談。

### 5. `compute_classwise_ece` 已修正空維度，但仍完全沒有測試

**原句：**

```python
if N == 0 or C == 0:
    raise ValueError("N and C must be positive.")
```

**原因：**

函式本身現在的主要 shape 與 reduction 已合理：

- `probs` 為 $(N,C)$；
- 每類 confidence 為 $(N,)$；
- correctness 為 $(N,)$；
- macro ECE 沿類別軸平均。

但新增分支沒有正常、邊界或故障測試。四類習題要求完整解答；只附函式而不核對正常值、row sum、label 越界及空維度，仍不完整。

**最小修法：**

在答案後附至少以下預期測試：

```python
eces, macro = compute_classwise_ece(
    [[.8, .2], [.3, .7]], [0, 1], [0, .5, 1])
assert len(eces) == 2
assert np.isclose(macro, np.mean(eces))
```

以及：

- `(0,2)` 空樣本；
- `(2,0)` 空類別；
- row sum 非一；
- label 越界；
- NaN probability。

不必宣稱已執行。

### 6. validation 選擇過程仍未保存於結果

**原句：**

```python
validation = evaluate(...)
tau = select_threshold(...)
...
return result
```

**原因：**

沒有 test 洩漏，這點正確；但 `result` 不包含 validation curve、coverage target 或候選 thresholds。呼叫端只能看到 test row 中的 `.8`，不能從結果物件稽核閾值選擇。

**最小修法：**

加入：

```python
validation["curve"] = risk_coverage(
    validation["confidence"], validation["correctness"], [0, .8, 1])
result["validation", "all"] = validation
result["selection"] = {
    "thresholds": [0, .8, 1],
    "target_coverage": .5,
    "selected_tau": tau,
}
```

這只是保存 validation 證據，不會讓 test 參與選擇。

### 8. `check_sources` 仍沒有防止重複 `(source,time)` 資料

**原句：**

```python
for source, time, split, group, logits, label in records:
    if source in owners and owners[source] != split:
        raise ValueError("Source crosses splits.")
```

**原因：**

跨 split 洩漏已正確拒絕，但同一來源、同一時間的記錄可以重複出現，造成 PPL、ECE 及 risk 重複計權。函式也不拒絕未知 split/group。既然資料契約明列來源、時間與群組，至少應保證記錄鍵唯一。

**最小修法：**

加入：

```python
seen = set()
key = (source, time)
if key in seen:
    raise ValueError("Duplicate source-time record.")
seen.add(key)
```

並限制 split 至 `{"valid","id","ood"}`、group 至 `{"routine","alert"}`。補一個重複 source-time 故障案例。

### 9. OOD 表格仍混用 token 數與 calibration event 數

**原句：**

| Total Tokens | 1000 | 1000 |
| ECE (5 bins) | 0.05 | 0.20 |

**原因：**

ECE 的分母是校準事件數，不必等於有效 token 數；selective risk 的分母又是接受決策數。表格目前只有 token 數，無法判斷 ECE 是在多少事件上估計。後文雖說決策數應另列，但表格仍未實作這項要求。

**最小修法：**

新增：

- Valid token count；
- Calibration event count；
- Decision count；
- Accepted count at selected $\tau$。

若 ECE 恰以每個有效 token 為事件，也必須明確說明兩者在此手設案例中相等，而不是默認相等。

**原因：**

## 四、非阻擋但建議同步修正

1. `compute_stable_log_softmax` 的 docstring 宣稱輸入為 $(N,L,V)$，函式本身卻不檢查三維；可改成接受任意至少一維張量並沿末軸計算，或明確驗證三維。
2. `risk_coverage` 允許未排序及重複 thresholds。若輸出稱為 curve，應要求嚴格遞增，或明說保留輸入順序。
3. `expect_value_error` 只檢查例外類型，任何非預期 `ValueError` 都會被誤認為成功。建議至少檢查訊息片段。
4. 正文預期訊息 `"Label out of bounds."` 與實際 `"Label out of bounds for valid tokens."` 不一致。
5. 小結「OOD 評估揭示模型在分布偏移下的脆弱性」可稍弱化為「量化在指定合成偏移下的表現差異」，避免有限合成資料被概括成普遍脆弱性。

## 五、總結判定

本輪已修好 array-like PPL 入口、PPL overflow 政策、ECE 定位、classwise 空維度及整合題答案，核心 PPL/ECE/OOD 聚合沒有發現新的 reduction 錯誤。程式未虛構執行，亦沒有把 token confidence 當成回答安全信心。

但 ECE 命題仍在 $q_b=0$ 時使用未定義的條件期望；新增的 classwise ECE 與 `OverflowError` 均沒有相應測試；validation 選擇證據及固定閾值的 ID/OOD risk 尚未被整合測試核對。另有表格分母、來源重複資料防線、OOD 解讀及引用狀態需修正。這些涉及完整證明、故障測試與評估可追溯性，仍不能核准。
