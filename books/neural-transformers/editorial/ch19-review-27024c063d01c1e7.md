# 一、模型與 shape 核對

輸入索引為：

\[
X\in\mathbb Z^{B\times T}.
\]

token embedding 輸出：

\[
E[X]\in\mathbb R^{B\times T\times D}.
\]

position embedding 切片：

\[
P_{0:T}\in\mathbb R^{1\times T\times D},
\]

與 token embedding 相加時只沿 batch 軸廣播，結果仍為：

\[
H_0\in\mathbb R^{B\times T\times D}.
\]

Q、K、V 線性投影均保持 \((B,T,D)\)。因 \(D=Hd_h\)，拆頭依次為：

\[
(B,T,D)\rightarrow(B,T,H,d_h)\rightarrow(B,H,T,d_h).
\]

scores 為：

\[
QK^T\in\mathbb R^{B\times H\times T\times T}.
\]

因果 mask 是 \((T,T)\)，正確廣播到 batch 與 head 軸。softmax 使用 `dim=-1`，即最後的 key 軸。與 V 相乘後：

\[
AV\in\mathbb R^{B\times H\times T\times d_h}.
\]

合頭流程：

\[
(B,H,T,d_h)\rightarrow(B,T,H,d_h)\rightarrow(B,T,D).
\]

最後 logits 為：

\[
Z\in\mathbb R^{B\times T\times V}.
\]

shape、transpose、broadcast 與 reduction 均正確。

# 二、`view`／`reshape` 說明已修正

本輪原句為：

> 「直接 `view` 通常會因 stride 與所求 shape 不相容而拋錯；若改用 `reshape`，框架可在必要時建立副本」

此說法正確。程式使用：

```python
out = out.transpose(1, 2).contiguous().view(b, t, self.d_model)
```

因為它選擇 `view`，所以 transpose 後先呼叫 `.contiguous()` 是合理且清楚的寫法。正文也正確區分：

- reshape／view：拆分或合併軸，不代表交換軸；
- transpose：交換軸；
- reshape：必要時可以複製；
- view：受 stride 相容性限制。

前次事實錯誤已消除。

# 三、因果遮罩與證明

程式使用：

```python
mask = torch.tril(torch.ones((t, t), device=x.device)).bool()
scores = scores.masked_fill(~mask, float('-inf'))
attn_weights = torch.softmax(scores, dim=-1)
```

本卷約定 True=允許，因此：

\[
M_{ij}=\mathrm{True}\iff j\le i.
\]

不允許的位置在 softmax 前設為 \(-\infty\)，符合遮罩契約。方形 causal self-attention 每列至少允許對角位置，所以核心實作不會產生全遮罩 query 列。

多層因果性證明亦與程式一致。第 \(l\) 層位置 \(i\) 的 attention 只使用 \(j\le i\) 的 K/V；`LN1`、`LN2` 與 FFN 均只沿 feature 軸逐位置運算；殘差也只合併同一時間位置。因此由層數歸納可得：

\[
Z_i=F_i(X_0,\ldots,X_i),
\]

不依賴 \(X_{i+1},\ldots,X_{T-1}\)。證明完整，不以有限測試取代一般性論證。

# 四、loss 與概率核對

程式使用：

```python
valid_mask = targets.ne(self.PAD_ID)
valid_count = valid_mask.sum().item()
```

以及：

```python
ce_loss_sum = nn.functional.cross_entropy(
    logits.reshape(-1, self.vocab_size),
    targets.reshape(-1),
    ignore_index=self.PAD_ID,
    reduction='sum'
)
loss = ce_loss_sum / valid_count
```

因此實際目標為：

\[
\mathcal L=
\frac{
\sum_{b,t:Y_{b,t}\ne PAD}
-\log p(Y_{b,t}\mid X_{b,0:t})
}{
\sum_{b,t}\mathbf1[Y_{b,t}\ne PAD]
}.
\]

核對結果：

- target PAD 不進入分子；
- 分母只計有效 target；
- 沒有二次平均；
- flatten 後 logits 是 \((BT,V)\)，target 是 \((BT)\)；
- logits 直接交給 cross-entropy，沒有先 softmax 再 log；
- 全 PAD target 在除法前拋錯。

loss 定義與程式一致。

合成資料由同一 `seq` 產生：

```python
x = seq[:, :-1]
targets = seq[:, 1:]
```

因此 target 正確錯一位，沒有把輸入與目標獨立抽樣。

# 五、padding 契約

本章選擇右側連續 padding，而不是一般 key padding mask。對有效前綴後接 PAD 後綴的序列，任何有效 query 都位於 PAD 之前；causal mask 使其不能看到右側 PAD，因此在此受限契約下可不另加 key padding mask。

程式分別檢查 input 與 target 的右側 padding，並保留指定錯誤訊息：

- `"PAD tokens must be at the right side of the sequence."`
- `"Target PAD tokens must be at the right side."`
- `"PAD input positions must have PAD targets"`
- `"No valid tokens in targets (all PAD?)"`

條件：

```python
idx.eq(PAD_ID) & targets.ne(PAD_ID)
```

實作的是：

\[
X_{b,t}=PAD\Longrightarrow Y_{b,t}=PAD,
\]

而不是錯誤的雙向等價。因此正常的序列結束：

\[
X=[1,2,3],\qquad Y=[2,3,PAD]
\]

合法。

測試目前涵蓋：

- 合法右側 input／target padding；
- 合法最後 target 為 PAD；
- input 內部 PAD；
- target 內部 PAD；
- PAD input 對應有效 target；
- 全 PAD target。

範圍足以滿足本章正常、邊界與故障測試要求。

# 六、PAD embedding 梯度測試已真正修復

本輪新增：

```python
model.zero_grad(set_to_none=True)
emb = model.tok_emb(torch.tensor([[0, 1]], dtype=torch.long))
emb.sum().backward()
assert torch.all(model.tok_emb.weight.grad[model.PAD_ID] == 0)
assert torch.any(model.tok_emb.weight.grad[1] != 0)
```

此測試具有故障鑑別力。

對標量：

\[
s=\sum_k E_{0,k}+\sum_k E_{1,k},
\]

若是普通 embedding，row 0 與 row 1 都應直接收到全一梯度；設定 `padding_idx=0` 後，lookup 的 backward 會抑制 row 0 的累積，但 row 1 仍應有非零梯度。

因此：

- 若移除 `padding_idx=0`，第一個 assertion 預期失敗；
- 若錯誤地切斷所有 embedding 梯度，第二個 assertion 預期失敗；
- 正確實作才同時滿足兩者。

probe 後又執行：

```python
model.zero_grad(set_to_none=True)
```

所以 probe 梯度不會污染後續端到端 language-model loss 測試。前次假陽性問題已消除。

後續代表性梯度測試亦核對梯度存在、shape 與參數一致且有限，涵蓋 embedding、Q/K/V、attention output、FFN 與 logits projection。這是合理的整合冒煙測試；它沒有聲稱是所有參數的有限差分證明。

# 十、非阻擋的後續改善

以下可在排版或後續修訂時改善，但不影響本輪核准。

1. 因果測試目前使用：

   ```python
   (x_mod[:, -1] + 1) % V
   ```

   有機會將 \(V-1\) 改成 PAD。這不會破壞因果測試的有效性：無論未來位置改成哪一個合法 token，過去輸出都不應變；而 PAD 位於最右側，也符合資料契約。不過若要純化測試，可改成：

   ```python
   x_mod[:, -1] = x_mod[:, -1] % (V - 1) + 1
   ```

2. shape 習題採 \(T=H=2\)，reshape 前後的數字相同，教學鑑別力較弱。可改用 \(T=3,H=2\)，但目前答案本身沒有數學錯誤。

3. 生成器可額外拒絕 `batch_size<1`、`seq_len<1`、`vocab_size<2`；目前主程式傳入的參數合法，且章內已有多種故障測試，因此這是健全性增強，不是現有正常路徑的 correctness 缺陷。

4. 「上三角 mask 將使測試失敗」與「未縮放會使 softmax 飽和」最好改成「一般非退化情況下預期失敗」及「可能使 softmax 過尖」。這是措辭精確化，不影響模型、證明或程式。

5. 「測試與預期結果」可把梯度測試說明由只提 `out.weight`，同步更新為代表性 embedding、Q/K/V、attention output、FFN 與 logits projection，並另列 PAD embedding probe。

以上均不再構成實質拒稿理由。
