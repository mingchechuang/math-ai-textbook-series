## 審稿結論

本輪已修正第21章 RNG state 的快照方式，亦擴充第23章對不同未來位置的因果性測試。這兩項修正有效。不過第21章的文字仍與新程式、更新後的 checkpoint 狀態定義不一致；第24章的 classwise ECE 也仍與正文的 ECE 定義混用。以下列出尚需的最小修正。

### 1. 第21章仍把 checkpoint 恢復條件寫成 RNG state 物件相同

**原句：**

> 「預期 `恢復後 dropout 遮罩一致` 為 `True`，前提是保存與恢復的是同一個 `bit_generator.state` 物件內容。」

**原因：**  
程式已改為 `copy.deepcopy(rng.bit_generator.state)`，恢復時也另行複製；正確條件應是「保存和恢復同一個 RNG 狀態值」，不要求同一物件。現有敘述反而把讀者帶回已修正的引用問題。

**最小修法：**  
改為「前提是 checkpoint 保存了抽樣前的 RNG 狀態快照，並在恢復時正確還原該狀態」。

### 2. 第21章小結仍將舊的有限欄位清單稱為完整狀態

**原句：**

> 「以步驟、參數、優化器狀態、RNG 狀態、資料游標組成的完整狀態」

**原因：**  
更新後的命題21.2已將狀態擴充為 $S_t=(\theta_t,u_t,r_t,c_t,t,d_t)$，並說明 $d_t$ 包含或可重建資料內容、切分、生成規則及模型與優化器設定；但小結仍列舊清單且稱為「完整狀態」。此外，程式中的 checkpoint 函式明言未涵蓋資料與設定版本，不能直接支撐小結的無條件表述。

**最小修法：**  
小結沿用命題21.2的條件式說法，列明狀態還須固定資料、切分、設定與批次順序；並註明程式函式僅示範部分欄位，不是完整可恢復 checkpoint。

### 3. 第24章 Classwise ECE 習題解答仍未與正文的 ECE 定義分開

**原句：**

> 「修改 `compute_ece` 以支持多類別 ECE（Classwise ECE）。」

以及解答：

> `correctness_c = (labels == c).astype(int)`  
> `conf_c = probs[:, c]`  
> `ece_c, _ = compute_ece(conf_c, correctness_c, bin_edges)`

**原因：**  
正文定義的 ECE 使用 top-label confidence $p_{\max}$，並以 argmax 是否命中作為正確性；解答計算的是每一類的 one-vs-rest ECE，使用 $p_c$ 與 $y_i=c$。這兩種指標可以各自成立，但定義與解讀不同，不能只說「修改 compute_ece」而不區分。解答目前也沒有手算預期值，正常測試只核對宏平均等於本身平均，無法確認類別計算正確。

**最小修法：**  
明確區分 top-label ECE 與 one-vs-rest classwise ECE；替 classwise 例子提供可核算的逐類結果及宏平均預期值。

### 4. 第23章測試敘述沒有同步到新增的中間位置因果測試

**原句：**

> 「另一項因果邊界是只改最後一個詞元，預期更早位置的 logits 不變」

**原因：**  
程式已新增逐一改動中間位置 $j$、檢查所有 $i<j$ logits 不變的測試；正文仍只描述改最後一個 token，低估了實際測試範圍，也使測試文件與程式不一致。

**最小修法：**  
改述為「逐一改動各位置 token，檢查其前方 logits 不變」，並說明最後位置測試是其中一例。

## 已確認的修正

第21章 RNG state 現在以深拷貝保存並恢復，消除了前輪指出的狀態別名問題。第23章已增加對中間未來位置的因果性檢查，且故障測試名稱改為描述 cache 長度與 `start` 不一致，較符合實際檢查內容。第24章 ECE 手算修正為 $0.17$，與表格及測試資料的分箱加權一致。
