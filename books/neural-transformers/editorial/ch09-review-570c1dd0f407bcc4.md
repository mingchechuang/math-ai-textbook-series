## 一、核心模型與梯度目前正確

現有輸入、參數與中間量 shape 為：

- $X:(B,D_{in})$
- $W_1:(D_{in},D_{hid})$
- $b_1:(D_{hid},)$
- $Z_1,H:(B,D_{hid})$
- $W_2:(D_{hid},1)$
- $b_2:(1,)$
- $Z_2,Y_{\mathrm{pred}},Y_{\mathrm{true}}:(B,1)$

標籤由：

> `Y_train = (X_train[:, [0]] > 0).astype(np.float64)`

建立，因此保留 $(B,1)$，沒有錯誤廣播。

對 batch mean logits BCE：

$$
L=\frac{1}{B}\sum_{i=1}^{B}
\left[\operatorname{logaddexp}(0,z_i)-y_i z_i\right],
$$

有：

$$
dZ_2=\frac{\sigma(Z_2)-Y_{\mathrm{true}}}{B},
$$

$$
dW_2=H^TdZ_2,\qquad db_2=\sum_{i=1}^BdZ_{2,i},
$$

$$
dZ_1=(dZ_2W_2^T)\odot(1-H^2),
$$

$$
dW_1=X^TdZ_1,\qquad db_1=\sum_{i=1}^BdZ_{1,i}.
$$

程式中的矩陣乘法、轉置與 reduction 軸符合這些公式。平均只在 $dZ_2$ 除一次 $B$，後續偏置梯度沿 batch 軸求和，亦正確。

分支式 sigmoid：

- $z\ge0$ 時計算 $1/(1+e^{-z})$；
- $z<0$ 時計算 $e^z/(1+e^z)$；

沒有裁切原始 logits，因此與 logits BCE 的導數完全對應。這部分已可保留。

## 二、有限差分與方向導數目前大致一致

### 1. 逐項差分的狀態恢復已修正

**逐字程式：**

```python
finally:
    param[idx] = original_value
    self.forward(self.X, self.Y_true)
    self.backward()
```

這能在正常與例外路徑恢復原參數並重建 cache，符合正文契約。

### 2. 全部參數確實被迭代

`params` 包含 $W_1,b_1,W_2,b_2$，並使用 `np.nditer(..., multi_index)` 檢查每個元素，符合「全部參數有限差分」要求。

### 3. 尺度化誤差已統一

本輪已正確使用：

```python
scaled_err = abs_err / max(1.0, abs(num_grad), abs(ana_grad))
```

並統一到 `max_scaled_err`、輸出名稱及回傳值。正文也說明小梯度時此量等於絕對誤差，語義一致。

### 4. 方向導數現在自足

方法會：

1. 對傳入的 $X,Y$ 執行 forward/backward；
2. 依固定順序展平梯度；
3. 計算 $\nabla L(\theta)^Tv$；
4. 計算正負方向的中心差分；
5. 在 `finally` 中還原 $\theta$ 並重建 cache。

這已修復舊稿使用外部舊梯度的問題。

## 三、仍缺少真正的可執行故障測試

章規要求正常、邊界、故障測試。現稿已有正常檢查和多個邊界斷言，但故障測試仍只是說明。

**逐字原句：**

> 「正確的故障測試：例如漏掉 `1 - H**2`，即 `dZ1 = dH`。」

這要求讀者手動修改正式實作，不是自足測試。主程式沒有故障版 backward，也沒有任何斷言證明梯度檢查會拒絕它。

**逐字原句：**

> 「`max_rel_err` 將遠大於 $10^{-5}$。」

這裡又回到已淘汰的 `max_rel_err` 名稱；目前程式使用的是 `max_scaled_err`。此外，「遠大於」沒有執行證據或普遍保證。如果 $H$ 接近零，則 $1-H^2$ 接近 1，漏掉 tanh 導數可能只產生很小差異。

**最小修法：**

加入測試專用錯誤梯度函數，而不是改壞正式 `backward`。例如：

- 正常 forward 保持不變；
- 故障解析梯度把 `dZ1 = dH`；
- 使用固定參數與固定資料，使 $|H|$ 明顯偏離零；
- 將故障梯度與同一份數值梯度比較；
- 斷言至少一項 `scaled_err >= tol`。

沒有執行紀錄時，正文只能說「預期故障斷言成立」，不能宣稱誤差實際遠大於多少。

這是目前最直接的章規缺口。

本輪新增：

這已比舊稿的 100 筆一般訓練更接近 tiny-set overfit check，且使用獨立模型、只取訓練資料、門檻失敗即中止，方向正確。

仍有三點需要修正。

### 1. 沒有保證 tiny set 含兩類

前八筆隨機樣本大概率包含兩類，但不同 seed 不構成類別平衡的邏輯保證。若 tiny set 全屬同一類，模型仍可能快速降低 loss，但測試覆蓋較弱。

**最小修法：**

直接建立固定、顯式包含正負第一特徵的 tiny set，或斷言 `np.unique(Y_tiny).size == 2`。

### 2. 門檻只檢查 loss 比例

只檢查降到初始 loss 的一半，未必足以稱為「過擬合小資料」。例如初始 loss 約 $0.7$，降到 $0.34$ 仍可能有錯分。

**最小修法：**

同時檢查 tiny-set accuracy，或把正文改成「小資料擬合除錯」而不是聲稱已過擬合。門檻仍只能標為預期，除非有外部執行紀錄。

### 3. 2000 步門檻未經執行

稿件正確地沒有列實測數值，但程式中的固定 2000 步與 0.5 比例仍是未驗證設計。這本身可接受，只需在測試說明中明確列為預期，而不能暗示已通過。

## 五、邊界測試已有進步，但尚有缺口

已加入的可執行測試包括：

- pack/unpack 往返；
- 過短、過長及含 NaN 的參數向量；
- `(B,)` 標籤；
- 空 batch；
- 非二元標籤；
- NaN 輸入；
- feature 維度錯誤；
- $B=1$ 輸出 shape；
- $z=\pm100$ 的 loss 與 bias 梯度。

這些均為有效改善。

### 1. 缺少非法 $h$、`tol`、方向 $v$ 的測試

雖然函數已拒絕這些值，但主程式沒有斷言：

- $h=0$、$h<0$、NaN；
- `tol <= 0`；
- $v=0$；
- $v$ 長度錯誤；
- $v$ 含非有限值。

**最小修法：**

用同樣的 `try/except/else` 模式補上。

### 2. 缺少非有限模型參數測試

`unpack_params` 拒絕非有限向量，但使用者仍可直接寫：

```python
model.W1[0, 0] = np.nan
```

forward 最終可能由 `Z2` 有限性檢查捕捉，但應至少有故障測試確認拒絕策略。更好的做法是在 forward 開頭統一檢查四組參數有限。

### 3. 邊界 loss 斷言重複計算

程式：

```python
assert np.isfinite(edge.loss()) and np.isclose(edge.loss(), 100.0)
```

會呼叫兩次 `edge.loss()`。這不是正確性錯誤，但可先保存 `edge_loss`，使故障訊息更容易定位。

## 七、建構器仍可因非法維度失敗

**逐字程式：**

```python
self.W1 = self.rng.normal(
    0, np.sqrt(1.0/dim_in), (dim_in, dim_hid)
)
```

沒有先驗證：

- `dim_in` 是正整數；
- `dim_hid` 是正整數；
- 兩者不是布林值。

`dim_in=0` 會除以零；負值或非整數會在其他位置產生不清楚的錯誤。

**最小修法：**

在建構器最前面拒絕非法維度，例如要求 `isinstance(dim_in, (int, np.integer))` 且 `dim_in > 0`，`dim_hid` 同理；若要排除布林值需另行判斷，因 Python 的 `bool` 是 `int` 子類。

### 更新後未確認參數有限

`train_one_step` 已檢查學習率為有限正數，這是改善；但極大有限學習率仍可能讓更新後參數溢位。

**最小修法：**

更新後檢查 $W_1,b_1,W_2,b_2$ 全部有限。更穩妥的是先算候選新參數，確認有限後再提交，避免模型停留在污染狀態。

## 八、習題仍不符合「完整解答」

### 1. 第一題仍是欠定問題

**題目原句：**

> 「給定 $B=2,D_{in}=2,D_{hid}=2$，計算 $dW_2$ 和 $db_2$。」

只有維度，無法得到唯一數值。解答自行加入 $X,W_1,b_1,W_2,b_2,Y_{\mathrm{true}}$。

**最小修法：**

把解答使用的所有輸入、參數及標籤移入題目，或把題目改成要求推導 shape 與一般公式。

### 2. 第三題條件仍錯置

**題目原句：**

> 「當 $Y=1$ 且 $W_2$ 極大時，梯度可能趨近 0」

$W_2$ 極大不保證 $z$ 為大正值。若 $z\to-\infty$ 且真標籤為 1：

$$
\sigma(z)-1\to-1,
$$

梯度不趨零。

**最小修法：**

改成「真標籤 $y=1$ 且 logit $z\to+\infty$」。

**解答原句：**

> 「梯度檢查會通過」

這也過度肯定。當梯度極小時，中心差分可能受取消誤差支配，反而變得不敏感。應改成「解析與真導數都趨近零，但數值核對是否穩定仍取決於步長與尺度」。

### 3. 第四題仍留有 `...`

**逐字原句：**

> `dZ1 = ...`

本卷明定程式不得留 `pass／TODO／omitted`；這裡以省略號取代關鍵計算，不是完整解答。

**最小修法：**

給出完整的 $B=1$ 程式：

- forward/backward；
- 明確重算 `dZ2,dH,dZ1`；
- `np.sum(dZ1, axis=0)`；
- shape 與 `np.allclose` 斷言。

## 十、框架與來源陳述仍需修正

**逐字原句：**

> 「框架不會報錯，但模型將永遠無法收斂」

一般自動微分框架會從前向圖產生梯度，非法 shape 通常會報錯。可能靜默存在的是合法但語義錯誤的廣播、reduction、資料 shape 或自訂 backward。「永遠無法收斂」亦無證據。

**最小修法：**

改為：

> 自動微分能計算既有計算圖的梯度，但不保證資料 shape、模型語義、reduction 或自訂 backward 正確。

參考來源中的：

> 「PyTorch Documentation on Numerical Stability」

沒有精確標題、版本或網址，且本章不使用 PyTorch；應刪除或提供可定位條目。NumPy 文件既標示未逐條核對，就不能暗示程式已由來源驗證。
