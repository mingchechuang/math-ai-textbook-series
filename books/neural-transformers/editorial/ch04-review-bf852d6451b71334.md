$$
-\ln0.9\approx0.1053605,\qquad-\ln0.6\approx0.5108256.
$$

因此：

$$
\text{Total NLL}
=2(0.1053605)+0.5108256

$$

$$
\text{Mean NLL}
=0.7215466/3
\approx0.2405155\text{ nats}.

轉成 bits：

$$
0.2405155/\ln2\approx0.34699\text{ bits}.
$$

稿中的 $0.72155$、$0.24052$、$0.3470$ 均正確。

## 2. 例題 4.3

有效 token 的 NLL 為 $2.0,0.5,0.5$，所以：

錯誤的 batch perplexity 平均為：

稿中 $4.519$ 與 $2.718$ 正確，反例有效。

D_{\mathrm{KL}}(P\parallel Q)

答案正確。

稿中結果均在合理四捨五入範圍內。

# 二、KL 命題的域與證明尚未完全相符

## 1. 命題宣稱的範圍過大

**原句：**

> `本章定義限於有限或可數離散樣本空間 $\mathcal{X}$。`

以及：

> `命題 4.1：對於任意兩個概率分布 $P,Q$，若 $P(x)>0\implies Q(x)>0$，則 $D_{KL}(P\|Q)\geq0$`

**問題：**

隨後的證明直接對可數和套用 Jensen：

$$
-\sum_{x\in S}P(x)\ln\frac{Q(x)}{P(x)}
\geq-\ln\sum_{x\in S}Q(x).
$$

在有限 $S$ 上這是完整證明。在可數無限 $S$ 上，還需要說明隨機變數、期望或負部／正部的可積性，或透過截斷集合再取極限。僅有 $P(x)>0\Rightarrow Q(x)>0$ 不保證 KL 有限；所有 $Q(x)$ 都為正時，KL 仍可能是 $+\infty$。結論本身可在擴展實數意義下成立，但目前證明沒有處理無限和極限。

本章規約要求「完整證明一個小命題」，不能把有限情形的證明直接宣稱涵蓋全部可數情形。

**最小修法：**

最簡單的修法是把命題明確限於有限 $\mathcal X$：

> 對有限離散樣本空間上的概率分布 $P,Q$……

前文仍可保留可數離散定義，但說明本章只證明有限情形；可數情形需額外極限論證，列為延伸結果。這不影響本章 NumPy 程式，因程式本來就只處理有限類別軸。

另一選項是補完整截斷證明，但沒有必要為本章增加測度論負擔。

## 2. `H(P,Q)-H(P)` 的使用條件應再明示一次

**原句：**

> `若 $H(P)=+\infty$……則 KL 散度定義可能涉及 $\infty-\infty$ 的不定式，本章不處理此種病態情況。`

這個警告方向正確。但習題 2 仍直接使用：

> `由恆等式 $H(P,Q)=H(P)+D_{KL}(P\|Q)$。`

**問題：**

若前文仍宣稱涵蓋可數無限空間，該習題需要限定在 $H(P)<\infty$ 且恆等式有定義的情形；否則不能對 $\infty-\infty$ 作普通代數移項。

**最小修法：**

在習題 2 題目與答案增加「假設 $\mathcal X$ 有限」即可，與命題的最小修法一致。

# 三、零機率與 CE 的域仍應補明

## 1. 支撐集規則只明列 KL，沒有明列 CE

**原句：**

> `若 $P(x)>0$ 且 $Q(x)=0$，則 $D_{KL}(P\|Q)=+\infty$。`

**問題：**

相同條件也直接導致：

$$
H(P,Q)=-\sum_xP(x)\ln Q(x)=+\infty.
$$

本章核心明列交叉熵與支撐集，因此不宜只在程式中表現，定義區也應直接寫出。

**最小修法：**

將規則 2 改成：

> 若 $P(x)>0$ 且 $Q(x)=0$，則該交叉熵項為 $+\infty$，所以 $H(P,Q)=+\infty$，且 $D_{\mathrm{KL}}(P\parallel Q)=+\infty$。

## 2. 擴展實數的寫法比實際需要更寬

**原句：**

> `我們採用擴展實數系 $\mathbb{R}\cup\{+\infty,-\infty\}$。`

**問題：**

合法離散概率下，本章討論的熵、CE、KL、NLL 最終值均落在 $[0,+\infty]$。$-\infty$ 是 $\ln0$ 的中間值，不是合法損失的最終值。現在的寫法容易讓讀者以為 NLL 或 KL 可以是 $-\infty$。

**最小修法：**

改成：

> 本章允許熵、CE、KL 與 NLL 取擴展非負實數 $[0,+\infty]$；中間計算約定 $\ln0=-\infty$。

## 3. 第二條零項約定措辭不夠精確

**原句：**

> `$P(x)\ln(0)$ 定義為 $0$（若 $P(x)=0$）。`

**問題：**

這是針對 $0\ln0$ 的特定極限約定，不是一般把任意 `P(x) * ln(0)` 設為零。雖然括號已限制 $P(x)=0$，但和第一條重複且可能混淆 CE 的正權重零預測情形。

**最小修法：**

合併成一條：

> 對任何 $a\geq0$，零權重項約定為 $0\ln a=0$；特別地 $0\ln0=0$。若權重 $P(x)>0$ 而 $Q(x)=0$，則 $-P(x)\ln Q(x)=+\infty$。

# 四、Perplexity 實作仍改變有限數學結果

## 1. 任意使用 700 作 overflow 閾值

**原句：**

```python
if mean_nll > 700: # ln(float_max) approx 709
    return np.inf
```

**問題：**

`float64` 的最大有限值對應對數約為 $709.78$，所以例如 `mean_nll=701` 的 `exp` 仍是極大但有限的浮點數。程式卻提前回傳 `inf`。本章強調「精確性」及不以任意閾值改寫數學定義，這與前述原則不一致。

**最小修法：**

使用實際 dtype 上限：

```python
limit = np.log(np.finfo(np.float64).max)
if mean_nll > limit:
    return np.inf
```

或使用：

```python
with np.errstate(over="ignore"):
    return float(np.exp(mean_nll))
```

並明示超出 `float64` 可表示範圍時回傳 `inf` 是數值表示策略，不是數學上的 perplexity 必然無限。

## 2. `sum_nll` 可能在除法前先 overflow

**原句：**

```python
sum_nll = np.sum(valid_nll)
mean_nll = sum_nll / count
```

**問題：**

即使每個 NLL 都是有限值，大量極大有限值求和仍可能得到 `inf`。此時 `mean_nll` 變成 `inf`，目前會因 `mean_nll > 700` 回傳 `inf`，但沒有區分「數學平均有限、浮點求和 overflow」與「數學值超出指數表示範圍」。

對一般教材小資料問題不大，但本章特別把數值穩定性列為核心契約，應明示這個限制。

**最小修法：**

至少加：

```python
sum_nll = np.sum(valid_nll, dtype=np.float64)
if not np.isfinite(sum_nll):
    return np.inf
```

更穩健可直接用 `np.mean(valid_nll, dtype=np.float64)`，但極端長陣列仍有浮點限制，文字中不應承諾任意規模都精確。

## 3. PP 的「100 個候選中隨機猜測」仍過強

**原句：**

> `若 $PP=100$，表示模型在平均意義上的預測困難度相當於在 100 個候選中隨機猜測。`

**問題：**

前一句已說只有均勻分布特例才精確，後一句又近似恢復了一般性解讀。一般情況下：

$$
PP
=\exp\left(-\frac1N\sum_t\ln p_t\right)
=\left(\prod_tp_t\right)^{-1/N},
$$

即正確 token 機率幾何平均的倒數。它不表示每一步真的在 100 個候選間均勻猜測。

**最小修法：**

將後句改成：

> $PP=100$ 表示正確 token 機率的幾何平均為 $1/100$；只有每步均勻分布在同樣數量候選上的特殊情形，才可解讀為 100 個等可能候選。

# 五、批次 KL 解答仍會先執行除以零

**原句：**

```python
p_support = p > 0
bad = np.any(p_support & (q == 0), axis=-1)
terms = np.zeros_like(p, dtype=np.float64)
terms[p_support] = p[p_support] * np.log(p[p_support] / q[p_support])
out = np.sum(terms, axis=-1)
out[bad] = np.inf
```

**問題：**

第二筆例子中存在 $p>0,q=0$。雖然 `bad` 已正確找出違規列，但下一行仍包含：

```python
p[p_support] / q[p_support]
```

因此會實際執行正數除以零，再取 `log(inf)`。結果最後被設成 `inf`，數值答案碰巧正確，但可能產生 divide-by-zero warning。本章在 CE 中刻意使用 mask 避免非法中間運算，批次 KL 也應採同一契約。

**最小修法：**

只計算有限支撐交集：

```python
safe = (p > 0) & (q > 0)
terms = np.zeros_like(p, dtype=np.float64)
terms[safe] = p[safe] * (
    np.log(p[safe]) - np.log(q[safe])
)
out = np.sum(terms, axis=-1)
out[bad] = np.inf
```

主函數 `kl_divergence` 已在發現支撐集違規後立即 `return np.inf`，沒有這個問題；只需修批次習題答案。
