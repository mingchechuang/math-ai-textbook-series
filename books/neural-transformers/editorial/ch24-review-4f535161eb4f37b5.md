\overline{\mathrm{NLL}}\approx1.20662,

$$

$$
\mathrm{NLL}=\ln(e^2+1)-0\approx2.1269.

result["ood", "alert"]["total_nll"] >

## 二、必須修正的問題

### 1. `synthetic_eval` 只計算分群，沒有計算整個 ID/OOD split

**原句：**

```python
for split in ("id", "ood"):
    for group in ("routine", "alert"):
        ...
        result[split, group] = {...}
```

**原因：**

指定 lab 要求「保留集與合成偏移集比較、分群結果」。目前函式只得到四個 `(split, group)` 結果，沒有：

- ID 整體總 NLL／token 數／PPL；
- OOD 整體總 NLL／token 數／PPL；
- ID 整體 ECE；
- OOD 整體 ECE；
- ID/OOD 整體 R-Curve；
- ID 與 OOD 的程式比較 assertion。

正文雖正確說明應將各組總 NLL 和 token 數相加，但程式沒有實作這個 reduction。指定 lab 不能只靠文字補充。

**最小修法：**

新增 split-level 聚合。PPL 必須用：

$$
\mathrm{PPL}_{s}
=
\exp\left(
\frac{\sum_g\mathrm{TotalNLL}_{s,g}}
{\sum_g\mathrm{Tokens}_{s,g}}
\right).
$$

ECE 與 R-Curve 則應串接該 split 的全部 calibration events／decisions 後重新計算，不能平均 group ECE 或 group risk。測試至少核對 ID 與 OOD 的整體 token 數及預期排序。

### 2. `total_nll` 沒有明確轉為 Python float

**原句：**

```python
"total_nll": mean_nll * mask.sum(),
```

**原因：**

結果通常是 NumPy scalar。這在目前字典內可用，但若後續序列化或做嚴格型別契約，可能與 Python `float` 不同。其他欄位如 `tokens`、`events` 已顯式轉型，介面不一致。

**最小修法：**

改成：

```python
"total_nll": float(mean_nll * mask.sum())
```

同樣可將 `ppl`、`ece` 明確轉成 Python float，使結果結構一致。

### 3. source 洩漏 assertion 沒有測到真正要防的情況

**原句：**

```python
assert len({r[0] for r in records}) == len(records)
```

並聲稱：

> 「每個 source_id 僅屬一個 split。」

**原因：**

這個 assertion 只要求每筆 record 的 source ID 完全不重複。真實建窗情境中，同一 source 應有多個窗口；真正要檢查的是同一 source 的所有窗口只能落入同一 split。把 source ID 全部設成唯一，反而繞過了重疊窗口及同來源跨集合的故障模式。

此外，records 中的第二欄時間沒有被任何切分或檢查使用。

**最小修法：**

讓至少一個 source 產生兩個窗口，然後建立：

```python
source_to_splits = {}
```

檢查每個 source 對應的 split 集合大小等於一。另加入一個故障資料，其中同一 source 同時出現在 ID 與 OOD，預期檢查函式拒絕。這才是資料洩漏故障測試。

### 4. 合成資料沒有 validation split，無法示範「驗證集選閾值」

**原句：**

```python
select_threshold(np.array([.8, .6]), np.array([1, 0]),
                 [0, .8, 1], .5)
```

**原因：**

函式名稱及參數聲稱是 validation，但這兩筆資料不是 `synthetic_eval` 資料契約中的 validation split，只是孤立陣列。程式也沒有示範：

1. 在 validation 上選 $\tau$；
2. 固定 $\tau$；
3. 套到 ID-test；
4. 套到 OOD-test。

因此測試雖驗證了 argmin 邏輯，仍沒有完成資料洩漏契約下的整合流程。

**最小修法：**

在 records 中加入 `validation` split，或另建具名 validation 常數資料；只對該資料呼叫 `select_threshold`。再使用回傳的固定 $\tau$ 評估 ID/OOD，不得分別為 ID/OOD test 重選閾值。

### 5. ECE 命題的空箱隨機變數仍未完全形式化

**原句：**

> 「定義空箱的貢獻為零；非空箱的貢獻為 $\frac{N_b}{N}|X_b|$。」

後面仍寫：

$$
E\left[\frac{N_b}{N}|X_b|\right].
$$

**原因：**

$X_b=\mathrm{Acc}_b-\bar p_b$ 在 $N_b=0$ 時未定義，所以乘積尚未被定義為一個遍及整個樣本空間的隨機變數。章稿文字已說明空箱貢獻為零，但公式應與文字一致。

**最小修法：**

明確定義：

$$
Y_b=
\begin{cases}
\frac{N_b}{N}|\mathrm{Acc}_b-\bar p_b|,&N_b>0,\\
0,&N_b=0.
\end{cases}
$$

然後證明 $E[Y_b]\ge q_b|\delta_b|$，最後寫 $\widehat{\mathrm{ECE}}=\sum_bY_b$。這是完成證明所需的最小形式化。

---

### 6. ECE 小結仍與命題標題矛盾

**原句：**

命題已改成：

> 「有限樣本固定分箱 ECE 的非負向上偏差」

但小結仍寫：

> 「有限樣本下存在正偏差」

**原因：**

證明只得到大於等於，不保證嚴格大於。核心契約已正確寫成「不保證嚴格大於」，小結又退回較強主張。

**最小修法：**

小結改成：

> 「在固定分箱及 i.i.d. 條件下，經驗 ECE 的期望不低於母體固定分箱 ECE。」

---

### 7. 「ECE 僅作為相對指標」仍不準確

**原句：**

> 「ECE 僅作為相對指標，用於比較同條件下的不同模型」

**原因：**

ECE 也能描述單一模型的分箱校準差距，不只是相對指標。另一方面，相同 bins 下不同模型的信心分布及箱占比不同，ECE 排序也不必穩定。

**最小修法：**

改為：

> 「ECE 是依賴資料、樣本量與分箱規則的描述性估計量，可在相同評估程序下輔助比較，但不能單獨作為絕對品質或安全保證。」

---

### 8. Selective Risk 公式仍重複限制條件

**原句：**

$$
R(\tau)=
\frac{\sum_{i:s_i\ge\tau}\mathbb I(\hat y_i\ne y_i)}
{\sum_{i:s_i\ge\tau}\mathbb I(s_i\ge\tau)}.
$$

**原因：**

分母中的 indicator 在受限求和內永遠為一。程式已用 `accepted` mask 清楚實作，數學公式應與程式契約一致。

**最小修法：**

定義 $a_i(\tau)=\mathbb I(s_i\ge\tau)$，寫成：

$$
C(\tau)=\frac1N\sum_i a_i(\tau),
$$

$$
R(\tau)=
\frac{\sum_i a_i(\tau)\mathbb I(\hat y_i\ne y_i)}
{\sum_i a_i(\tau)}.
$$

### 9. `select_threshold` 的 tie-breaking 說明與「較高 coverage」不是完全等價

**原句：**

> 「同 risk 選較小閾值」

正文解釋：

> 「例如選擇較小的 $\tau$ 以保留較高 coverage」

**原因：**

較小閾值保證 coverage 不低，但不保證嚴格較高；如果兩閾值之間沒有任何 confidence，coverage 會相同。這是小問題，但應避免把非增關係寫成嚴格效果。

**最小修法：**

改成「選較小閾值，以取得不低的 coverage」。

---

### 10. `risk_coverage` 沒有拒絕非有限 correctness 的專門訊息

**原句：**

```python
or not np.all((correctness == 0) | (correctness == 1))
```

**原因：**

NaN correctness 最終會被拒絕，功能上安全；但它被歸入統一的 `Invalid decision data`，無法區分 shape、非有限值、非二元值與非法 threshold。卷規要求故障測試與明確策略，建議拆開檢查。

**最小修法：**

至少依次檢查 shape、空輸入、finite、值域與 thresholds，給出相應錯誤。這不是主要阻擋項，但能使故障測試可定位。

### 11. `synthetic_eval` 的 ECE bins 造成第一箱必空，示範價值有限

**原句：**

```python
ece, _ = compute_ece(confidence, correct, [0, 0.5, 1])
```

**原因：**

confidence 是二分類的最大 softmax 概率，理論上至少為 $0.5$，所以 $[0,0.5)$ 永遠為空。這不錯，但無法測試多個非空箱的 ECE 聚合。

**最小修法：**

可使用 `[0, 0.75, 1]`，或保留現有 bins 但明說第一箱必空，另以例題 4.2 測試雙箱皆非空。現有正常 ECE 測試已涵蓋後者，因此只需補說明。

### 12. `compute_global_ppl` 的 array-like 契約仍與其他函式不一致

**原句：**

```python
if logits.ndim != 3:
```

而 `compute_ece` 先執行 `np.asarray`。

**原因：**

若輸入巢狀 list，ECE 可處理，PPL 會因不存在 `.ndim` 而出現非契約錯誤。函式應一致地限定 ndarray，或一致轉換。

**最小修法：**

入口加：

```python
logits = np.asarray(logits)
labels = np.asarray(labels)
valid_mask = np.asarray(valid_mask)
```

但不能把整數 mask 自動轉成布林，仍須保留 dtype 檢查。

### 13. logits 的全張量有限政策仍未寫入 docstring

**原句：**

```python
if not np.all(np.isfinite(logits)):
    raise ValueError(...)
```

**原因：**

這表示 padding／mask=False 的位置也不能含 NaN/Inf。此策略正確且保守，但 docstring 沒有明示。`np.where` 只控制 reduction，不會豁免無效位置的非有限值。

**最小修法：**

在 `compute_global_ppl` 與 `compute_stable_log_softmax` 的 docstring 明寫：「所有 logits，包括無效 token 位置，均須有限。」

### 14. PPL overflow 仍使用 `print`

**原句：**

```python
if not np.isfinite(perplexity):
    print(f"Warning: PPL overflow...")
```

**原因：**

底層數值函式直接列印有副作用，而且 `np.exp` 可能先發出 runtime warning。Mean NLL 本身可能仍有效，應以明確 API 政策處理。

**最小修法：**

回傳 `inf` 而不列印，並在文件中說明；或在指數化前檢查範圍並拋出 `OverflowError`。不要由核心函式直接輸出文字。

---

### 15. `compute_classwise_ece` 仍未處理空樣本與空類別

**原句：**

```python
N, C = probs.shape
...
macro_ece = np.mean(eces)
```

**原因：**

若 $C=0$，`eces` 為空並產生 NaN；若 $N=0$，錯誤會延遲到內層函式。新增的測試也沒有測 classwise ECE。

**最小修法：**

加入：

```python
if N == 0 or C == 0:
    raise ValueError("N and C must be positive.")
```

再補正常、空樣本、空類別、row sum 非一、label 越界測試。

### 16. 整合題解答仍未利用本章新增程式

**原句：**

> 「繪製 R-Curve：x 軸為 Coverage，y 軸為 Risk。」

**原因：**

現在章內已有 `risk_coverage` 與 `select_threshold`，但習題解答仍只是三句概念描述，沒有給出 validation 選 $\tau$、固定閾值、套到 ID/OOD test、不可達時報錯等流程，因此仍非完整解答。

**最小修法：**

在答案中明列：

1. validation 產生候選曲線；
2. 依 coverage 約束選 $\tau^\star$；
3. 固定 $\tau^\star$；
4. 分別評估 ID-test 與 OOD-test；
5. 若 validation 無可行候選則報告不可達；
6. 不在 OOD-test 重調閾值；
7. 同時報告 decision count、accepted count、coverage、risk。

### 17. OOD 語義結論仍過強

**原句：**

> 「這表明模型對新異常模式缺乏泛化能力。」

**原因：**

高 PPL 只直接表示模型給該群真實 token 較低概率。原因可能是詞彙、模板、長度、tokenizer、標註或合成規則差異，不足以單獨證明語義泛化失敗。

**最小修法：**

改成：

> 「這表示模型與告警群的 token 分布匹配較差；是否屬於語義泛化失敗，仍須控制詞彙、模板、長度、tokenizer 與標註規則。」

### 18. 手設表格仍沒有 ECE 事件數

**原句：**

表格只有：

**原因：**

PPL 分母是有效 token；ECE 分母是 calibration events；Risk 分母是接受決策。三者不能共享一個未說明的 1000。正文已指出決策數要另列，ECE event count 仍缺失。

## 三、shape、broadcast、reduction 與梯度範圍

本章沒有訓練或梯度程式，因此不存在需核對的反向傳播；評估函式只做前向 reduction，這是合理範圍。PPL 的主要 shape 正確：

- logits：$(N,L,V)$；
- labels/mask：$(N,L)$；
- gather 結果：$(N,L)$；
- log-softmax：沿 $V$ 軸；
- NLL：對有效 token 求和後除一次。

`risk_coverage` 中 confidence 與 correctness 同為 $(N,)$，`accepted & (correctness == 0)` 不發生意外 broadcast。threshold 逐一迭代，也沒有跨軸 reduction 錯誤。

新增程式沒有聲稱已執行，正文也明確說測試只是預期，符合證據契約。本章不需要重複完整 Transformer 或訓練 loop；但 split-level OOD 聚合與 validation/test 閾值流程仍屬本章不可省略的評估 loop。
