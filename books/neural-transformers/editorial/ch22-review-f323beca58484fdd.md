## 審稿結論

本輪已修正前次所列主要問題：prompt 末端 EOS 政策明確、零溫度仍驗證截斷參數、top-k/top-p 使用一致的同分排序、seed 與 logits 有檢查，測試入口亦可選擇執行。作者仍明確聲明未執行程式，沒有虛稱執行、訓練或查證來源。

尚有以下須修事項：

1. **EOS 測試的預期 greedy 路徑錯誤。**

   原句：「因為每一步最大 logit 依序指向『水溫』、『正常』與 EOS。」

   查 `transition` 表：BOS 的最大值是水溫；水溫列最大值是正常；正常列最大值是 EOS，故這段描述正確。但生成測試寫「`stopped.tolist() == [BOS, 1, 2, EOS]`」亦與此一致，沒有問題。此疑慮不成立，不應阻擋。

2. **測試程式依賴 Python 的 `assert`，最佳化模式下測試可能失效。**

   原句：「`assert np.array_equal(a, b)`」

   `python -O chapter22.py test` 會略過 `assert`，卻仍印出 `預期：tests completed`；這容易讓讀者以為檢查確實執行。雖作者未宣稱已通過，測試介面仍應避免此歧義。

   最小修法：以明確的檢查函式取代 `assert`，條件不成立時拋出 `AssertionError`；或在測試入口偵測最佳化模式並拒絕執行。

3. **`generate` 對 prompt 含末端 EOS 的停止判斷早於 `max_new_tokens=0`，但目前結果相同；此順序不構成錯誤。**  
   不需修正。對內部 EOS 保留上下文的政策也已明確，不應把它誤判成錯誤停止條件。

4. **測試未覆蓋 top-p 同分排序及 top-k/top-p 組合的順序。**

   原句：「`# 同分時索引升序。`」

   現有測試只驗證 top-k 同分。文字也規定 top-p 同分按索引升序，且先 top-k 再 top-p，但沒有相應測試，無法防止後續改動破壞該契約。

   最小修法：補一個 top-p 同分邊界案例，以及一個 top-k 後再 top-p 的小向量案例，核對候選集合與重新正規化結果。

5. **字數低於本卷正文最低要求。**

   原句：「`"measured_characters": 3288`」

   本卷要求每章至少 3000 個中文字，公式、程式、英文與來源不充字數。該欄位顯示的字數無法證明其中排除了程式碼、公式及英文；正文中也有大量非中文內容，因此不能據此確認中文正文達到 3000 下限。

   最小修法：補足並確認至少 3000 個中文正文字符；不應以程式碼、公式、英文或參考文獻補數。

6. **程式的 `top_p` 型別驗證接受字串數值，但這是可容忍轉換，非核心錯誤。**

   原句：「`top_p = float(top_p)`」

   例如字串 `"0.8"` 會被接受，雖 API 未明確說明是否只接受數值純量。這不影響機率正規化正確性，但契約可更一致。

   最小修法：若要嚴格型別，先拒絕字串與布林值；否則在介面說明允許可轉換為浮點數的純量。此項本身不足以阻擋。

除上述測試覆蓋與字數要求外，本章的正溫度排序命題、機率計算、top-k/top-p 重新正規化、shape 契約及停止迴圈整體合理；完整二步樹亦已補足 greedy 反例。建議處理必修項後再送審。
