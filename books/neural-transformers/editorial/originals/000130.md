# 第29章 唯讀Agent、工具契約與稽核

## 1. 學習目標與先備知識

本章探討在受限環境下設計唯讀Agent的安全機制，核心在於將「模型提議」與「程式授權」徹底分離。讀者需掌握以下先備知識：
1.  **工具調用（Tool Call）的本質**：理解LLM輸出的JSON或結構化代碼僅是「意圖表達」，而非執行指令。
2.  **Schema驗證**：熟悉JSON Schema或類似的數據結構定義語言，用於約束輸入參數的形狀與類型。
3.  **最小權限原則（Principle of Least Privilege）**：在作業系統或資料庫管理中，只賦予執行任務所必需的最小讀取權限，絕不賦予寫入或執行權限。
4.  **事件驅動架構（Event-Driven Architecture）**：理解如何通过狀態機（State Machine）記錄每一次操作的生命週期，包括請求、驗證、執行（若允許）、結果與審計日誌。

本卷前幾章已建立Transformer的數學基礎與小型模型訓練流程。本章不重複模型結構，而是聚焦於如何將這些模型輸出的「語義建議」安全地橋接到「物理/數位世界」的唯讀操作介面。我們強調：**模型生成的代碼或工具調用，絕不允許直接執行Shell指令、訪問網路或操作設備硬體。** 所有操作必須經過程式端的嚴格靜態分析與授權檢查。

## 2. 問題與直覺

### 2.1 為什麼不能信任模型的直接輸出？

在大型語言模型（LLM）作為Agent的核心組件中，模型根據上下文生成下一步動作。例如，在養殖監控場景中，模型可能生成：
```json
{
  "tool": "get_sensor_data",
  "params": {
    "sensor_id": "DO-01",
    "timestamp": "2024-05-01T10:00:00Z",
    "limit": 10
  }
}
```
這個JSON看似無害，但存在以下風險：
1.  **提示注入（Prompt Injection）**：惡意使用者可能在資料中嵌入指令，誘導模型生成惡意參數，如SQL注入字串或路徑穿越（`../../etc/passwd`）。
2.  **幻觉（Hallucination）**：模型可能生成不存在的`sensor_id`或無效的時間戳記，導致下游系統錯誤。
3.  **權限提升（Privilege Escalation）**：如果系統未嚴格驗證，模型可能嘗試調用寫入工具（如`set_feed_rate`），即使任務僅為監控。

**直覺結論**：必須在模型與工具執行器之間設置一道「防火牆」，即**唯讀Gateway**。該Gateway負責：
-   驗證參數是否符合預定義的Schema。
-   檢查調用的工具是否在允許清單（Allowlist）中。
-   確保操作是唯讀的（Read-Only）。
-   記錄所有事件以供稽核。

### 2.2 唯讀Agent的邊界

唯讀Agent的「唯讀」不僅指記憶體或檔案系統，更擴展到任何具有副作用的操作。具體來說：
-   **允許**：查詢感測器讀數、讀取歷史日誌、檢索文件庫、計算指標。
-   **禁止**：修改感測器配置、發送控制指令（如開關水泵）、寫入資料庫、訪問外部網路API、執行任意代碼。

這種設計確保了即使模型被攻擊或出現故障，也無法對生產環境造成實體或數據損失。

## 3. 定義、定理與推導

### 3.1 工具契約（Tool Contract）的數學形式化

我們將工具定義為一個函數 $f: \mathcal{P} \rightarrow \mathcal{R}$，其中 $\mathcal{P}$ 是參數空間，$\mathcal{R}$ 是結果空間。為了保證安全，我們引入**驗證函數** $V: \mathcal{P} \rightarrow \{True, False\}$ 和**授權函數** $A: \mathcal{P} \rightarrow \{Allow, Deny\}$。

**定義 29.1（有效工具調用）**
一個工具調用 $c = (t, p)$，其中 $t$ 是工具名稱，$p$ 是參數，當且僅當滿足以下條件時稱為**有效且授權的調用**：
1.  $t \in \mathcal{T}_{allow}$，其中 $\mathcal{T}_{allow}$ 是唯讀工具的允許清單。
2.  $V(p) = True$，即參數 $p$ 符合工具 $t$ 的預定義Schema。
3.  $A(p) = Allow$，即根據當前用戶身份與上下文，該操作被授權。
4.  工具 $t$ 的實現保證其副作用集合 $\sigma(t) = \emptyset$（即純函數或唯讀操作）。

**命題 29.1（唯讀性保持）**
若系統中所有被調用的工具均滿足 $\sigma(t) = \emptyset$，且系統狀態僅由初始狀態與唯讀查詢結果決定，則系統在執行任意序列的有效調用後，其可寫狀態空間 $S_{write}$ 保持不變。

**證明**：
設系統狀態為 $S = (S_{ro}, S_{wo})$，其中 $S_{ro}$ 為唯讀數據，$S_{wo}$ 為可寫數據。
初始狀態為 $S_0 = (S_{ro,0}, S_{wo,0})$。
對於任意有效工具調用 $t_i$，其執行結果為 $r_i = t_i(S_{ro,0}, p_i)$。
根據唯讀性定義，$t_i$ 僅讀取 $S_{ro,0}$，不修改 $S_{ro,0}$ 或 $S_{wo,0}$。
因此，執行後狀態 $S_1 = (S_{ro,0}, S_{wo,0})$。
以此類推，對於任意長度 $n$ 的調用序列 $t_1, \dots, t_n$，最終狀態 $S_n = (S_{ro,0}, S_{wo,0})$。
故 $S_{write} = S_{wo,0}$ 保持不變。$\square$

**注記**：此命題依賴於「工具實現的正確性」。即程式碼層面必須保證工具函數確實沒有寫入操作。這需要通過靜態代碼分析或沙箱機制來驗證，而非僅依賴模型輸出。

### 3.2 參數驗證的有限域約束

為了防止參數中的惡意輸入，我們定義參數空間 $\mathcal{P}$ 為有限離散集合的笛卡爾積。例如，`sensor_id` 必須屬於 $\{S_1, S_2, \dots, S_k\}$，`timestamp` 必須屬於合法時間戳集合。

**定義 29.2（Schema驗證）**
給定Schema $S$，參數 $p$ 通過驗證當且僅當 $p$ 的每個字段 $p_j$ 屬於預定義的合法值集合 $\mathcal{L}_j$，且類型正確。

這種離散化約束消除了連續空間中的模糊性，使得驗證函數 $V(p)$ 可以通過簡單的集合 membership 測試實現，計算複雜度為 $O(|p|)$。

## 4. 逐步手算例題

### 4.1 例題一：工具調用的合法性檢查

**情境**：
-   允許清單 $\mathcal{T}_{allow} = \{\text{"get\_dissolved\_oxygen"}, \text{"get\_ph\_level"}\}$
-   當前用戶權限：唯讀監控員。
-   模型生成調用：
    ```json
    {
      "tool": "get_ph_level",
      "params": {
        "sensor_id": "PH-02",
        "time_range": "last_1h"
      }
    }
    ```
-   已知：感測器清單中不包含 `PH-02`，僅有 `PH-01` 和 `PH-03`。

**步驟**：
1.  **工具檢查**：`get_ph_level` $\in$ $\mathcal{T}_{allow}$？**是**。
2.  **參數Schema檢查**：
    -   `sensor_id` 類型為 String？**是**。
    -   `time_range` 類型為 Enum（`last_1h`, `last_24h`, `last_7d`）？**是**。
3.  **權限檢查**：用戶為監控員，允許讀取PH值？**是**。
4.  **數據存在性檢查（可选但推薦）**：`PH-02` 是否存在於感測器註冊表？**否**。

**結果**：
-   若僅檢查Schema與權限，則調用**有效**。
-   若包含數據存在性檢查（防止模型幻觉），則調用**拒絕**。
-   **建議策略**：在唯讀Agent中，數據存在性檢查應由工具執行器內部處理並返回錯誤信息，而非在Gateway層拒絕，以便記錄模型的幻觉事件。但Gateway應拒絕明顯的格式錯誤或非法ID前綴。

### 4.2 例題二：SQL注入嘗試的攔截

**情境**：
-   工具：`search_logs`
-   參數Schema：`query` 字段必須匹配正則表達式 `^[a-zA-Z0-9\s_]+$`（僅允許字母、數字、空格、下劃線）。
-   模型生成參數：
    ```json
    {
      "query": "O2 level; DROP TABLE sensors; --"
    }
    ```

**步驟**：
1.  **正則表達式匹配**：
    -   字符串包含 `;`、`/`、`-` 等非法字符。
    -   匹配失敗。
2.  **驗證結果**：$V(p) = False$。

**結果**：
-   Gateway拒絕調用，並記錄事件：`SECURITY_VIOLATION: Invalid parameter format for tool search_logs`。
-   不執行任何資料庫查詢。

### 4.3 例題三：權限邊界測試

**情境**：
-   允許清單 $\mathcal{T}_{allow} = \{\text{"get\_sensor\_data"}\}$
-   模型生成調用：
    ```json
    {
      "tool": "set_feed_rate",
      "params": {
        "rate": 10
      }
    }
    ```

**步驟**：
1.  **工具檢查**：`set_feed_rate` $\in$ $\mathcal{T}_{allow}$？**否**。

**結果**：
-   Gateway立即拒絕，返回錯誤：`TOOL_NOT_ALLOWED`。
-   此事件標記為高風險，觸發稽核警報。

## 5. 實作與程式

以下提供一個自足的Python實現，模擬唯讀Agent的工具Gateway。我們使用標準庫 `json` 和 `re`，不依賴第三方框架，以確保輕量與可移植性。

### 5.1 工具註冊與Schema定義

```python
import json
import re
import time
import hashlib

class ToolContractError(Exception):
    """自定義異常：工具契約違反"""
    pass

class ReadOnlyTool:
    def __init__(self, name, schema, allowed_roles):
        self.name = name
        self.schema = schema
        self.allowed_roles = allowed_roles
        
    def validate(self, params):
        """
        驗證參數是否符合Schema
        Schema為字典，鍵為參數名，值為類型或正則表達式
        """
        if not isinstance(params, dict):
            raise ToolContractError("Params must be a dictionary")
        
        for key, value in params.items():
            if key not in self.schema:
                raise ToolContractError(f"Unknown parameter: {key}")
            expected_type = self.schema[key].get('type')
            pattern = self.schema[key].get('pattern')
            
            if expected_type == 'str':
                if not isinstance(value, str):
                    raise ToolContractError(f"Param {key} must be string")
                if pattern and not re.match(pattern, value):
                    raise ToolContractError(f"Param {key} fails pattern check")
            elif expected_type == 'int':
                if not isinstance(value, int):
                    raise ToolContractError(f"Param {key} must be integer")
            elif expected_type == 'float':
                if not isinstance(value, (int, float)):
                    raise ToolContractError(f"Param {key} must be number")
            else:
                raise ToolContractError(f"Unsupported type: {expected_type}")
        
        # 檢查必填字段
        for key in self.schema.keys():
            if key not in params:
                raise ToolContractError(f"Missing required parameter: {key}")

class AuditLogger:
    def __init__(self):
        self.events = []
        
    def log(self, event_type, details):
        entry = {
            "timestamp": time.time(),
            "type": event_type,
            "details": details,
            "hash": hashlib.sha256(str(details).encode('utf-8')).hexdigest()
        }
        self.events.append(entry)
        
    def get_last_n(self, n):
        return self.events[-n:]

class ReadOnlyAgentGateway:
    def __init__(self):
        self.tools = {}
        self.logger = AuditLogger()
        self.current_role = "monitor" # 模擬當前角色
        
    def register_tool(self, tool_name, schema, allowed_roles, handler_func):
        """
        註冊唯讀工具
        handler_func: 實際執行函數，必須保證唯讀
        """
        if not self._is_read_only_tool(tool_name):
            raise ValueError(f"Tool {tool_name} is not marked as read-only")
        self.tools[tool_name] = {
            "contract": ReadOnlyTool(tool_name, schema, allowed_roles),
            "handler": handler_func
        }
        
    def _is_read_only_tool(self, tool_name):
        # 簡單檢查：工具名不能包含 write, set, delete, create, update
        forbidden_keywords = ["write", "set", "delete", "create", "update", "execute", "run"]
        for kw in forbidden_keywords:
            if kw in tool_name.lower():
                return False
        return True

    def execute_tool_call(self, json_call):
        """
        執行模型生成的工具調用
        """
        try:
            call = json.loads(json_call) if isinstance(json_call, str) else json_call
            tool_name = call.get("tool")
            params = call.get("params", {})
            
            # 1. 檢查工具是否存在
            if tool_name not in self.tools:
                self.logger.log("DENY_TOOL_NOT_FOUND", {"tool": tool_name, "params": params})
                return {"status": "error", "message": "Tool not found"}
            
            tool_info = self.tools[tool_name]
            contract = tool_info["contract"]
            handler = tool_info["handler"]
            
            # 2. 檢查角色權限
            if self.current_role not in contract.allowed_roles:
                self.logger.log("DENY_PERMISSION", {"tool": tool_name, "role": self.current_role})
                return {"status": "error", "message": "Permission denied"}
            
            # 3. 驗證參數Schema
            try:
                contract.validate(params)
            except ToolContractError as e:
                self.logger.log("DENY_SCHEMA_VIOLATION", {"tool": tool_name, "error": str(e)})
                return {"status": "error", "message": str(e)}
            
            # 4. 執行工具（應為唯讀操作）
            self.logger.log("EXECUTE_START", {"tool": tool_name, "params": params})
            result = handler(params)
            self.logger.log("EXECUTE_SUCCESS", {"tool": tool_name, "result_hash": hashlib.sha256(str(result).encode()).hexdigest()})
            
            return {"status": "success", "result": result}
            
        except json.JSONDecodeError:
            self.logger.log("DENY_INVALID_JSON", {"raw": json_call})
            return {"status": "error", "message": "Invalid JSON"}
        except Exception as e:
            self.logger.log("EXECUTE_ERROR", {"error": str(e)})
            return {"status": "error", "message": str(e)}
```

### 5.2 模擬唯讀工具實現

```python
# 模擬資料庫
MOCK_SENSOR_DATA = {
    "DO-01": [
        {"time": "2024-05-01T10:00:00Z", "value": 7.5},
        {"time": "2024-05-01T10:05:00Z", "value": 7.4},
        {"time": "2024-05-01T10:10:00Z", "value": 7.6}
    ],
    "PH-01": [
        {"time": "2024-05-01T10:00:00Z", "value": 7.2},
        {"time": "2024-05-01T10:05:00Z", "value": 7.1}
    ]
}

def get_dissolved_oxygen(params):
    """
    模擬唯讀工具：獲取溶解氧數據
    """
    sensor_id = params["sensor_id"]
    limit = params.get("limit", 10)
    
    if sensor_id not in MOCK_SENSOR_DATA:
        return {"error": "Sensor not found"}
    
    data = MOCK_SENSOR_DATA[sensor_id]
    # 模擬時間範圍過濾
    return data[-limit:]

def get_ph_level(params):
    """
    模擬唯讀工具：獲取PH值
    """
    sensor_id = params["sensor_id"]
    if sensor_id not in MOCK_SENSOR_DATA:
        return {"error": "Sensor not found"}
    data = MOCK_SENSOR_DATA[sensor_id]
    return data[-1]

# 初始化Gateway
gateway = ReadOnlyAgentGateway()

# 註冊工具
gateway.register_tool(
    tool_name="get_dissolved_oxygen",
    schema={
        "sensor_id": {"type": "str", "pattern": r"^DO-\d{2}$"},
        "limit": {"type": "int"}
    },
    allowed_roles=["monitor", "admin"],
    handler_func=get_dissolved_oxygen
)

gateway.register_tool(
    tool_name="get_ph_level",
    schema={
        "sensor_id": {"type": "str", "pattern": r"^PH-\d{2}$"}
    },
    allowed_roles=["monitor"],
    handler_func=get_ph_level
)
```

## 7. 反例與常見陷阱

### 7.1 陷阱一：過度信任模型輸出的類型

**反例**：
模型生成 `{"sensor_id": "DO-01", "limit": "10"}`（`limit` 為字符串）。
**風險**：如果工具實現中直接執行 `data[-limit:]`，Python會拋出 `TypeError`，但更重要的是，如果工具實現包含複雜邏輯，類型錯誤可能導致非預期行為。
**正確做法**：Gateway的Schema驗證必須嚴格檢查類型，將 `int` 與 `str` 區分開。上述程式碼中已實現此檢查。

### 7.2 陷阱二：忽略「唯讀」工具的副作用

**反例**：
工具 `get_sensor_data` 實現中，為了性能緩存，寫入了本地磁碟或記憶體中的共享狀態。
**風險**：雖然名為 `get`，但實際上有寫入操作，違反了唯讀性。
**正確做法**：
1.  使用靜態代碼分析工具（如 `pylint` 自定義規則）檢查工具函數是否調用了 `open(..., 'w')`、`sqlite3.execute` 等寫入API。
2.  在沙箱環境中運行工具，監控文件系統調用（`ptrace` 或 `strace`）。

### 7.3 陷阱三：日誌洩露敏感信息

**反例**：
稽核日誌中記錄了用戶的完整查詢參數，包含可能存在的敏感數據（如內部網路IP）。
**風險**：日誌被未授權訪問時，洩露敏感信息。
**正確做法**：
1.  對參數進行脫敏處理（Masking），例如將IP地址替換為 `***`。
2.  僅記錄參數的哈希值或摘要，而非原始值，除非必要。

### 7.4 陷阱四：正則表達式ReDoS攻擊

**反例**：
使用正則表達式 `^(a+)+$` 驗證輸入。
**風險**：攻擊者輸入 `"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa!"`，導致正則表達式匹配時間指數級增長，造成服務癱瘓（ReDoS）。
**正確做法**：
1.  使用經過優化的正則表達式庫（如 Python 的 `re` 模塊在較新版本中已有所改進，但仍需謹慎）。
2.  限制輸入長度，避免過長字符串進入正則匹配。
3.  使用有限狀態機（FSM）代替複雜正則表達式進行驗證。

## 8. AI、幾何與養殖案例

### 8.1 養殖場監控Agent

**場景描述**：
某養殖場部署了10個溶解氧（DO）感測器和5個PH感測器。管理員希望利用AI Agent自動監控水質異常，並生成報告。

**Agent工作流**：
1.  **感知**：模型生成調用 `get_dissolved_oxygen` 獲取所有DO感測器的即時數據。
2.  **推理**：模型分析數據，發現 DO-03 的溶解氧值持續下降，低於安全閾值 6.0 mg/L。
3.  **提議**：模型生成調用 `get_ph_level` 獲取 PH-03 的數據，以確認是否因pH異常導致。
4.  **授權與執行**：Gateway驗證調用，執行唯讀查詢。
5.  **輸出**：模型生成警報文本：“DO-03 溶解氧低，建議檢查曝氣裝置。”

**幾何直覺**：
在特徵空間中，DO和PH值構成了多維空間中的點。模型通過學習歷史數據，隱式地學到了這些維度之間的相關性（幾何結構）。唯讀Agent的作用是讓模型能夠“查看”當前數據點在這些維度上的坐標，而不允許模型“移動”這些點（即不允許控制設備）。

**安全邊界**：
-   模型不能生成 `increase_aeration` 調用，因為該工具不在允許清單中。
-   如果模型嘗試生成此調用，Gateway將拒絕並記錄警報。
-   人類操作員收到警報後，手動決定是否調整曝氣裝置。

### 8.2 稽核與溯源

**案例**：
某日，操作員發現系統記錄顯示某次DO查詢結果異常。
**稽核步驟**：
1.  查詢 `AuditLogger`，找到對應對 `timestamp` 的事件。
2.  檢查事件類型是否為 `EXECUTE_SUCCESS`。
3.  驗證 `details` 中的參數哈希與工具返回值哈希是否匹配。
4.  追溯模型生成該調用的上下文，檢查是否受到提示注入影響。

**結論**：
通過嚴格的唯讀契約與稽核機制，系統確保了AI Agent僅作為“觀察者”與“分析者”，而非“操作者”，從而最大化了安全性。

## 10. 習題解答

### 習題 1 解答
```python
schema = {
    "query": {
        "type": "str",
        "pattern": r"^[a-zA-Z0-9\s_]{1,100}$"
    },
    "start_time": {
        "type": "str",
        "pattern": r"^\d{4}-\d{2}-\d{2}$"
    },
    "end_time": {
        "type": "str",
        "pattern": r"^\d{4}-\d{2}-\d{2}$"
    }
}
```
*注：時間先後順序的檢查應在工具實現中進行，因為Schema正則表達式無法表達跨字段約束。*

### 習題 2 解答
| 工具 | monitor | analyst | admin |
| :--- | :---: | :---: | :---: |
| `get_sensor_data` | Allowed | Allowed | Allowed |
| `get_historical_report` | Denied | Allowed | Allowed |
| `export_data` | Denied | Denied | Allowed |
| `set_alert_threshold` | **Denied** | **Denied** | **Denied** |

*注：`set_alert_threshold` 應在Gateway層直接拒絕，因為它包含寫入操作，不應註冊為唯讀工具。*

### 習題 3 解答
-   **複雜度分析**：正則表達式 `^(a+)+$` 對輸入 `a^N!` 的匹配時間為 $O(2^N)$，因為內層 `(a+)+` 可以有多種分組方式。
-   **安全替代**：使用簡單的正則表達式 `^a+$`，或直接使用字符串方法：
    ```python
    def is_safe_a_string(s):
        return all(c == 'a' for c in s)
    ```
    此方法複雜度為 $O(N)$，無ReDoS風險。

### 習題 4 解答
```python
class HashChainLogger:
    def __init__(self):
        self.prev_hash = "GENESIS"
        self.chain = []
        
    def log(self, event):
        current_hash = hashlib.sha256(self.prev_hash + str(event).encode('utf-8')).hexdigest()
        self.chain.append({
            "event": event,
            "hash": current_hash,
            "prev_hash": self.prev_hash
        })
        self.prev_hash = current_hash
        
    def verify_chain(self):
        for i, entry in enumerate(self.chain):
            if i == 0:
                expected_prev = "GENESIS"
            else:
                expected_prev = self.chain[i-1]["hash"]
            
            if entry["prev_hash"] != expected_prev:
                return False
            if hashlib.sha256(expected_prev + str(entry["event"]).encode('utf-8')).hexdigest() != entry["hash"]:
                return False
        return True
```

def test_negative_limit():
