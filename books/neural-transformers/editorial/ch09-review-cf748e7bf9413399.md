## 一、本輪核心阻擋：`check_gradients` 含未定義變數

**逐字程式：**

```python
scaled_err = abs_err / denom

if abs_err > max_abs_err:
    max_abs_err = abs_err
if rel_err > max_rel_err:

```

`rel_err` 已不存在；本輪實際定義的是 `scaled_err`。因此第一次進入迴圈時，執行到：

```python

```

即會發生 `NameError`。

後續：

```python
status = "PASS" if max_rel_err < tol else "FAIL"
```

也仍使用舊命名。由於 `max_rel_err` 初值為零，若只修前一處而沒有統一語義，名稱仍會誤導。

**最小修法：**

統一改成：

```python
max_scaled_err = 0.0
...
scaled_err = abs_err / denom
max_scaled_err = max(max_scaled_err, scaled_err)
...
status = "PASS" if max_scaled_err < tol else "FAIL"
print(... Max Scaled Err ...)
return max_scaled_err
```

主程式的 `err` 可保留，但文字中的 `max_rel_err`、`Max Rel Err` 及測試章節也應一併改成 `max_scaled_err`／`Max Scaled Err`。

這不是命名風格問題，而是目前自足程式不能完成核心驗收的直接故障。

## 二、重新核算目前已正確的核心數學

標籤使用 `X[:, [0]]`，因此保持 $(B,1)$，避免 `(B,1)` 與 `(B,)` 的錯誤廣播。對 batch mean logits BCE：

$$
L=\frac{1}{B}\sum_{i=1}^{B}
\left[\operatorname{logaddexp}(0,z_i)-y_i z_i\right],
$$

梯度為：

$$
dZ_2=\frac{\sigma(Z_2)-Y_{\mathrm{true}}}{B}.
$$

後續：

$$
dW_2=H^TdZ_2,\quad
db_2=\sum_{i=1}^BdZ_{2,i},
$$

$$
dZ_1=(dZ_2W_2^T)\odot(1-H^2),
$$

$$
dW_1=X^TdZ_1,\quad
db_1=\sum_{i=1}^BdZ_{1,i}
$$

皆與現有 backward 相符。batch mean 只除一次，偏置梯度沿軸 0 求和，也正確。

分支式 sigmoid 現在沒有裁切原始 logits，故與 logits BCE 導數一致。命題 9.1 也已正確改為純量方向函數 $\phi(t)=L(\theta+tv)$ 的中心差分命題。這些部分可以保留。

## 三、逐項有限差分的狀態修復基本正確，但介面仍有缺口

### 1. `try/finally` 修復方向正確

**逐字程式：**

```python
finally:
    param[idx] = original_value
    self.forward(self.X, self.Y_true)

```

這已符合正文所述「任何一步失敗也要還原參數」的契約。若正負擾動任一方拋出例外，原參數和 cache 都會嘗試恢復。

### 2. `idx` 沒有明確驗證

`param[idx]` 可由 NumPy 自行拋出索引錯誤，但作為公開方法，最好驗證 `idx` 是否是該參數可接受的索引 tuple。這不是當前主要阻擋項，但可加入故障測試。

### 3. `finally` 中的恢復錯誤可能覆蓋原始錯誤

如果擾動計算與恢復 forward 都失敗，`finally` 中的新例外會遮蔽原始例外。最小實作可以接受，但章稿若強調故障診斷，應至少確保原參數先被恢復，再視需要重建 cache。核心要求是參數不能留在擾動狀態。

### 4. 尚未檢查解析梯度有限

程式只檢查 `numeric`：

```python

```

但 `ana_grad` 也應在比較前確認有限。否則 NaN 參與 `abs` 和 `max` 時可能導致不直觀的判定。

**最小修法：**

在每一項比較前加入：

```python
if not np.isfinite(ana_grad):
    raise ValueError(...)
```

## 五、scaled error 的語義仍未完整同步

本輪註解已改成：

> `Scaled error: the denominator floor keeps near-zero gradients stable.`

這是正確改善。但變數、輸出、正文測試仍混用 `rel_err`、`max_rel_err`、`Max Rel Err`。

現有尺度化誤差為：

$$
e_s=\frac{|g_n-g_a|}
{\max(1,|g_n|,|g_a|)}.
$$

當兩梯度小於 1 時，它等於絕對誤差；當梯度大於 1 時，才按梯度尺度正規化。因此應始終稱為 scaled error，而非 relative error。

**最小修法：**

程式、輸出、測試敘述及主程式變數全部統一。若同時回報最大絕對誤差，最好讓通過條件明確寫成：

- 小尺度使用絕對容差；
- 大尺度使用尺度化容差；

或說明目前的單一 scaled error 已將兩者合併。不能保留兩套名稱。

### 故障測試仍要求手動修改正式程式
