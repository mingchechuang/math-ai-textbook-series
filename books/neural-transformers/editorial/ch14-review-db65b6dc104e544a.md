## 二、小結仍錯誤地宣稱「必要」且能「避免」飽和

逐字原句：

> 縮放因子 $\sqrt{d_k}$ 的必要性來自於避免 Softmax 梯度飽和（在獨立單位方差假設下）。

原因：

章稿前文已正確指出：

> 這是縮放的動機，不是對所有資料或訓練狀態的保證。

方差命題只證明在零均值、單位方差及相互獨立條件下：

$$
\operatorname{Var}(q\cdot k)=d_k,
$$

所以除以 $\sqrt{d_k}$ 後，單一分數的方差為1。它沒有證明：

1. $\sqrt{d_k}$ 是任何分布下唯一必要的尺度；
2. 使用它便能避免所有 Softmax 飽和；
3. 不使用它便必然不能訓練。

訓練後 $Q,K$ 可能相關、具有非零均值或不同分量方差；即使分數方差為1，某一列仍可能存在極端值。

最小修法：

把小結第1點改成：

> 在獨立、零均值、單位方差的尺度近似下，除以 $\sqrt{d_k}$ 可抵消內積標準差隨維度增加的效應，降低 Softmax 僅因維度增長而過度尖銳的風險。

正文其他部分不需改動。

## 三、幾何直覺仍把內積誤稱為投影長度

逐字原句：

> $QK^T$ 測量的是向量夾角的餘弦相似性（若向量已歸一化）或投影長度。

原因：

一般情形下：

$$
q\cdot k=\|q\|\|k\|\cos\theta.
$$

只有 $q,k$ 都是單位向量時，內積才等於餘弦相似度。內積本身也不是一般定義下的標量投影長度；$q$ 在 $k$ 方向上的標量投影是：

$$
\frac{q\cdot k}{\|k\|}.
$$

因此，「或投影長度」不精確，且會使讀者忽略向量範數對注意力分數的影響。

最小修法：

整句改成：

> 若兩向量均已單位化，內積等於餘弦相似度；未歸一化時，內積同時反映兩向量的範數與夾角。縮放只控制整體尺度，不會把一般內積轉換成純角度相似度。

## 四、養殖案例仍把注意力權重當作最終貢獻

逐字原句：

> 注意力權重本身不是因果證據，僅表示在當前模型表示下該 Token 對當前預測的貢獻較大。

原因：

前半句正確，後半句仍錯。章稿自己的習題5已給出直接反例：若兩個 value 都是 $[2,3]$，則權重分別為 $(0.9,0.1)$ 和 $(0.1,0.9)$ 時，兩個輸出均是 $[2,3]$。一般而言，若所有 $V_j=v$：

$$
Y_i=\sum_jA_{ij}V_j
=v\sum_jA_{ij}
=v.
$$

因此，注意力權重可以大幅改變而輸出完全不變。最終預測還會受到 value 的大小與方向、輸出投影、殘差、正規化和後續層影響。

最小修法：

改成：

> 注意力權重本身不是因果證據，只表示該 query 對相應 key/value 位置分配了較大的混合係數；不能單由權重判定最終預測貢獻、語義重要性或因果關係。

這樣才與問題直覺段和習題5一致。

另有一處用語：

> $Q,K,V$：來自同一個 Embedding 層的不同投影。

通常更精確的說法是「來自同一組輸入表示的不同線性投影」，因為 $Q,K,V$ 不一定直接由 embedding lookup 層產生，也可能由前一層隱藏表示產生。

最小修法：

把「同一個 Embedding 層」改成「同一組輸入隱藏表示」。

## 五、`stable_softmax` 文件與實作仍互相矛盾

逐字原句：

> 注意: 若輸入含 NaN 或全列為 -inf，會導致未定義行為或錯誤，需在上游檢查。

但函式本身已實作：

> `if np.any(np.isnan(x)) or np.any(np.isposinf(x)):`  
> `raise ValueError(...)`

以及：

> `if np.any(np.all(np.isneginf(x), axis=axis)):`  
> `raise ValueError(...)`

原因：

目前的實際契約是 `stable_softmax` 自己拒絕這些輸入，不是交給上游檢查。部分位置為 `-inf` 也不是未定義；只要該 row 至少有一個有限 logit，這正是合法 hard mask 的計算方式。

最小修法：

將 docstring 改為：

> 輸入含 `NaN`、`+inf`，或某個沿 `axis` 的 row 全為 `-inf` 時，函式明確拋出 `ValueError`。部分元素為 `-inf`、但該 row 至少存在一個有限 logit 時允許計算。

`sum_exp == 0` 的後備檢查可保留。因為合法 row 在減最大值後至少有一項 `exp(0)=1`，該分支主要是防禦性保護。

## 六、mask 的非法型別仍可能產生非契約錯誤

逐字原句：

> `if mask.shape != scores.shape:`

這行先存取 `mask.shape`，之後才檢查 dtype。若呼叫者傳入 Python list，會拋出 `AttributeError`，而非明確的 `TypeError`。

目前 $Q,K,V$ 已先檢查：

> `if not all(isinstance(x, np.ndarray) for x in (Q, K, V)):`

mask 最好採同一接口原則。

最小修法：

在使用 `mask.shape` 前加入：

```python
if not isinstance(mask, np.ndarray):
    raise TypeError("Mask must be a NumPy array")
```

然後再檢查 shape 和布林 dtype，並加入對應故障測試：

```python
rejects(lambda: scaled_dot_product_attention(
    q, k, v, [[[True, False, True]]]), TypeError)
```

## 七、有限差分測試的方向與名稱需更精確

### 1. 測試2不是數值梯度驗證

逐字原句：

> `# 測試 2: 梯度驗證`

其內容只是：

> `assert dQ.shape == Q.shape`  
> `assert dK.shape == K.shape`  
> `assert dV.shape == V.shape`

原因：

這只驗證梯度 shape，不驗證數值。數值有限差分是在測試3，而且測試2使用的隨機 `dY` 並沒有被測試3使用。

最小修法：

將註解改為：

```python
# 測試 2: 梯度 shape
```

以及把「測試與預期結果」中的第2點改成「驗證三個梯度 shape 與輸入一致」。

### 2. 有限差分只核對全一上游方向

逐字原句：

> `dY = np.ones_like(Y)`

以及：

> `return np.sum(y)`

這兩者數學上一致，對應：

$$
L=\sum Y.
$$

因此並非錯誤。但章稿新增正文已正確警告，若 value 有對稱性，分數梯度可能退化。使用固定非均勻 $dY$ 能提供更有辨識力的 VJP 核對。

最小修法：

讓 `finite_diff_check` 接受可選 `dY`：

```python
def finite_diff_check(Q, K, V, mask=None, dY=None, eps=1e-5):
    Y, cache = ...
    if dY is None:
        dY = np.ones_like(Y)
```

loss 改為：

```python
return np.sum(y * dY)
```

測試時用固定局部 RNG 產生非均勻 `dY`。若不修改程式，至少應在文字中明確說「有限差分核對的是 $L=\sum Y$ 所對應的單一 VJP 方向」，不要暗示核對所有上游梯度。

## 八、測試的可重現性仍不一致

新增的非對稱測試使用：

> `rng = np.random.default_rng(14)`

但前面的正常、梯度、全遮罩與廣播測試仍使用：

> `np.random.randn(...)`

原因：

有限差分測試3使用未固定的全域隨機輸入。雖然一般標準常態小矩陣預期不會造成問題，但若某次失敗，章稿沒有完整 seed 契約可重現同一輸入。這也使固定 $10^{-5}$ 門檻不是針對一組明列資料。

最小修法：

把

```python
rng = np.random.default_rng(14)
```

移到 `run_tests()` 開頭，將所有 `np.random.randn(shape)` 改為：

```python
rng.standard_normal(shape)
```

固定 seed 只保證本程式在相容環境下產生受控案例，不代表跨版本或跨硬體逐位一致。

依本卷要求，程式習題需有完整解答，不能只寫「應核對」或描述未提供的步驟。

最小修法：

```python
def scaled_dot_product_attention(
        Q, K, V, mask=None, attn_bias=None, scale_factor=None):
```

若未來允許 bias broadcasting，則還需沿廣播軸求和回 bias 原 shape；本題目前要求同 shape，故不涉及該 reduction。

## 十一、反例與常見陷阱仍有過度絕對措辭

逐字原句：

> Softmax 輸入差異過大，導致權重極端二值化，梯度極小，訓練收斂緩慢。

原因：

$d_k=512$ 且分量符合命題假設時，未縮放分數的標準差約22.6，確實提高尖銳與梯度弱化風險，但不能由此保證每一列權重「極端二值化」，也不能保證實際訓練必然收斂緩慢。具體情況取決於分數差、上游梯度、初始化、殘差等。

最小修法：

改成：

> 在命題的尺度假設下，未縮放分數的標準差約22.6，較容易產生尖銳權重並使傳向 logits 的部分梯度變弱，增加優化困難。
