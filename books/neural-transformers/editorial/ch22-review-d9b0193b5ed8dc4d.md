## 審稿結論

本章的核心數學與解碼流程大致正確，正面例題、正溫度排序命題及重現性聲明也符合本卷要求；作者沒有虛稱程式已執行或模型已訓練。以下問題須修正，主要涉及生成器停止語義、輸入驗證、top-k 排序，以及實際可呼叫的程式與測試。

### 必須修正

1. **prompt 已以 EOS 結尾時，生成器沒有遵守停止政策。**

   原句：「若 prompt 已含 EOS，本章仍把 prompt 視為既有上下文，不自動刪除；呼叫者可選擇是否立即停止。」

   但 `generate` 沒有「是否立即停止」的參數，也沒有檢查 prompt 是否已含 EOS；此時仍會呼叫模型並追加 token。這與「直到產生 EOS」的停止說明不一致，也使 prompt 含 EOS 後的輸出行為未定義。

   最小修法：加入明確參數（例如 `stop_if_prompt_ends_with_eos`），並在迴圈前實作；或明確規定一律立即停止，刪除「呼叫者可選擇」的說法。另須說明 prompt 中 EOS 若非末 token 時如何處理。

2. **產生 EOS 後只停止單序列；這點可以接受，但測試宣稱過強。**

   原句：「EOS 狀態會令 EOS logit 最高；最多再生成一個 EOS。」

   這項測試以 prompt `[EOS]` 呼叫生成，確實會再產生一個 EOS，然後停止。但它測的是「已結束 prompt 仍會新增一個 EOS」，不是通常所說「生成 EOS 後停止」；也沒有測到新生成 EOS 後不再繼續。

   最小修法：用會先輸出非 EOS、下一步輸出 EOS 的 stub model，檢查新增序列在 EOS 處停止；prompt 已含 EOS 的情況另立測試，對應第 1 點採用的政策。

3. **`top_k`／`top_p` 在零溫度分支被略過，且非有限 logits 檢查不完整。**

   原句：「`temperature=0` 明確退化成 one-hot greedy，不計算 `logits / 0`。」

   `next_token_distribution` 在零溫度時直接回傳 one-hot，因此即使 `top_k=0` 或 `top_p=0` 等非法參數也會被接受；對全有限以外的輸入，NaN/Inf 的部分情形雖先拒絕，但 API 參數仍未一致驗證。程式實際提供的是「零溫度忽略截斷」，而非全文列出的統一篩選政策。

   最小修法：不論溫度為何，先驗證 `top_k`、`top_p` 及其他參數；明定零溫度與 top-k/top-p 同用時的政策（例如拒絕同用，或明定 greedy 優先），並加故障測試。

4. **`top_k` 的排序說明與程式並非穩定地依索引打破同分。**

   原句：「本章使用穩定索引排序，並取達到門檻所需的最短前綴。」

   程式以 `argsort(..., kind="mergesort")[::-1]` 排序；反轉會倒置同分項原有順序。這與「穩定索引排序」不符，也讓例文中同分邊界的實際規則不清楚。

   最小修法：採用明確的排序鍵，例如機率降序、索引升序；top-k 與 top-p 共用同一排序函式，並補同分測試。對 top-p，可保留達到門檻的最短前綴，但須依此 tie-break 規則決定前綴。

5. **程式主流程沒有執行測試，讀者無法照章得到測試結果。**

   原句：「`# 需要測試時，由讀者明確呼叫： # run_tests()`」

   `demo()` 只印出生成結果；直接執行程式不會執行 `run_tests()`。雖然作者明確說明測試未執行，沒有捏造執行紀錄，但章稿要求自足程式與故障測試；目前測試函式也沒有實際涵蓋排序並列、非法 seed、模型輸出非有限值或所有 token 遭禁用等重要故障。

   最小修法：在入口提供明確選項，讓讀者可分別執行 `demo()` 與 `run_tests()`；新增上述故障案例，並仍只寫「預期結果」，不可改稱已通過。

6. **`seed` 未驗證，且生成函式可能在模型回傳非有限 logits 時表現不一致。**

   原句：「固定 seed 只保證在相同 NumPy 版本、亂數演算法、機率與呼叫順序下具有重現意義。」

   `generate` 直接將任意 `seed` 傳給 `default_rng`，其錯誤訊息與接受型別由 NumPy 決定，沒有本章定義的 API 契約。此外，greedy 路徑不經 `next_token_distribution`，模型若回傳 NaN/Inf logits，`argmax` 仍可能產生 token；抽樣路徑則會拒絕。兩模式故障語義不同。

   最小修法：在取最大值或建分布前，統一檢查 logits shape 與有限性；明定 seed 支援的型別與錯誤行為，並為兩種模式加同一非有限輸出測試。

7. **例題三不足以支持「逐步 greedy 不一定得到全域最大序列」的結論。**

   原句：「另一條序列為：$p(Bb)=0.4\\times0.9=0.36$。」

   這個比較只列出 `Aa` 與 `Bb`，沒有交代交叉延續 `Ab`、`Ba` 的條件機率；若題意是證明全域最佳序列，尚未完整定義可比較的候選序列分布。

   最小修法：列出兩種前綴各自所有第二步候選的條件機率，或明確把例子限定為「只比較兩條指定路徑」，並另給完整的二步樹來證明 greedy 序列非全域最大。

8. **參考來源未充分對應本章實作聲明。**

   原句：「NumPy random `Generator` 文件可作亂數 API 的延伸查詢入口；實際重現性仍受版本、演算法與呼叫順序影響。」

   此來源沒有列出可定位網址；其餘來源也主要是 Transformer 背景或未逐條核對的入口，不能支持 NumPy 排序、亂數與抽樣器的具體行為。作者有坦承來源未核實，沒有虛構查證，但參考資料尚不自足。

   最小修法：補上可定位的 NumPy `Generator` 文件連結，並只把未核對資料標為延伸閱讀，不寫成已核實的實作依據。
