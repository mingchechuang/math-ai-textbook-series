# 第20章 專題：可稽核的養殖決策輔助系統

## 學習目標與先備知識

本章把資料矩陣、投影、檢索、評估與誤差傳播整合為池A的純模擬決策輔助流程。讀完後，你應能追蹤一筆資料如何形成建議、指出資料切分與測試的用途，並設計人工批准和回滾關卡。只需會讀矩陣乘法、基本向量運算及簡單Python；所有數值皆為教學合成，不代表真實養殖閾值或操作規範。

## 從池A提出問題

池A收到感測器的溫度、溶氧、pH，水面影像特徵，以及工作日誌。系統可能把它們整理成特徵，再從已核准的SOP檢索相關段落，產生供人員檢查的摘要。這不是自動控制器：不連真實設備，不下投餌、加藥或增氧指令。

每筆資料要保留時間、來源、單位、缺值標記及版本。溫度以攝氏表示，溶氧以mg/L表示，pH為無量綱；特徵表不能只留數字而丟掉這些語境。影像與日誌也須記錄來源與時間，避免把不同時刻的資料錯配。

## 概念與推導

令每列代表一筆觀測、每欄代表一項特徵，批次矩陣為$X\in\mathbb{R}^{n\times d}$。本章示範以三個數值欄位構成$X$；實務中影像表示與文字表示可各自形成矩陣，再由已訓練的映射投影到共同維度。若使用線性投影$Z=XW^T$，其中$W\in\mathbb{R}^{k\times d}$，則$Z\in\mathbb{R}^{n\times k}$。投影是壓縮或轉換表示，不會憑空保證特徵完整，也不等同於理解池況。

縮放器的平均值和標準差只由訓練集估計；驗證集用來選擇設定，測試集留到最後估計泛化表現。對訓練資料的第$j$欄，平均為$\mu_j=\frac{1}{n}\sum_i x_{ij}$，樣本標準差使用分母$n-1$。其他切分只套用訓練所得的$\mu_j,s_j$，計算$(x_{ij}-\mu_j)/s_j$。若把測試資料也用來估計縮放器或投影方向，測試資訊便滲入訓練流程，評估不再公平。

對一筆投影後的查詢向量$q$與SOP向量$d_r$，可計算餘弦相似度$s_r=q^Td_r/(\|q\|\|d_r\|)$，再取top-k候選供人核對。向量相近只表示表示空間中的接近，並不代表SOP適用，也不能代替來源、版本、適用範圍和現場專業判斷。檢索到的內容應能回溯到文件識別碼與段落。

評估也要按資料生成方式切分。若同一日的連續量測被隨機分到訓練和測試，模型可能只記住相鄰時段的相似性；較穩妥的模擬方案是按時間先後切分。除了預先指定的預測誤差，也要檢查缺值、過期、單位不符、輸入超出訓練範圍等條件。平均誤差小，不代表每一筆都安全或可信。

誤差會沿計算流程傳遞。若線性投影使用矩陣$W$，輸入誤差$\delta x$造成輸出誤差$\delta z=W\delta x$，因此$\|\delta z\|\leq\|W\|\|\delta x\|$（相容的向量與矩陣範數）。這只給出上界直覺：投影可能放大某些方向的誤差。缺值被錯誤填補、感測器漂移或影像品質變差，都可能影響下游檢索與摘要，必須記錄品質狀態，而非只看最後文字是否流暢。

## 手算例題

假設訓練集三筆合成溫度為$20,22,24$，單位攝氏。平均值為$\mu=(20+22+24)/3=22$；樣本標準差為$s=\sqrt{[(20-22)^2+(22-22)^2+(24-22)^2]/(3-1)}=2$。因此三筆標準化值依序為$-1,0,1$。若一筆驗證資料是$23$，只套用訓練統計量，得到$(23-22)/2=0.5$；不能重新用驗證資料改寫平均與標準差。

再假設投影矩陣$W=\begin{bmatrix}1&1\\1&-1\end{bmatrix}$，輸入$x=\begin{bmatrix}2\\1\end{bmatrix}$，則$z=Wx=\begin{bmatrix}3\\1\end{bmatrix}$。若輸入誤差$\delta x=\begin{bmatrix}0.1\\0\end{bmatrix}$，輸出誤差為$W\delta x=\begin{bmatrix}0.1\\0.1\end{bmatrix}$。一個欄位的小偏差因投影而同時影響兩個表示分量；下游相似度排序也可能隨之改變。

## Python實驗

以下程式只示範人工指定的訓練統計量、驗證縮放與基本資料有效性檢查。預期輸出為`0.5`及`True`；程式不讀取設備、不連網，也不執行任何養殖操作。

```python
# 輸入：訓練溫度 [20, 22, 24]，驗證溫度 23
train = [20.0, 22.0, 24.0]
validation = 23.0

mean = sum(train) / len(train)
variance = sum((x - mean) ** 2 for x in train) / (len(train) - 1)
std = variance ** 0.5
scaled = (validation - mean) / std

# 模擬的資料有效性欄位：時間、單位及來源均存在
record = {"timestamp": "模擬時間", "unit": "攝氏", "source": "合成感測器"}
valid = all(record[key] for key in ("timestamp", "unit", "source"))

print(scaled)  # 預期：0.5
print(valid)   # 預期：True
```

完整模擬流程可分成幾個可稽核階段：固定seed=42產生合成資料；按時間切出訓練、驗證、測試；只以訓練資料擬合縮放與投影；保存模型、特徵定義、程式版本及資料切分識別碼；在測試集報告事先選定的誤差與有效性失敗筆數；再以模擬紀錄執行檢索、建議摘要和人工批准流程。固定seed便於重現，但不保證統計可靠性。

## 連回生成式AI、多模態與Agent

多模態系統可把感測特徵、影像表示與日誌文字表示分別保存在可追溯的欄位中，再投影至共同空間做比較或融合。相似度和線性代數只是骨架；生成式模型另有非線性、統計不確定性與語言生成誤差。Agent可呼叫唯讀檢索介面，回報候選SOP來源、資料新鮮度及缺失欄位，並產生待審摘要；工具權限應以白名單限制，不能讓模型自行改寫設備狀態或發出控制命令。

## 常見錯誤與限制

把相關性當成因果、把相似度當成健康判斷，都是越界解讀。隨機切分相鄰時間資料可能高估表現；以全資料估計縮放參數會造成資料洩漏；只報平均誤差則可能掩蓋少數大錯。合成資料上的測試不能證明真實池塘的效果。缺值、過期、來源不明或單位不一致時，系統應停止產生可操作建議，改為標示待查，不應用流暢文字掩飾資料不足。

## 習題

1. **基本計算：**訓練集兩筆溶氧合成值為$4,6$。依樣本標準差定義，求平均、標準差及驗證值$5$的標準化結果。
2. **觀念：**為何不能用測試集估計縮放器？固定seed是否足以保證評估可靠？
3. **養殖應用：**模擬資料缺少時間戳，但檢索找到相似SOP。系統應如何處理？說明理由。

## 習題解答

1. 平均為$5$；樣本標準差為$\sqrt{[(4-5)^2+(6-5)^2]/(2-1)}=\sqrt{2}$。驗證值標準化為$0/\sqrt{2}=0$。
2. 測試集是最後評估用；用它估計縮放器會讓測試分布資訊滲入流程，造成評估偏差。固定seed只使某些隨機步驟可重現，不代表樣本具代表性或誤差足夠小。
3. 標示資料無效並停止提出可操作建議；相似SOP不會補回缺失的時間資訊，因而無法確認資料新鮮度與適用時段。交由現場專業人員查核。

## 本章小結

池A的輔助流程必須讓資料、轉換、檢索、測試結果和人工決策都可追溯。訓練統計量不可偷看測試資料，投影與檢索也會傳遞輸入誤差。部署前要以純模擬流程檢查資料切分、測試、權限與失敗處置；正式採用前須由現場專業人員批准安全操作規範，模型建議不能取代養殖專業。
