# 第01章 場、單位與數值模型的範圍

## 學習目標與先備知識

本章是第三卷的入口。讀完本章後，期望能做到以下事項：第一，能區分純量場、向量場與張量場，並以座標、時間及單位完整標示；第二，能判斷一個數值模型有哪些輸入屬於單位、哪些屬於無因次參數，並在進入離散之前先把量綱算清楚；第三，能把「模型誤差」與「離散誤差」分開討論，知道它們量測的對象不同；第四，能建立一個合成池域的最小設定，把座標、網格、單位、初始條件與邊界條件都放進一個可雜湊的結構，並在收到非有限或不一致輸入時拒絕執行；第五，能閱讀後續章節中的梯度、散度、旋度與守恆定律時，先確認其成立條件。

先備知識最少包含：一維與多變數微積分的基礎、向量運算、以 Python 3.10 及 NumPy 操作小型陣列的經驗。讀者不需先讀 Volume IV，因為 Volume IV 尚未編成；本卷涉及的分析結果將在需要時明列成立條件，不會假設讀者已讀過尚未存在的章節。本卷也不承諾量子場論、工業級 CFD 或特定套件的完整 API；章內若使用 SciPy，會明示其為相依套件，且核心實驗只用 NumPy 即可完成。

## 問題與直覺

當我們在紙上寫下 \(\partial c/\partial t = D\nabla^2 c\) 時，這是一個連續介質模型：濃度 \(c\) 是位置的函數，擴散係數 \(D\) 是常數，時間與空間都是連續的。但是電腦裡沒有「連續」，只有有限個浮點數。於是有兩層問題必須分開：第一層是「這個方程式是否為我們關心的系統的良好近似」，這是模型誤差；第二層是「用有限差分或有限體積離散這個方程式後，數值解與連續解的差有多大」，這是離散誤差。把兩者混為一談，會使得我們在調整網格或時間步長時，無法判斷觀測到的差異究竟來自哪一層。

再深一層，在場的層級，量有純量、向量與張量之分。純量場在每一點只有一個實數值，例如水溫、壓力、濃度。向量場在每一點有一個方向與大小，例如流速、熱通量、溶質通量。張量場出現在應力、擴散張量、應變率這些量上。把純量誤寫成向量，或把向量誤寫成純量，在數值模型中是根本的錯誤。舉例而言，若把擴散通量寫成純量，就無法正確處理變係數擴散或非等向擴散。

除此之外，單位是物理模型的骨幹。一段程式可以把 \(D=0.01\) 當作 \(0.01 \,\text{m}^2/\text{s}\)，也可以當作 \(0.01 \,\text{cm}^2/\text{s}\)，兩者相差一萬倍。若沒有把單位紀律放在模型與離散之前，後面再怎麼細化網格也是無效的。因此本章的首要任務是：在進入梯度、散度、有限差分與相場之前，先把場的類型、單位、無因次化與設定驗證這四件事處理清楚。

## 數學與物理推導

### 場的分類與座標

純量場 \(f(\mathbf{x}, t)\) 把位置與時間映到實數，例如溫度 \(T(\mathbf{x}, t)\)（單位 K）。向量場 \(\mathbf{v}(\mathbf{x}, t)\) 把位置與時間映到向量，例如速度 \((u(\mathbf{x}, t), v(\mathbf{x}, t))\)（單位 m/s 或每個分量各自的單位）。張量場 \(\boldsymbol{\sigma}(\mathbf{x}, t)\) 取值在張量空間，例如應力（單位 Pa）或擴散張量 \(\mathbf{D}\)（單位 m\(^2\)/s）。在本卷中，向量場的每個分量都必須附上單位描述；張量場則要說明指標順序與對稱性假設。

座標方面，本卷採用右手系：X 軸向右、Y 軸向上、Z 軸朝觀者。二維物理網格的形狀為 \((N_y, N_x)\)，其中 \(j\) 沿 \(+Y\) 方向、\(i\) 沿 \(+X\) 方向，展平時 \(k = j N_x + i\)。繪圖時使用 `origin='lower'`，或明確翻轉，以免和影像檔以 row 向下為主的慣例混同。cell 中心位於 \(((i+1/2)\Delta x, (j+1/2)\Delta y)\)。若採 node-centered 配置，索引與邊界必須另外說明，不可與 cell-centered 的索引混用。

### SI 單位與量綱

本卷有因次範例使用 SI 基本與衍生單位：長度 m、時間 s、速度 m/s、擴散係數 m\(^2\)/s、溶質濃度 kg/m\(^3\)、溫度 K 或明示攝氏溫差。若來源資料使用 mg/L，必須推導換算：\(1\,\text{mg/L} = 10^{-3}\,\text{kg/m}^3\)，因為 \(1\,\text{L}=10^{-3}\,\text{m}^3\)，且 \(1\,\text{mg}=10^{-6}\,\text{kg}\)，兩者相除得到 \(10^{-3}\,\text{kg/m}^3\)。來源項必須與濃度的時間導數同單位，例如濃度單位為 kg/m\(^3\) 時，來源項 S 的單位是 kg/(m\(^3\cdot\)s)。

### 無因次化

無因次化的目的是將方程式與參數縮減為少數組合，並讓數值尺度落在合理範圍。以擴散方程為例，
$$ \frac{\partial c}{\partial t} = D \nabla^2 c, $$
選定參考長度 \(L\)、參考時間 \(T\)、參考濃度 \(C_0\)，定義 \(x^* = x/L\)、\(t^*=t/T\)、\(c^*=c/C_0\)，代入後得到
$$ \frac{\partial c^*}{\partial t^*} = \frac{D T}{L^2} \nabla^{*2} c^*. $$
組合 \(\mathrm{Fo} = DT/L^2\) 即 Fourier 數。若 \(D=0.01\,\text{m}^2/\text{s}\)、\(L=1\,\text{m}\)、\(T=100\,\text{s}\)，則 \(\mathrm{Fo}=1\)，無因次方程與原方程同形，數值處理更直觀。相反地，若未先算 \(\mathrm{Fo}\) 就隨意選時間步長，很可能在前幾步就超出穩定條件，或時間尺度與真實物理嚴重不符。

### 模型誤差與離散誤差

模型誤差衡量的是「連續模型與真實現象之間的差」，來源包含：忽略的物理過程（例如未計入代謝耗氧）、不適用的邊界條件（例如把池壁當作完全絕熱但實際有熱交換）、參數非均勻但模型假設均勻等。離散誤差衡量的是「離散方程的解與連續模型解的差」，它隨網格與時間步細化而改變。把網格細化十倍後觀測到解的差異，不必然表示模型更正確，它只表示離散層的近似更好。反之，如果模型本身用錯，即使離散誤差已收斂到機器精度，答案仍是錯的。後續章節談一致性、穩定性、收斂與製造解時，都會緊扣兩者的區分。

## 逐步手算例題

### 例題 1：梯度、散度與散度定理

考慮純量場 \(T(x,y) = 20 + 0.5x + 0.25y^2\)（單位 °C，\(x,y\) 單位 m）。求點 \((1,2)\) 的解析梯度，並以步長 \(h=0.1\) 的中央差分估算。

解析偏導：\(\partial T/\partial x = 0.5\)，\(\partial T/\partial y = 0.5y\)。在 \((1,2)\) 得到 \(\nabla T = (0.5, 1.0)\)，單位 °C/m。

中央差分在該點的近似為：
$$ \frac{\partial T}{\partial x}\bigg|_{(1,2)} \approx \frac{T(1.1,2)-T(0.9,2)}{0.2} = \frac{0.5(1.1)-0.5(0.9)}{0.2} = 0.5, $$
$$ \frac{\partial T}{\partial y}\bigg|_{(1,2)} \approx \frac{T(1,2.1)-T(1,2.0-0.1)}{0.2}. $$
計算得 \(T(1,2.1)-T(1,1.9) = 0.25((2.1)^2-(1.9)^2) = 0.25(4.41-3.61)=0.20\)，除以 0.2 得到 1.0，與解析一致。這是一個「差分無誤差」的特例，因為 T 對 x 是一次、對 y 是二次，中央差分對二次項恰好精確。

接著使用向量場 \(\mathbf{v}(x,y) = (x, y)\)（單位 m/s），在單位方形 \([0,1]^2\) 上驗證散度定理：
$$ \iint_{[0,1]^2} \nabla\cdot\mathbf{v}\, dA = \oint_{\partial[0,1]^2} \mathbf{v}\cdot\mathbf{n}\, dl. $$
左側：\(\nabla\cdot\mathbf{v} = 2\)，故積分為 2。右側分四邊：下邊 \(y=0\)、外法向 \(\mathbf{n}=(0,-1)\)，\(\mathbf{v}\cdot\mathbf{n}=-y=0\)，積分 0；右邊 \(x=1\)、\(\mathbf{n}=(1,0)\)，\(\mathbf{v}\cdot\mathbf{n}=x=1\)，積分 1；上邊 \(y=1\)、\(\mathbf{n}=(0,1)\)，\(\mathbf{v}\cdot\mathbf{n}=y=1\)，積分 1；左邊 \(x=0\)、\(\mathbf{n}=(-1,0)\)，\(\mathbf{v}\cdot\mathbf{n}=-x=0\)，積分 0。邊界通量總和為 2，與左側一致。

### 例題 2：無因次化與時間步估算

沿用 \(D=0.01\,\text{m}^2/\text{s}\)、\(L=1\,\text{m}\)、\(C_0=1\,\text{kg/m}^3\)。若計畫做一維顯式 FTCS 擴散模擬，穩定條件為 \(D\Delta t/\Delta x^2 \le 1/2\)。取 \(N_x=101\) 個 node，\(\Delta x = 0.01\,\text{m}\)，則 \(\Delta t \le 0.5 \cdot (0.01)^2 / 0.01 = 0.005\,\text{s}\)。這是一個可手算得到的必要條件。若把 \(\Delta x\) 減半為 0.005 m，則 \(\Delta t \le 0.00125\,\text{s}\)，時間步被迫縮小四倍，說明空間細化對顯式時間格式的成本衝擊。

進一步把長度用 L 無因次化：\(\Delta x^* = 0.01\)，\(\Delta t^* = \Delta t \cdot D / L^2 = 0.005 \times 0.01 = 5\times 10^{-5}\)。穩定條件在無因次形式下相同，這說明只要把參數一併無因次化，檢查條件與維度無關。

## 實作與程式

以下程式建立合成池域的最小設定，驗證輸入與單位一致性，並輸出設定的 SHA-256 雜湊。此程式只依賴 NumPy 與標準庫；未執行前不宣稱任何結果，實際輸出僅為依推導得到的預期。

```python
import hashlib
import json
import numpy as np

REQUIRED_UNITS = {
    "Lx": "m", "Ly": "m", "D": "m^2/s",
    "dt": "s", "T_end": "s", "c0": "kg/m^3",
}

def make_config(Nx, Ny, Lx, Ly, D, dt, T_end, c0,
                source=0.0, units=None):
    units = dict(REQUIRED_UNITS) if units is None else dict(units)
    if not isinstance(Nx, int) or not isinstance(Ny, int):
        raise ValueError("Nx, Ny 必須為整數")
    if Nx < 2 or Ny < 2:
        raise ValueError("Nx, Ny 至少為 2")
    for name, val in [("Lx", Lx), ("Ly", Ly), ("D", D),
                      ("dt", dt), ("T_end", T_end),
                      ("c0", c0), ("source", source)]:
        if not np.isfinite(val):
            raise ValueError(f"{name} 必須為有限值")
    if Lx <= 0 or Ly <= 0:
        raise ValueError("Lx, Ly 必須為正值")
    if D <= 0:
        raise ValueError("D 必須為正值")
    if dt <= 0 or T_end <= 0:
        raise ValueError("dt 與 T_end 必須為正值")
    if c0 < 0:
        raise ValueError("c0 必須為非負")
    if dt > T_end:
        raise ValueError("dt 不可大於 T_end")
    cfg = {
        "Nx": Nx, "Ny": Ny, "Lx": float(Lx), "Ly": float(Ly),
        "D": float(D), "dt": float(dt), "T_end": float(T_end),
        "c0": float(c0), "source": float(source),
        "units": units,
    }
    return cfg

def config_hash(cfg):
    payload = json.dumps(cfg, sort_keys=True).encode("utf-8")
    return hashlib.sha256(payload).hexdigest()

def dx_dy(cfg):
    return cfg["Lx"] / cfg["Nx"], cfg["Ly"] / cfg["Ny"]

def explicit_diffusion_limit(cfg):
    dx, dy = dx_dy(cfg)
    return 0.5 / (cfg["D"] * (1.0/dx**2 + 1.0/dy**2))
```

預期輸出（未執行）：以 `Nx=Ny=32, Lx=Ly=1.0, D=0.01, dt=1e-4, T_end=1.0, c0=1.0` 呼叫 `make_config` 應成功並產生 64 字元雜湊；將 `D=-1` 代入應丟出 `ValueError`；將 `c0=np.nan` 代入亦應丟出 `ValueError`。

若後續章節需要 SciPy，會明示匯入並以小型矩陣做對照；本章刻意只用 NumPy 與標準庫。

## 測試與預期結果

以下列出本章需要的正常與故障測試。全部屬於預期，未執行前不宣稱通過。

正常測試：(1) 以 \(N_x=N_y=32\) 建立設定，雜湊為 64 字元，且相同輸入兩次雜湊相同；(2) 以例題 1 的場在四個內點計算中央差分，與解析梯度一致到浮點捨入；(3) 對例題 2 的參數計算 `explicit_diffusion_limit`，得到約 \(1.25\times 10^{-3}\,\text{s}\)（以 \(N_x=N_y=101\) 為例）。

邊界測試：(1) \(N_x=2\)、\(N_y=2\)，設定應成立但 `dx=Lx/2`，檢查 cell 中心為 \(((i+1/2)dx,(j+1/2)dy)\)；(2) \(c_0=0\) 應允許，因非負限制只排除負值；(3) `T_end=dt` 應允許，代表單一時間步。

故障測試：(1) `D=0` 必須拒絕，因為擴散係數為零會使模型退化，且用以計算穩定條件的除法不正；(2) `c0=-1e-3` 必須拒絕，以避免初始條件已違反非負；(3) `dt>T_end` 必須拒絕；(4) 任意欄位為 `np.nan` 或 `np.inf` 必須拒絕；(5) `units` 若與既有維度不一致（例如把 `D` 註記為 `m/s`）應拒絕，此檢查需要在 `make_config` 內比對單位字典。

關於「數值穩定、守恆、能量下降、非負與物理可信」五者，必須分開陳述：穩定性是演算法對擾動不放大；守恆是離散總量在週期或零通量邊界下不變；能量下降是對特定離散算子與時間格式（例如半隱式或凸分裂）能量泛函單調不增；非負是解在合理離散下有下界；物理可信則是模型與真實系統一致。這五者彼此既不充分也不必要。例如顯式 FTCS 可穩定但不保證非負；Crank–Nicolson 對擴散方程 A 穩定且能量下降，但會對高頻模態產生振盪；有限體積法可以精確守恆但不必然單調。

## 除錯與常見陷阱

第一個陷阱是把單位與無因次量混用。例如同時把 \(D\) 以 m\(^2\)/s 儲存，又把 \(\Delta x\) 以 cm 儲存，穩定條件則不知不覺少算一萬倍。第二個陷阱是把二維網格的 `q[j,i]` 與影像 row 向下混用，導致上下顛倒或把展平索引 \(k=jN_x+i\) 誤寫為 \(k=iN_y+j\)。第三個陷阱是把模型誤差與離散誤差混為一談：細化網格收斂後，並不代表假設的邊界條件是對的。第四個陷阱是以為設定雜湊等同設定驗證；雜湊只保證同一組位元組的一致性，不保證內容在物理上合理，所以仍須搭配結構化檢查。第五個陷阱是以為「穩定條件是充要條件」；CFL 型條件對顯式格式是必要，但對於某些非線性或變係數問題不一定充分。第六個陷阱是為求好看裁掉負值或平滑振盪，這會改變離散質量、能量或組分，且未記錄時等同掩蓋錯誤。

## 養殖與相場案例

本卷所有養殖資料一律合成，不提供現場閾值，也不連真實設備。以合成池域為例，可以設定 \(L_x=4\,\text{m}\)、\(L_y=2\,\text{m}\)，內部初始溫度均勻 \(T_0=298.15\,\text{K}\)，初始溶氧濃度 \(c_0 = 7\times 10^{-3}\,\text{kg/m}^3\)（等同 7 mg/L）。這些都是合成設定，不用以判定真實水體是否適養。

相場橋接方面，本章只說明場與單位，不展開 Allen–Cahn 或 Cahn–Hilliard 的動力學。讀者應記得：相場變數 \(\phi\) 預設為無因次；能量密度為 \(W(\phi) = (\phi^2-1)^2/4\)；總自由能為 \(F = \int [W(\phi) + \kappa|\nabla\phi|^2/2]\,dV\)。這些將在第 25 章之後展開。溶氧跨管理閾值不是相變，任何縮放或渲染都不能取代物理驗證。agent 只能唯讀查詢證據，不得自行改模型、投餌、加藥或操作設備。

## 習題

**習題 1（手算）**：給定 \(u(x,y) = 3x^2 - 2xy + y^2\)（單位 m\(^2\)/s，指某個純量勢），在點 \((1,-1)\) 求 \(\nabla u\)，並以 \(h=0.2\) 的中央差分對 x 分量驗證。

**習題 2（程式）**：擴充 `make_config`，加入 `bc` 欄位，取值為 `"dirichlet"`、`"neumann"` 或 `"robin"`，並拒絕其他值。檢查設定相同的兩次呼叫產生相同雜湊。

**習題 3（反例）**：給出一組 `make_config` 輸入，使其「所有數值有限、所有正負檢查通過」，但模型在物理上仍不一致。說明如何以額外檢查捕捉它。

**習題 4（整合）**：對 \(D=2\times 10^{-9}\,\text{m}^2/\text{s}\)（近似水中分子擴散）、\(L=0.1\,\text{m}\)、\(N_x=51\) 的一維設定，計算 \(\Delta x\)、顯式 FTCS 的 \(\Delta t\) 上限，並說明若要在 \(T_{\text{end}}=60\,\text{s}\) 內完成模擬，需要多少個時間步。

## 習題解答

**解答 1**：偏導 \(\partial u/\partial x = 6x - 2y\)，\(\partial u/\partial y = -2x + 2y\)。在 \((1,-1)\) 得 \(\nabla u = (6+2, -2-2) = (8, -4)\)，單位為原始純量單位每公尺。中央差分對 x 分量：\(u(1.2,-1) = 3(1.44) - 2(1.2)(-1) + 1 = 4.32 + 2.4 + 1 = 7.72\)；\(u(0.8,-1) = 3(0.64) - 2(0.8)(-1) + 1 = 1.92 + 1.6 + 1 = 4.52\)；差分為 \((7.72-4.52)/0.4 = 8.0\)，與解析一致。

**解答 2**：在 `make_config` 內加入
```python
allowed_bc = {"dirichlet", "neumann", "robin"}
if bc not in allowed_bc:
    raise ValueError(f"不支援的邊界條件：{bc}")
```
將 `bc` 寫入 `cfg`，兩次相同輸入的雜湊相同；將 `bc="periodic"` 傳入應拒絕（本卷於後續章節另行處理週期設定，須自成一組檢查）。此處以 `json.dumps(..., sort_keys=True)` 序列化，字典順序不影響雜湊。

**解答 3**：例如 \(L_x=L_y=1\,\text{m}\)、\(D=1\,\text{m}^2/\text{s}\)、\(c_0=1\,\text{kg/m}^3\)，但 `bc="neumann"` 且 `source=1.0`；均勻 Neumann 下若來源非零，穩態不存在，這在物理上不一致。可加入的檢查是：在 `bc="neumann"` 且 `source != 0` 時拒絕，或明示此設定僅作為暫時演算，且需另加零空間處理。另一例是把 `units["D"]="m/s"`，與 `D` 的維度不一致，須拒絕。這說明「通過有限性與正負檢查」不足以保證設定自洽，仍須有語意層的檢查。

**解答 4**：\(\Delta x = 0.1/51 \approx 1.9608\times 10^{-3}\,\text{m}\)。顯式 FTCS 一維穩定條件為 \(D\Delta t/\Delta x^2 \le 1/2\)，故 \(\Delta t \le 0.5 \cdot \Delta x^2 / D = 0.5 \cdot (3.844\times 10^{-6}) / (2\times 10^{-9}) \approx 960.8\,\text{s}\)。要把 \(T_{\text{end}}=60\,\text{s}\) 模擬完，時間步數約為 \(60/960.8 \approx 0.0625\)，即一步已足夠，因為物理擴散本身的時間尺度遠大於這個上限。這說明「時間步上限」與「需要多少步」是兩個獨立的量。若把 \(D\) 改大或 L 改小，所需步數會顯著上升。

## 本章小結

本章界定第三卷的範圍：經典場／連續介質與科學計算，不涉量子場論或工業級 CFD。我們依序處理了場的類型、SI 單位與無因次化、模型誤差與離散誤差的分離、合成池域的最小設定、設定雜湊、非有限與不一致輸入的拒絕、二維網格索引與 MAC 速度配置，以及顯式擴散穩定條件的量綱檢查。透過例題 1 與例題 2 的逐步手算，讀者應已內化：任何擴散係數、時間步長、網格間距都要先看單位，再看無因次組合。穩定性、守恆、能量下降、非負與物理可信必須分開討論，不得互相代替。本章提供的 `make_config` 與 `config_hash` 會在本卷後續多章作為設定基礎，但每章仍會明列各自的額外輸入契約。
